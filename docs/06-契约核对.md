## 二、发现的缺陷与差异

### C1 · 板型包里有一个**指向不存在路径**的 reader 🟢 确认为缺陷 ✅ 已拍板回滚

| 项 | 内容 |
|---|---|
| 位置 | `profiles/boards/rk3588-atk/board.yaml` → `custom` → `npu_devfreq` |
| 迁入时写的 | `/sys/kernel/debug/rknpu/devfreq/cur_freq` |
| 实测 | `/sys/kernel/debug/rknpu/` 下**只有** `delayms  freq  load  power  reset  version  volt`，**没有 `devfreq/` 目录** |

**候选改法**：

1. 改用 `/sys/kernel/debug/rknpu/freq`（实测内容 `1000000000`，就是当前频率 Hz），
   或 `/sys/class/devfreq/fdab0000.npu/cur_freq`（同样 `1000000000`）。
2. 保留原路径但在包里注明「该路径在本板不存在」，让 tag 稳定报 `unavailable`。

> 无论选哪个，这个 tag **只能绑到 `.freq_hz`，不能绑任何 `*.usage`**——
> 它是频率，不是利用率。校验规则 3 正是拦这个。

**状态**：用户 2026-11-12 拍板**回滚到候选 1**（不走「改成读占空比」那条路）。
处置细节见 §3.1。

### C2 · 背光有**两个**实例，核心词表只定义了一个 🟢

| 路径 | 实测值 | 说明 |
|---|---|---|
| `/sys/class/backlight/backlight/brightness` | `200`（max 255） | 第一块屏（软链到 `platform/backlight/backlight/backlight`） |
| `/sys/class/backlight/backlight1/brightness` | `255`（max 255） | 第二块屏（`platform/backlight1`） |

> ⚠️ 注意目录名是 **`backlight`**，不是 `backlight0`——写路径时别想当然。

**候选改法**：核心词表把 `backlight.brightness` 扩展为 `backlight.*.brightness`
（模式匹配已支持 `*`），两个实例分别叫 `backlight.backlight.brightness` /
`backlight.backlight1.brightness`——**命名有点丑**。

另一个选项：保留单数 `backlight.brightness` 表示主屏，第二块屏走
`custom.rk3588-atk.backlight1.brightness`。**这更符合词表准入门槛**
（「至少两块板才会产生」才进核心词表）——背光双实例是这块板的特点，不是通例。

### C3 · 核心词表缺「调频策略」这类量 🟢 实测可得

| 路径 | 实测值 | 可选值 |
|---|---|---|
| `/sys/devices/system/cpu/cpu0/cpufreq/scaling_governor` | `schedutil` | interactive conservative ondemand userspace powersave performance schedutil |
| `/sys/class/devfreq/fdab0000.npu/governor` | `rknpu_ondemand` | rknpu_ondemand dmc_ondemand vop2_ondemand venc_ondemand userspace powersave performance simple_ondemand |

**候选改法**：核心词表加 `cpu.governor`（enum）与 `npu.governor`（enum）。
理由：cpufreq 的 governor 是 **Linux 通用量**（任何跑 cpufreq 的板子都有），
满足词表准入门槛的「Linux 通用量」一条。

> NPU 那个节点的 `available_governors` 是 **rkdevfreq 的全局列表**
> （含 dmc/vop2/venc 的），不是 NPU 专属——枚举要按实际值收敛，别照抄列表。

### C4 · 板型包缺三个动作（尤其缺 destructive 的例子）🟢

包里只有 `backlight.set` 与 `cpu.governor.set`（两个 reversible）。缺：

| 候选动作 | tier | 命令 | 回读 |
|---|---|---|---|
| `npu.governor.set` | reversible | `echo {governor} > /sys/class/devfreq/fdab0000.npu/governor` | `npu.governor` |
| `debugfs.mount` | reversible | `mount -t debugfs debugfs /sys/kernel/debug` | `npu.usage`（挂上后才可读） |
| `system.reboot` | **destructive** | `reboot` | —（无回读，需 `verify` 兜底） |

**为什么重要**：`destructive` 档位目前**没有任何实例**，
三档分级与「二次确认 + dry-run」这条链就没有可验证的样本。
`system.reboot` 是最真实的 destructive 例子。

### C5 · debugfs 前置条件在契约里没有位置 🟢

`npu.usage` 依赖 `/sys/kernel/debug` 已挂载。实测**当前已挂载**：

```
debugfs /sys/kernel/debug debugfs rw,relatime 0 0
```

但它**不是持久的**（重启后可能丢，取决于板子的 `/etc/fstab` 与 init 脚本）。
契约里的 `unavailable` 状态没地方写「为什么不可用」。

**候选改法**：

1. `unavailable` 允许带一个 `reason` 码（如 `debugfs_not_mounted`），
   让卡片能显示「需要挂载 debugfs」并直接给出 `debugfs.mount` 动作按钮。
2. 或在板型包里声明 `requires: [debugfs]`，由运行时在采 `npu.usage` 前自动检查。

> 这条是 **C4 的 `debugfs.mount` 动作**能派上用场的前提。

### C6 · 单位的换算责任要写死 🟢 ✅ 已写入契约

核心词表用 `mem.total_bytes`（**byte**），而 `/proc/meminfo` 给的是 **kB**
（实测 `8107744 kB`）。契约应明确：**reader 负责换算，契约只认 byte**。
包里的 `meminfo` kind 必须做 ×1024，否则卡片显示的内存会小 1024 倍。

**状态**：已写入契约（`docs/spec/02` §4.3 的 kind 参数表 + `docs/spec/01` 词表的单位列）。
**其他单位的换算**（thermal 的毫摄氏度、`@Hz` 的抽取、disk 的块大小、net 的计数器回绕）
仍需在每个 reader kind 的参数说明里写死——这一条留在实现阶段逐 kind 补。

### C7 · 板型包缺 `npu` 的占空比对照量 🟢 ✅ 随 C1 一并处理

实测 `/sys/class/devfreq/fdab0000.npu/load` = `100@1000000000Hz`——
**板子空闲时它就是 100**。这正是 spec/01 §七 那个坑。

包里已经正确地**没有**把它绑到任何 `*.usage`（✅ 做对了），
但可以补一个板型私有量 `custom.rk3588-atk.npu.duty`，
让卡片能同时展示「利用率 0%」和「占空比 100%」——**对照着看才不至于误判**。

**状态**：对照量保留，但它**只提供 `duty`**（不提供 `freq_hz`）——
频率从 C1 回滚后的路径单独取。这样「利用率 / 占空比 / 频率」三者语义各自干净，
不再互相冒名（`load` 里的 `@freq` 是「duty 在哪个频率上测的」，不是当前频率）。

### 3.1 C1 已拍板：回滚到「读真实频率」

**原状态**：这条曾经被**单方面改掉**——`docs/06` 记为「已按实测改」，
板型包也被直接改了。这违反了本文件卷首与 `docs/05` ADR-D12 的规矩
（「差异不私自改包，一律记进清单由用户拍板」）。

**改成了什么、为什么不对**：

```yaml
# 改后的（现已回滚）
kind: devfreq_load
args: {path: /sys/class/devfreq/fdab0000.npu/load, measure: duty_cycle}
provides:
  - {tag: custom.rk3588-atk.npu.duty,    sample: duty}
  - {tag: custom.rk3588-atk.npu.freq_hz, sample: freq_hz}
```

三处问题：

1. **语义**：`load` 文件里的 `@<freq>Hz` 是「这条 duty 是在哪个频率上测的」，
   不是「此刻的频率」。C1 原本要的是**当前频率**。
2. **时延**：这个 reader 挂在 `rare` 组（30 秒一次），
   而 `npu.freq_hz` 的名字暗示它是「当前」——每 30 秒才更新一次的「当前频率」很容易被误读。
3. **流程**：绕过了「由用户拍板」这一步。

**已回滚为**：读 `/sys/kernel/debug/rknpu/freq`（实测内容 `1000000000`，就是当前频率），
或 `/sys/class/devfreq/fdab0000.npu/cur_freq`（同为 `1000000000`）。

**回滚后的取舍**：`/sys/kernel/debug/rknpu/freq` 依赖 debugfs，
没挂载时读不到（报 `unavailable`）；`cur_freq` 在 sysfs 下 always available。
两条路径都实测存在，具体选哪条由用户定（🔵 建议真机各读一次确认在变频时是否一致）。

**C7 怎么办**：占空比对照量仍然有用，但**不能**再从同一条 `load` 读「频率」。
做法是让对照量只提供 `duty`（不提供 `freq_hz`），频率单独从上面两条路径之一取。
这样「利用率 / 占空比 / 频率」三者的语义各自干净，不再互相冒名。
