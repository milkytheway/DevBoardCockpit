# 计划 4 · 卡片框架（M5）与布局（M5b）

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让一张 AI 写的 HTML 卡片能**安全地**跑起来——读它要读的 tag，不碰别的，不联网，不搞垮工作台；改文件即热更新；布局可拖拽可保存。

**Architecture:** 新增四层：**卡片目录层**（双根发现 → manifest 校验 → 分配实例 id）→ **协议层**（`cockpit://` 托管卡片目录 + 注入 CSP 头 + 注入 bridge 脚本与主题样式）→ **桥接层**（页面侧经纪人握手 → `MessageChannel` 私有通道 → main 侧会话按权限过滤）→ **呈现层**（用户卡区；M5b 再上网格）。**权限过滤一律在 main**（可信进程），renderer 只建 iframe、转发消息、**不做任何权限判断**。卡片跑在 `sandbox="allow-scripts"` 的**不透明源** iframe 里（契约 §六），断网由宿主注入的 CSP 执行（契约 §6.1，**逐条原文，不改**）。

**Tech Stack:** TypeScript `strict`、Electron 34、electron-vite、vitest（unit/web）、**Playwright（Electron 模式）**、react-grid-layout（M5b）

**Spec:** `docs/21-第三部分设计-卡片框架与控制面.md`（**本计划的依据**，含全部拍板与自我更正）、`docs/spec/03-card-manifest.md`（卡片契约）、`docs/spec/01-tag-contract.md`（五态与 reason 码）、`docs/superpowers/spikes/2026-11-13-卡片沙箱与桥接实测.md`（尖兵实测，本计划的隔离判据来自它）

> **本计划覆盖 M5 + M5b**（2026-11-14 拍板：M5 **不做**布局，布局单独一期 M5b）。
> **M6（控制面）另开计划 5**——写侧连着注入防线（`spec/02` §4.6），单独一份、慢慢做。
> **本计划不含授权（consent）流程**：M5 只做只读卡，没有写权限可授权；授权属 M6。

## Review Focus

评审者**专门**盯这五类输入——本计划的测试**故意不覆盖**它们：

| # | 输入类 | 为什么危险 |
|---|---|---|
| **RF-1** | **卡片 A 的 iframe 导航到卡片 B 的 URL** | `event.source` 还是同一个 iframe → 宿主若只按 source 认人，**B 的代码会借 A 的权限发消息**。桥接必须**再比一次 instanceId**——而 instanceId 是**跟着 bridge 脚本**走的（每个实例一份） |
| **RF-2** | **卡片在 `permissions.read` 之外请求 tag**，或**用通配符订阅后收窄范围** | 越权读 = 数据泄漏。**通配符订阅必须每次推送再判一次**，不能只在订阅时判 |
| **RF-3** | **卡片目录里的符号链接、`%2e%2e`、绝对路径**指向卡片目录之外 | 路径穿越 = 卡片能读宿主文件系统的任意内容 |
| **RF-4** | **一张卡抛异常 / 死循环 / 疯狂订阅** | 契约 §六：「单卡崩溃不影响其他卡，也不影响工作台」。疯狂订阅会把 main 的内存与 IPC 打满——**退订必须真的释放** |
| **RF-5** | **CSP 违规发生后，谁能看到** | 契约 §6.1 承诺「agent 能看到这张卡试图联网」。若 `console-message` 的归属做不对，agent 看到的是**别的卡**的违规 —— 或者什么都看不到 |
