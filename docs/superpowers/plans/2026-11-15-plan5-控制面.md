# 计划 5 · M6 控制面（动作执行链）

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让宿主**能执行板子接受的一次写入，并如实回报结果**：参数按类型编码 → 过危险地板 → 经往返队列执行 → 按回读五种形式取值 → 写一行可追责的审计 → 必要时请人确认。

**Architecture:** 新增一层 **控制面**（`src/main/actions/`）：**编码器**（纯函数，把参数按类型编成命令行片段）→ **地板复查**（对**编码后的** argv 匹配 `spec/02` §5.2.1）→ **执行器**（经 `RoundTripQueue` 的 `action` 队列执行，保证与采样不并发）→ **回读**（`spec/02` §4.4 的五种形式）→ **审计**（行式、每行 flush）。**授权与确认**（动作 id + 参数域 + `confirm_id`）走 main 侧，**renderer 不判权限**。

**Tech Stack:** TypeScript `strict`、Electron 34、electron-vite、vitest（unit/web）、Playwright（Electron 模式）

**Spec:** `docs/spec/02-board-pack.md`（§4.1 动作为什么不能只是命令 / §4.3 参数 / §4.4 回读五形式 / §4.5 `verify` / §4.6 注入防线 / §5.2–5.2.1 危险地板 / §5.4 审计 / §5.5 授权粒度）、`docs/spec/03-card-manifest.md` §5（写侧：闭环的四步）、`docs/spec/04-mcp-tools.md` §2.4（`execute_action`）、`docs/21-第三部分设计-卡片框架与控制面.md` §6.9（七步执行链）与 §10.2（六条机械判据）、`docs/28-流程包评审处置.md`（ADR-D31 的裁决）

> **本计划不动契约**：`spec/02` 的动作/回读/授权/地板与 `spec/03` §5 的 `actions.invoke` **都已经写好了**——
> M6 是**实现已定的契约**，不是设计新东西。
> **流程包（workflow pack）不在本计划内**：按 ADR-D31 的 R1/R13，流程层在尖兵与本计划之后，
> 且**首版不进 `docs/spec/`**（格式先落 `docs/` + `fixtures/`）。
> 本计划的 Task 1 就是那道**尖兵**——它替流程层探路，也替执行器定形状。

## Review Focus

评审者**专门**盯这六类输入——本计划的测试**故意不覆盖**它们：

| # | 输入类 | 为什么危险 |
|---|---|---|
| **RF-1** | **参数里塞分隔符**（`--model "x; reboot"`、`$(rm -rf /)`、反引号、`%USERPROFILE%\.ssh\id_rsa`） | 注入防线（`spec/02` §4.6）漏一条 = 板子被当 shell 用。A4 的队列也救不了——它只防串台，不防注入 |
| **RF-2** | **地板匹配被绕过**：模板里的占位自带引号（`'{value}'`）、用 `basename` 形态的路径（`/usr/bin/rm`）、用变量间接引用（`sh -c "$X"`） | `spec/02` §5.2.1 说「匹配不上不等于安全」；运行时复查必须对**编码后**的 argv 做，且 `basename` 也要算 |
| **RF-3** | **`confirm_id` 被复用**：同一次确认凭据重放两次、跨动作用、跨版本用、超 5 分钟用 | 确认凭据是「人点了这一次」的凭据；复用 = 绕过确认（ADR-D31 R2③） |
| **RF-4** | **回读与执行被采样插队**（串口） | `spec/02` §1.2.1：「回读若被采样插队，读到的可能是别的命令的输出」→ 「回读不符」成了假阴性 → 驾驶舱显示错的真实状态 |
| **RF-5** | **动作在串口上要退出码**（`command_ok` / `verify`） | 串口没有退出码（事实 S5）→ 回读永远「不符」→ 用户以为动作失败，其实成功了 |
| **RF-6** | **审计与执行脱节**：执行了但没审计行 / 审计行写了但没执行 / 参数没进审计 | `spec/02` §5.4：审计是追责单位；没有它，「板子怎么变成这样的」无人能答 |

## Task 4: 动作执行器 + 往返队列的事务化

### 4.1 步骤

- [x] **4.1.1 `src/main/tags/runtime.ts` 开一条「跑一次独占事务」的口子**
  （`docs/21` §6.9 指出的缺口：队列是函数内的局部变量，`connection` 是 private）：
  - `runTransaction<T>(fn: (conn: Connection) => Promise<T>): Promise<T>`
  - **经同一个 `RoundTripQueue`**，且用 `action` 队列（动作优先于采样）。
- [x] **4.1.2 `src/main/hal/round-trip-queue.ts` 升级到四级优先级**
  （ADR-D23）：`action-verify` > `manual-refresh` > `card-sampling` > `diagnostics`。
  - 现在的实现只有 `action` / `sample` 两级 → **加一级 `kind`**。
- [ ] **4.1.2b 执行原语必须**可中断** ⭐（尖兵 §三·F3）
  - 「设一个取消标志，下一步再看」**不叫取消**：尖兵实测里，一个 75 秒的传输步
    在收到取消信号后**照跑完**；
  - → 执行器要能**杀掉在飞的子进程与传输**（abort 语义），
    并在返回时把「被取消」如实报出来（不是「失败」）。
- [ ] **4.1.3 `src/main/actions/executor.ts`**:
  - `invokeAction(profile, actionId, params, opts)` 的流程：
    **编码 → 地板复查 → 授权 →（必要时）确认 → 队列内执行 → 回读 → 审计**；
  - **回读是强制的**（A5）：没有 `readback` 的动作**在执行前就被拒**（不是执行完再报）；
  - 执行**必须**走 `Connection.exec`（**不新开连接**，否则绕开队列）。
- [ ] **4.1.4 串口上没有退出码**（A11 / RF-5）：回读形式 `command_ok` / `verify`
  **在串口传输上被拒绝**（执行前拒，报 `unsupported_transport`）。
- [ ] **4.1.5 执行器要能对**指定的连接**执行**（A17）：签名是
  `invokeAction(profile, actionId, params, opts)`——**profile 是参数**，
  不是「运行时那条连接」。这样流程层的「在客机上跑 scp」才能复用它
  （直传已实测可行：客机 → 板子 `scp` 成功，见尖兵 §三·五）。
- [ ] **4.1.6 凭据准备是一个**显式的独立动作**（不是隐藏步骤）**：
  「把源目标的公钥装进目标目标的 `authorized_keys`」= 板子动作，`danger: destructive`，
  参数 = 公钥字符串（走参数编码与地板）。**它是 destructive → 必须走确认通道**（R2③）。

### 4.2 判据

| # | 判据 |
|---|---|
| 1 | 动作与采样**不并发**（单测：队列里动作在飞时采样让路） |
| 2 | 采样让路 → **跳过本周期，不补发**（调度器的责任，已有实现，回归守住） |
| 3 | 串口上 `command_ok` / `verify` **被拒绝**（`docs/21` §10.2 判据 5） |
| 4 | 没有 `readback` 的动作**执行前**被拒 |
| 5 | **执行原语可中断**（杀得掉在飞的子进程/传输），取消如实报「被取消」 |
| 5 | **回读与执行不可拆分**（RF-4）：回读期间采样插队 → 结果必须被识别为不可信（**这是队列级保证**，单测用假的连接证明） |

## Task 5: 授权与确认通道

### 5.1 步骤

- [ ] **5.1.1 `src/main/actions/authorization.ts`**：
  - `authorize(action, params, granted): 'ok' | 'needs_confirmation' | 'denied'`
  - `reversible` 且参数在 `guard` 域内 → `ok`（**记审计**）；
  - 参数**超出 `guard`** → `needs_confirmation`（A10：**不是直接拒绝**）；
  - `destructive` → `needs_confirmation`；
  - 动作 id **不在已授权集合** → `denied`。
- [ ] **5.1.2 确认通道**（A8）：
  - main 维护待确认队列 → 页面弹模态（**显示最终命令与参数域**）；
  - 人点了 → 生成 `confirm_id`：**一次性**、5 分钟有效、绑定
    `(动作 id, 参数规范化摘要, 板型包 id, 契约版本)`；
  - **重放**（同凭据用两次 / 跨动作 / 跨版本 / 超时）→ 一律 `denied`（RF-3）。
- [ ] **5.1.3 参数化动作**的授权域：guard 只能缩小（A10）。

### 5.2 判据

| # | 判据 |
|---|---|
| 1 | `reversible` + 域内 → 直接执行**且记审计** |
| 2 | `reversible` + **超域** → 走确认（**不是拒绝**） |
| 3 | `destructive` → 每次都问 |
| 4 | `confirm_id` **一次性**；重放被拒（RF-3 的四个变体各有单测） |
| 5 | 确认界面**展示最终命令**（不是参数名） |

## Task 6: 回读的五种形式（`spec/02` §4.4）

### 6.1 步骤

- [ ] **6.1.1 `src/main/actions/readback.ts`**：
  | 形式 | 实现 | 备注 |
  |---|---|---|
  | 1 `tag` | **定向读一次**那个 tag（**新鲜的**，不是等下一个周期） | |
  | 2 `file_equals` | 读文件比值，`expect` 可以是 `{param}` | `tolerance` 照契约 |
  | 3 `command_ok` | 看退出码 | **串口上不可用**（A11） |
  | 4 `verify` | 执行后跑二次命令，轮询到成功或超时 | 与形式 3 同样在串口上不可用 |
  | 5 `none` | `ok: true` + **`verified: false`** + 非空 `consequence` | 只允许 `reversible`（A6） |
- [ ] **6.1.2 结果形状**：`{ ok, verified, value?, unit?, status?, reason? }`
  —— **`verified` 不是 `reason`**（ADR-D25：「报 `ok: false` 是另一种撒谎」）。

### 6.2 判据

| # | 判据 |
|---|---|
| 1 | 五种形式各有正例 |
| 2 | `kind: none` → `ok: true` + `verified: false`，**不显示成已生效** |
| 3 | 判据能表达**「文件已到位但没生效」**（尖兵 §二·Q3：deliver 成功、load 失败时板子就是这个状态） |
| 3 | 形式 3/4 在串口上**被拒绝** |
| 4 | 形式 1 读到的 tag 是**新鲜的**（不是等下一个周期的那份） |
