# Task 10 · 真机验收清单（需在 Windows 宿主机上做）

> **为什么这份清单单独存在**：实现跑在 Linux 沙箱里，而验收要连**真板子**——
> 沙箱里没有 adb、没有串口设备、没有你的 VMware 客机。
> 自动化测试（148 个用例）覆盖了纯逻辑与接线，但**证明不了线是通的**。
>
> **照下面 7 步走一遍**，每步都记录实际结果。
> 任何一步不符，**先别往下走**——把现象记进「记录结果」那一节。

## 准备（步骤 0）

```powershell
cd "D:\3588\02、RK3588开发平台\DevBoardCockpit"

# 装依赖（会触发 electron-rebuild，把 node-pty / serialport 重编译到 Electron 的 ABI）
npm install

# 四道检查必须全绿
npm run lint
npm run typecheck
npm test
npm run build              # 三段构建 + **构建产物自检**（preload 文件真的在吗）
npm run mutation:check     # 变异测试：12 项，每项改坏后必须变红
npm run gen:vocabulary:check   # 词表三份一致
```

**如果 `npm install` 在 `postinstall` 报错**——那就是 ADR-D11 说的事：
`node-pty` / `serialport` 没针对 Electron 的 ABI 重编译。
报错里通常会写缺哪个模块名，对照 `docs/04-架构设计.md` §14 的第一条风险。

> **`npm run mutation:check` 必须是 12 项、0 形同虚设。**
> 如果它报「变异脚本本身出错」或「形同虚设」，说明有测试不再守着已修好的东西——
> **先修它，再往下走**。

```powershell
# 确认板子在 device 状态（事实 A7：只认 device）
& "$env:USERPROFILE\Downloads\platform-tools_r33.0.3-windows\platform-tools\adb.exe" devices
```

## 步骤 1 · 窗口起得来吗（preload 有没有加载）

1. `npm run dev`。
2. **工具栏上应该出现连接按钮**（「板子 · 串口」「板子 · ADB」……）。
3. 点一下，看**有没有报错**。

**如果工具栏是空的**（一个连接按钮都没有，页面显示「选一个连接开始」）→
**preload 没加载成功**，`window.cockpit` 是 undefined，整个应用没有 API。
开 DevTools 的 Console 看有没有 preload 相关的报错。
这一条是本轮修掉的 P0（`docs/11-计划1评审报告.md` 的「preload 路径错」）。

## 步骤 2 · 串口

1. 点「板子 · 串口」。
2. **应看到板子的 root 提示符。**
3. 手工输入 `uname -a` 回车 → 应看到一行输出。

**如果看到 `__DBC...__` 这类 marker 漏在输出里** → RF-1 没修好，
问题在 `src/main/hal/session.ts` 的 `extractMarkerOutput`——
板子回显命令，marker 在 transcript 里出现两次，要取两次之间的内容。

## 步骤 3 · ADB（**重点**：行规程）

1. 点「板子 · ADB」。**应看到提示符，且带颜色。**
   - 有颜色 = 事实 A2 的 `TERM=xterm-256color` 与 A3 的 `ls` shell 函数生效了；
   - 没颜色 = 会话环境脚本没被执行（查 `terminalEnvScript()`）。
2. 输入 `ls` → **列出的文件名应该是多列**（`-C` 生效）。
3. **按回车，命令必须真的执行。**
   - 如果打字能看见、但按回车**什么也不发生** → 行规程没生效。
     ADB 是 pipe 模式，远端没有行规程，宿主必须把回车译成 `\n`
     （`src/main/terminal/line-editor.ts`）。这条是**真机实测过的缺陷**（R-01）。
4. **按退格**，最后一个字符应该消失（而不是把远端已经收到的内容弄乱）。
5. `ls -l` 再回车 → 应看到详细列表。

**注意**：ADB 是 pipe 模式，板子不回显 —— 宿主替它回显。
如果你看到**两行**同样的字，说明回显做了两遍。

## 步骤 4 · SSH

1. 点「Ubuntu · SSH」。应看到客机提示符。
2. `whoami` → 应回 `alientek`。

## 步骤 5 · 文件互传（**双向**）

1. 在远端树点「刷新」→ 应列出远端目录。
   - **列不出来** → 看是不是本机连接（Windows 上没有 `ls`，
     本机传输走的是 fs，根目录映射到工作目录）。
2. 选中远端一个文件 → 点 ↓ 下载 → **应弹出一条「已保存到 …」**，
   文件应出现在 `%USERPROFILE%\Downloads\`。
   - **下载按钮必挂 / 报「没有本地落盘路径」** → 落盘位置没接上。
   - 界面**什么都没显示**（既不报错也不提示）→ 错误被吞了。
3. 选一个本地文件 → 点 ↑ 上传 → 应提示「已上传 … → …」。
   - **报「找不到文件」** → 上传没传绝对路径，
     宿主在自己的 CWD 里找同名文件了。
   - **静默传走了另一个文件** → 这是**数据安全问题**，立刻停下记下来。

## 步骤 6 · 错误消息（**读得懂吗**）

1. 用一个**占用中的串口**（或拔了线的板子）点连接。
2. **应看到一句人话**，例如「串口 COM3 被占用」。

**如果看到的是 `[object Object]` 或 `Error invoking remote method '…'`** →
错误跨 IPC 边界退化了（R-03）。这轮已修（`src/shared/errors.ts` +
`src/preload/index.ts`），若仍出现说明改动没生效。

## 步骤 7 · 会话日志

关掉应用，然后检查：

```
%LOCALAPPDATA%\DevBoardCockpit\logs\<今天日期>\
```

- 应有 `board-serial-<HHMMSS>.log` 等文件；
- 内容含刚才的输入与输出；
- **不含 `[` 开头的 ANSI 码**（事实 G4：ANSI 要剥掉）。

## 步骤 8 · 超时码

断网后执行一条要网络的命令 → 应返回 **124**（事实 G1：统一超时码）。

## 已知没被自动验证的部分

| 项 | 为什么 | 怎么验 |
|---|---|---|
| node-pty 的 Electron ABI | 沙箱是 Linux 且装依赖时跳过了 postinstall | 步骤 0 的 `npm install` + 步骤 2–4 |
| preload 在沙箱 preload 下真的能加载 | 沙箱里没有 Electron 运行时 | 步骤 1 |
| 终端的实际渲染 | happy-dom 不实现 canvas，测的是接线不是像素 | 步骤 2–4 肉眼看 |
| 串口的真实 marker 行为 | 需要真板子回显 | 步骤 2 |
| ADB 的真实行规程 | 远端是 busybox，`\r` 与 `\n` 的差别只有真机能验 | 步骤 3 |
| SSH 的真实认证 | 沙箱里没有客机 | 步骤 4 |
| 文件互传的**真实**传输 | 需要真的板子/客机 | 步骤 5 |
| 错误消息的**真实**呈现 | 跨 Electron IPC 的序列化行为 | 步骤 6 |

这八项是 `docs/04-架构设计.md` §14 列的高风险点，加上本轮两份实现层评审查出的新项。
**这轮做完，计划的 M0–M2 才算真的验完。**
