> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让「契约」变成**跑得起来的代码**——板型包能被加载、被契约的 27 条规则逐条校验、它的 reader 能在**真板子**上把数据取回来并变成 tag。

## Global Constraints

**继承计划 1 的 G1–G24**（见 `docs/superpowers/plans/2026-11-12-plan1-工程骨架与终端三通道.md`）。
下面是本计划**新增**的约束，每条都隐含包含在每个任务里。

| # | 约束 | 出处 |
|---|---|---|
| **N1** | **解析是纯函数**：同样的输入 → 同样的输出。唯一允许的状态是「两次采样之间的历史」，且**状态由 runtime 传进去**（`ReaderContext`），不许藏在模块级变量里 | ADR-D22（reader 保持纯函数）、规则 5 |
| **N2** | **读不到的东西不是 0**（事实 G2）。解析失败 → **绝不填 0**、绝不返回 `NaN`。**但「资源不在」与「读坏了」是两件事**：资源不在（路径不存在、设备被拔）→ `unavailable`；读出来了但坏了（解析失败、越界、类型不符）→ `error`（契约 §2.1.1）。两者都要带 reason 码 + detail | 事实 G2、`spec/01` §2.1.1 |
| **N3** | 五态与 reason 码**照抄契约**：`ok / stale / unavailable / error / pending`；reason 是封闭枚举。**不许自造码** | `spec/01` §2.1.1 |
| **N4** | tag 只能来自**核心词表**或 `custom.<本包 id>.`（规则 1）；`custom` 命名空间的包 id 必须与包自身的 id 一致 | 规则 1 |
| **N5** | **校验器逐条实现 27 条**，缺一条都不算实现（契约原话：「这 27 条就是契约本身」） | `spec/02` §七 |
| **N6** | 机器专属值（adb 路径、串口号、主机名）**只进 `profiles/settings.json`**，不进代码、不进仓库 | AGENTS.md |
| **N7** | `fixtures/` **只增不改**（修正向量 = 新增文件） | AGENTS.md |
| **N8** | **单位换算是 reader 的责任**：契约只认 `byte` / `hertz` / `percent` / `celsius`（`/proc/meminfo` 给 kB → reader ×1024；thermal 给毫度 → reader ÷1000） | `docs/06` C6 |
| **N9** | **`unavailable ≠ 0` 的兄弟条款**：NPU 的 devfreq `load` 读出的是**占空比**，空闲时就是 100——**不许**把它绑到任何 `*.usage` 上 | `spec/01` §七、规则 3/4 |
| **N10** | **不碰共享 `node_modules` 的原生模块**（`node-pty` / `serialport`）。沙箱侧有 2 个测试套件因平台二进制不匹配而**加载失败**——那是**已知环境限制**，不是本计划的 bug | `scripts/acceptance/linux-natives.sh` |

## Review Focus

评审者**专门**盯这五类输入——本计划的测试**故意不覆盖**它们：

| # | 输入类 | 为什么危险 |
|---|---|---|
| **RF-1** | **畸形输入**：空文件、超长行、二进制垃圾、缺字段、字段类型错 | 解析器最容易在这里**抛未捕获异常**或**静默填 0**——两者都违反 N2 |
| **RF-2** | **未知字段**：顶层、reader 内、action 内、`provides` 内各塞一个假字段 | 「被静默忽略的字段就是拼错的字段」（规则 10/24）——**静默忽略**是最难查的一类 bug |
| **RF-3** | **`/proc/stat` 的计数器倒退或跳变**（重启、计数器回绕、采样间隔不固定） | 做差算出的百分比会变成负数或 >100——**比 0 更坏的是假数** |
| **RF-4** | **marker 分段的边界**：某个 reader 的输出里**恰好含 marker 文本**、某段为空、最后一段没有换行 | 分段错位 = **A 的数据被算成 B 的**——监控面板上两个数悄悄互换 |
| **RF-5** | **`requires.capabilities` 的非法值**（`stream`、拼错的名字、空数组、重复项） | 规则 25/26 是 2026-11-13 新加的——**新规则最容易没实现或没测试** |

```ts
  /** 这个 kind 能产出的 sample 模式 */
```

`ParamSpec`：

```ts
{ type: 'string' | 'integer' | 'number' | 'boolean' | 'enum' | 'glob';
```

### Step 2 · 跑，确认红 → Step 3 · 写实现 → Step 4 · 跑，确认绿

**校验器的形状**（每个任务都要能拿它做自动化判据）：

```ts
export interface ValidationIssue {
  severity: 'error' | 'warning';
  rule: number;              // 契约里的规则号（1..27）
  path: string;              // 包内的位置，如 `readers[2].provides[0].tag`
  message: string;           // 给人看的一句话
}
export function validatePack(pack: BoardPack): ValidationIssue[];
```

**规则号必须落在报告里**——「哪条规则破了」比「包不合法」有用得多。

**`floor.ts`** —— 危险地板匹配（§5.2.1）：
- 先按 §4.6 把参数编码进模板 → 得到最终命令
- 按 shell 词法切分 argv（不执行 shell、不做变量展开）
- 词元**相等**才命中（`upgrade_status.sh` **不**命中 `upgrade`）；模式以 `*` 结尾才允许前缀匹配
- 路径类先规范化（展开 `..`、合并 `//`、去掉尾部 `/`）
- `dd` 类：匹配 `dd` 词元 + **目标参数**命中块设备路径
- `rm -rf /` 类：匹配 `rm` + `-rf`/`-fr` + 规范化后等于 `/`
- **匹配不上 ≠ 安全**：表外命令按包的声明走，但**记一条 warning**（运行时检查 R3）

### Step 5 · 写 `scripts/validate-profiles.ts` + 加 npm script

`package.json`：
```json
"validate:profiles": "tsx scripts/validate-profiles.ts"
```

脚本行为：

## Task 5: 8 个 kind 的解析函数（黄金向量）

**要解决的**：M3 的验收判据是「**黄金向量跑通**」。
`fixtures/board/` 里已经有 4 份**真机样本**——
解析器必须能把它们解析成契约要的 tag。

**产出**：`ReaderKind` 接口**加上 `parse`**，以及 8 个 kind 的解析实现。

**它扩展 Task 3 的接口**：Task 3 只定了 `params` / `samples` / `fetch`
（校验器只需要这三样），`parse` 在这里加。

### Step 1 · 先写失败的测试

`tests/unit/tags-readers.test.ts` —— **每个 kind 至少一个「真机样本 → 期望 sample」的用例**：

| kind | 用哪份样本 | 期望 |
|---|---|---|
| `proc_stat` | `fixtures/board/rk3588-atk-proc-stat-pair.txt` | **两次采样做差** → `cpu.usage` 是个 0..100 的数；**首读是 `pending`** |

| `devfreq_load` | `fixtures/board/rk3588-atk-devfreq.txt` | `duty` = 100、`freq_hz` = 1000000000；**末尾的 `@1000000000Hz` 要剥掉** |
| `rknpu_load` | `fixtures/board/rk3588-atk-devfreq.txt` | `Core0: 0%, Core1: 0%, Core2: 0%,` → 三个核各 0；**末尾的逗号要认**（`docs/06` §5.2） |

| `exec_regex` | 同上 | 正则第一个捕获组 |
| `script` | 构造一段 JSON | JSON 的键 → sample |

**再加「不许错得没道理」的用例**（RF-1、N2）：
- 空输入 → **不是 0**，是「读不到」（`unavailable`）
- 格式不对的输入 → 同上
- **`/proc/stat` 计数器倒退** → **不是负数**，是「读不到」（RF-3）
- `proc_stat` **首读** → `pending`，**不是 0**（规则 5）

### Step 2 · 跑，确认红 → Step 3 · 写实现 → Step 4 · 跑，确认绿

**`ParseResult` 的形状**（N2/N3 的落点）：

```ts
export type ParseResult =
  | { status: 'ok'; samples: Record<string, number | string | boolean> }
  | { status: 'pending' }
  | { status: 'unavailable'; reason: ReasonCode; detail: string }   // 资源不在
  | { status: 'error'; reason: ReasonCode; detail: string };        // 读出来了但坏了
```

> **为什么有 `error`**：契约 §2.1.1 的分界——
> 「资源**不在**」是 `unavailable`（卡片该引导用户去挂 debugfs），
> 「资源**在但读不出来**」是 `error`。
> **把两者混成一个 `unavailable` 的一半表就死了**（`stale` 与 `error` 永不出现）。

**reason 只能用契约里的封闭枚举**（N3）：`not_in_pack / device_absent /
service_down / link_busy_terminal / parse_error / out_of_domain / timeout`。

## Task 6: 取数片段 + poll group 合成 + marker 分段

**要解决的**：契约 §1.2——**一个 poll group = 一次往返**。
同组的所有 reader 合成**一条** shell 命令，一次取回，每个 reader 的输出用 **marker** 隔开。

**产出**：`src/main/tags/fetch.ts`。

### Step 1 · 先写失败的测试

`tests/unit/tags-fetch.test.ts`：

- `buildGroupCommand(readers)` 产出一条命令，里面有**每个 reader 的 marker**
- marker **每次唯一**（两次调用产出的命令**不一样**）
- `splitSections(output, readers)` 把输出按 marker 切回**每个 reader 自己的文本**
- **空 section**（某 reader 没输出）→ 该 reader 的文本是**空串**，不是 undefined、不是串到下一个
- **最后一段没有换行** → 照样切得出来
- **某个 reader 的输出里恰好含 marker 文本**（RF-4）→ **不切错**
- **marker 缺失**（板子只回了一半）→ 该 reader 报「读不到」，**不把别的 reader 的数据算成它的**

### Step 2 · 跑，确认红 → Step 3 · 写实现 → Step 4 · 跑，确认绿

**marker 形状**：复用计划 1 的 `src/main/hal/session.ts` 的 `buildMarker`——
**不要另起一套**（§1.2.1：「契约的 marker 协议」与「串口那套」必须同源）。
但**取数的 marker 与串口往返的 marker 是两回事**：
取数用 `__DBC` 协议的那一套（唯一、可认领）。

**为什么取数也要 marker**：串口上板子**会回显命令**（事实 S2），
marker 在 transcript 里出现**两次**——这正是 §1.2.1 说的「一次只有一条命令在飞」的前提。
**取数是一次往返里的多个 reader**，所以每个 reader 都要有**自己的** marker。

```bash
git commit -m "feat(tags): poll group 合成一条命令 + marker 分段"
```

## Task 7: TagStore（五态 + seq）

**要解决的**：ADR-D22——**TagStore 是读数的唯一汇点**。
「驾驶舱」的产品底线是「UI 显示板子的真实状态」；
一份状态有多个副本，就等于没有真相。

**产出**：`src/main/tags/store.ts`。

### Step 1 · 先写失败的测试

`tests/unit/tags-store.test.ts`：

- 写入一个读数 → 读回**同一个对象**（不是副本）
- `seq` 在**同一 tag 内单调递增**（ADR-D22）
- **不同 tag 的 seq 各自独立**
- **五态迁移**照契约 §2.1：
  - `ok` → `stale`（超时未刷新）→ **保留旧值**
  - `ok` → `unavailable` → **不保留**（值为 `null`）——契约 §2.1.1 明写：「`stale` 保留旧值，`unavailable` 不保留（值为 `null`）」
  - `ok` → `error` → **保留旧值**（从 ok/stale 进来时），同时标 `error`
  - `pending` → `error` → **没有旧值**，值为 `null`（从没成功过）
  - `pending` → `error` → **没有旧值**，值为 `null`
  - `unavailable` → `error` → 同上
- **`unavailable` 没有 value**（N2）；`ok` **必带** value
- **写进去的读数不可变**（改了返回对象的字段 → store 里的不变）
- **乱序的旧值被丢弃**（ADR-D22：「渲染层按 `seq` 丢弃乱序的旧值」——但**丢弃发生在 store**，渲染层只拿到最新的）

### Step 2 · 跑，确认红 → Step 3 · 写实现 → Step 4 · 跑，确认绿

