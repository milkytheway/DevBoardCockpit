## 二、宿主侧的三步（Linux 沙箱做不了）

### 步骤 1 · 装依赖并跑 e2e

```powershell
cd D:\3588\02、RK3588开发平台\DevBoardCockpit
npm install
npm run test:cards
```

**判据**：**10 条** e2e 全绿——
① 应用起得来、preload 装上了宿主能力
② 卡片碰不到宿主 DOM（`SecurityError`）
③ 卡片连不上网（fetch 被 CSP 挡）
④ 卡片读不到没权限的 tag（且**看不出存不存在**）

## 四、真机实测（2026-11-14 · 沙箱里的 Linux Electron 34.5.8）

**这一节不是「计划要跑的」，是「已经跑过的」**：
把修好的代码重新构建，在沙箱里用 **Linux 版 Electron 34.5.8** 真跑起来，
装一张卡，用 CDP 驱动，逐条打日志。

| 测什么 | 结果 |
|---|---|
| 外壳 CSP 放不放行卡片（C2） | ✅ iframe 正常加载；修之前是 `ERR_BLOCKED_BY_CSP` |
| bridge 装没装上（C3） | ✅ 卡片里 `typeof window.cockpit === 'object'`，卡片自己的文字变成 `cockpit-ok` |
| CSP 违规抓不抓得到（C4） | ✅ `connect-src` / `img-src` / `script-src` **三类全部落进那张卡的运行时日志**（`captured=e2e-card`） |
| 顶层方法调不调得通（C6） | ✅ `capabilities()` 拿到能力表、`log()` 回 `{ok:true}`、未知名字回 `unknown_method` |
| 越权读泄露存在性吗 | ✅ 没权限的 tag 与不存在的 tag **同一个形状**（`unavailable` + `not_found`） |
| 卡片碰不到宿主文件系统吗 | ✅ 软链指向目录外 → 挡住（单测 + 变异守卫 M49） |

> **这一步改变了两个结论**：
> ① `console-message` 那条路**走不通**（`sourceId` 对 `connect-src` 是空串 → 归属不到卡）；
> ② bridge 的**顶层方法形状是错的**（`cockpit.capabilities()` 报 TypeError）。
> 两条都躲过了单测、类型检查、lint 与构建——**「测试全绿」和「产品能用」之间隔着一次真机运行**。

> **e2e 也跑过了（2026-11-14 晚）**：沙箱里用 Linux Electron 34.5.8 跑 Playwright 的
> Electron 模式，**8 条全绿**（应用起得来 + 七条隔离判据）。
> → **一跑就逮到三个真 bug**：① 用户根目录不存在时**不监听**（第一次装卡永远不被发现）；
> ② 启动后才装的卡**它的目录没被监听**（「改文件即生效」对它无效）；
> ③ e2e 的 harness 自己两处错（卡写到了错的地方、Xvfb 被提前杀）。
> 又补上设计 §10.1 缺的两条判据：**卡片碰不到别的卡**、**改文件即热更新**——
> 后一条**测出来是红的**：热更新**根本没实现**（清单刷新了，但 iframe 不重载），
> 已修（内容指纹进实例 id → URL 变 → iframe 重建）。

> **仍然要宿主再跑一次**：Windows 上的那一次（同一套代码，只换平台）。
