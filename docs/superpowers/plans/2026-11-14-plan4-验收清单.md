## 二、宿主侧的三步（Linux 沙箱做不了）

### 步骤 1 · 装依赖并跑 e2e

```powershell
cd D:\3588\02、RK3588开发平台\DevBoardCockpit
npm install
npm run test:cards
```

**判据**：6 条 e2e 全绿——
① 应用起得来、preload 装上了宿主能力
② 卡片碰不到宿主 DOM（`SecurityError`）
③ 卡片连不上网（fetch 被 CSP 挡）
④ 卡片读不到没权限的 tag（且**看不出存不存在**）
⑤ 卡片抛异常不影响宿主
⑥ 卡片用不了浏览器的存储（不透明源 → `SecurityError`）

> **注意**：`npm install` 之后**沙箱侧的 Linux 平台包会掉**——
> 跑 `bash scripts/acceptance/linux-natives.sh restore` 恢复（两边共享一个 `node_modules`）。

### 步骤 2 · 真板子上的卡片

```powershell
npm run dev
```

**判据**：

| # | 事 | 看到什么 |
|---|---|---|
| B1 | 接上板子（`board-adb`），卡片区出现「CPU 占用率」卡 | 值 = `cpu.usage` 的**真值**，**在动** |
| B2 | 把板子拔了（或停掉 adb server） | 卡片变成**「不可用 · 缺 cpu.usage」**，**不是 0** |
| B3 | 终端占着 COM3 时开 dev | 面板明说「串口 COM3 被终端占用」，**且 adb 那条路仍然出数** |

### 步骤 3 · 改文件即热更新

**判据**：改 `fixtures/cards/cpu-usage/card.js` 里的一个字 → **不用重启**，
卡片在 1 秒内变了；**布局位置没丢**。

## 三、A8 的现状（变异守卫）

计划 4 新增 **M36–M45**（卡片模块 + 运行时候选）：

| # | 守住什么 | 状态 |
|---|---|---|
| M36 | 读权限的覆盖判定不能恒真（恒真 = 越权读） | ✅ |
| M37 | 路径穿越必须挡住 | ✅ |
| M38 | manifest 的未知字段必须报错 | ✅ |
| M39 | 规则 5 离线时是「未验证」不是「不合法」 | ✅ |
| M40 | 不认识的方法必须回 `unknown_method` | ✅ |
| M41 | 握手必须带 instanceId | ✅ |
| M42 | 订阅路径的权限过滤不能整体消失 | ✅ |
| M43 | 存储的单键配额必须守 | ✅ |
| M44 | CSP 违规必须归到**对的那张卡** | ✅ |
| M45 | `board_pack` 为 null 的 profile 必须剔掉 | ✅ |

> **写守卫时抓到过两个自己测试里的洞**（都改了）：
> ① M40 的变异文本里带着 `unknown_method` 字样 → 断言照样通过 → 改成不含该串；
> ② M42 那条测试的假 store **从不回调** → 「一个都不推」这句断言是**空的** →
>    改成真推送。**这就是变异测试的用处**：绿的测试不一定在守。
