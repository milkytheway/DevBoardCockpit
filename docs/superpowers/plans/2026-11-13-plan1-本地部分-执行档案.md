## 一之二、**为什么要装这些东西**（2026-11-13 补）

> 这条是本地 agent 追问「为什么要装」之后查出来的。
> **结论：大部分不是工程需要，是 `postinstall` 的一行 `-f` 引出来的。**

### 事实：这两个原生模块是 **NAPI** 的

`node-pty` 与 `serialport` 的导出表里都有 `napi_register_module_v1`
——**NAPI 不绑定 Node/Electron 的 ABI 版本**，
所以**包自带的 prebuilds 跨 Node 与 Electron 版本通用**。

于是「为 Electron 重编译」这件事对它们是**多余的**。

### 那为什么 `npm install` 还要编译？

因为 `postinstall` 写死了 `-f`（electron-rebuild 的原话：
「Force rebuilding modules, even if we would skip it otherwise」），
而**即使去掉 `-f`，electron-rebuild 也认不出 prebuildify 布局**
（它只查 prebuild-install 的元数据，`lib/module-rebuilder.js:69`）——
所以它对这两个模块**每次都从源码重编**，
连带 Python、MSVC，以及 node-pty 硬写的 `SpectreMitigation: 'Spectre'`（缺它就 MSB8040）。

**→ 已改**：`postinstall` 现在是 `node scripts/ensure-native.mjs`——
**加载不了才编译**。Windows / macOS 有 prebuild → **什么都不做，不需要编译器**；
Linux 没有 node-pty 的 prebuild → 才编译。

### 分三类人，各要装多少

| 谁 | 要装什么 | 说明 |
|---|---|---|
| **用的人**（只想用这个工具） | **零** | 但**还没有打包配置**——`npm run build` 只产出 `out/`，不是能双击的 exe。**开源前必须补 electron-builder**（见 §九） |
| **开发者**（想改代码） | **Node 就够** | `git clone && npm install && npm run dev`。postinstall 改完之后，干净克隆**不需要 Python、不需要 MSVC** |
| **贡献者**（要动原生模块的 C++） | 全套 | 只有改了 node-pty/serialport 的源码、或换 Electron 大版本时才需要 |

## 三、事 B · 物理串口 COM3（**只有 Windows 上才能验的那条通道**）

### B.1 为什么必须你在本地做

沙箱侧我用**虚拟串口设备**（pty 对）验过应用的串口代码——
**驱动是真的 node-serialport**（真 termios、真原始模式），marker 协议认领成功。
但**虚拟设备不是真板子**。

而**应用只认设备路径**（node-serialport 打开 `COM3`）——
它连不了 TCP。所以「应用对着真板子的串口控制台跑一遍」这件事，
**只有 Windows 上的应用能验**。

### B.2 第一步：用**应用自己**打开 COM3（**这才是关键**）

1. **关掉 SecureCRT**（它独占 COM3）；
2. `npm run dev`；
3. 点「板子 · 串口」；
4. **应看到板子的 root 提示符**；
5. 手工输入 `uname -a` 回车 → **应看到一行输出**。

> **这一步过了，M1 的串口判据就真的过了。**
> 沙箱侧验不了这一条——它需要真 COM3。

### B.3 第二步：起串口 TCP 服务（**让我从沙箱远程驱动**）

**不用装任何东西**——`serial-server.py` **零依赖**（Python 标准库 + Win32 API），
在 `C:\Users\Administrator\Desktop\嵌入式Linux学习\90-工具\`。

```powershell
cd "C:\Users\Administrator\Desktop\嵌入式Linux学习\90-工具"
python serial-server.py --port 2323
```

应该输出：

```
[serial-server] COM3 @ 1500000 baud, listening on 0.0.0.0:2323
[serial-server] ready. Ctrl+C to stop.
```

> ⚠️ **它和应用抢 COM3**——所以**先做 B.2（用应用验），再起它**，
> 或者验完 B.2 把应用那个标签关掉再起。

放行防火墙（**只需一次**，管理员 PowerShell）：

```powershell
New-NetFirewallRule -DisplayName "COM3 TCP 2323" -Direction Inbound -Protocol TCP -LocalPort 2323 -Action Allow
```

### B.4 判据

```powershell
# 从宿主自己测（应该回板子的 root 提示符或命令输出）
printf 'uname -a\n' | nc 127.0.0.1 2323
```

> **看不到输出**？先看串口那边：
> - **DCB.BaudRate 要写真实值 `1500000`**，不是索引常量 `12`
>   （写成 12 的话驱动真的按 12 波特设，**一个字节都读不到**，而且**自我掩盖**：读回来还是 12）。
> - **`fFlags` 里 `fRtsControl` 是 2bit 字段，值 0 才是 enable**——
>   写成 `0x04` 是 RTS disable，而 Rockchip 的 `fiq_debugger`/`earlycon` **需要 RTS 有效**。
> - `COMMTIMEOUTS`：`ReadIntervalTimeout=0xFFFFFFFF`、`ReadTotalTimeoutConstant=200`。
>
> 这三条 **工具里已经改对了**（`serial-server.py` 第 126 行有注释记录）——
> 你只需要确认它用的是仓库里这一份，而不是别处拷来的旧版。

### B.5 交回什么

告诉沙箱侧的 agent：

```
串口 TCP 已起：<宿主 IP>:2323
应用自己的串口标签：B.2 的结果（看到提示符了吗？uname -a 有输出吗？）
```

宿主的 IP 有几个（**看 `adb-repair.ps1` 最后打印的列表**——**机器专属的值不进仓库**），
沙箱侧会挨个试。

## 四、事 C · 客机免密 SSH（**一次就够**）

### C.1 装

**不用装**——`sshvm.py` 用 paramiko。装一下：

```powershell
pip install paramiko
```

### C.2 做（**幂等**，反复跑不会把 authorized_keys 撑爆）

```powershell
cd "C:\Users\Administrator\Desktop\嵌入式Linux学习\90-工具"
python sshvm.py bootstrap
```

它会生成 ed25519 密钥并把公钥装进客机。

### C.3 判据

```powershell
python sshvm.py run 'whoami'
```

应该回 `alientek`。

### C.4 为什么必须是 paramiko，**不能用 `ssh.exe`**

宿主 Windows **不允许空密码远程登录**，而 `ssh.exe` 的密码认证在脚本里用不了：
- `SSH_ASKPASS` + `setsid` 直接判 `Permission denied`；
- 要用密码只能 `pty.fork()`（Windows 上没有 `pty.fork`）——
  所以**宿主上改用 paramiko**，它能显式喂密码。

> 沙箱侧则是另一条路：私钥在 `/tmp/id_ed25519`，
> **沙箱重启会丢**——丢了就在沙箱侧重建（`pty.fork()` 喂密码——**密码不进仓库**，见 `90-工具\sshvm.py` 的说明）。

## 六、已知坑（**都踩过，别重复踩**）

| # | 坑 | 症状 | 对策 |
|---|---|---|---|
| 1 | `netsh portproxy` 绑 `0.0.0.0` | **代理转发给自己**——adb 每条命令都 `protocol fault`，连 `kill-server`/`start-server` 都救不回来 | 绑**具体 LAN 地址**；`adb-repair.ps1` 已经这么改了 |
| 2 | adb client 与 server 版本不一致 | `could not read ok from ADB Server` | 两边都用 **r33.0.3** |
| 3 | 探测 adb server 时**必须带 4 位十六进制长度头** | 裸发 `host:version` 连健康 server 也会被关连接，回 0 字节——**分不出健康与坏了** | `host:version` 要发成 `b"000chost:version"` |
| 4 | 串口 DCB 波特率写成索引 `12` | 读不到任何字节，**而且自我掩盖**（读回来还是 12） | 写真实值 `1500000` |

| 6 | `.ps1` / `.bat` 里写中文 | PS 5.1 / cmd 按 ANSI(GBK) 读，乱码里的引号会截断字符串 | **所有 `.ps1`/`.bat` 一律纯 ASCII** |
| 7 | `0xC0000000` 在 PowerShell 里是 Int32 负数 | 赋给 uint32 字段出错 | 显式 `[uint32]0x...` |
| 8 | `SSH_ASKPASS` + `setsid` | 密码认证直接 `Permission denied` | 用 `pty.fork()`；Windows 上用 paramiko |
| 9 | **`postinstall` 里写死 `electron-rebuild -f`** | 干净克隆被迫装 Python + MSVC（+1.6 GB 的 VS），**而这两个包是 NAPI 的、重编译根本多余** | 已改成 `scripts/ensure-native.mjs`：**加载不了才编译** |

## 六之二、共享 node_modules 的原生模块（**装完之后还要看一眼**）

`node_modules` 是**沙箱与本机共享的同一个目录**，而原生模块按平台编译：

| 包 | Linux（沙箱） | Windows（本机） | 冲突吗 |
|---|---|---|---|
| `@serialport/bindings-cpp` | `prebuilds/linux-x64` ✓ | `prebuilds/win32-x64` ✓ | **不冲突**（NAPI）——`build/` 删掉，两边各走各的 prebuild |
| `node-pty` | **没有 linux prebuild**，只能自己编 | `prebuilds/win32-x64` ✓ | **冲突** |

**本机装完依赖后，做这一件事**：

```powershell
Remove-Item -Recurse -Force node_modules\node-pty\build -ErrorAction SilentlyContinue
Remove-Item -Recurse -Force node_modules\@serialport\bindings-cpp\build -ErrorAction SilentlyContinue
```

删掉之后两边都走各自的 NAPI prebuild，**谁也不碍着谁**。
（沙箱侧要 Linux 版 node-pty 的话，跑 `bash scripts/acceptance/linux-natives.sh` 恢复。）

> **不这么做的后果**：`build/` 里是 Linux 的 ELF → 本机加载即
> `invalid ELF header`，**测试文件直接加载失败**
> （2026-11-13 实测：178 条 → 222 条，加载失败的那两个文件里还有一批用例根本没跑到）。

### [其它] 遇到的坑（哪怕最后解决了）

**1. `node_modules` 是 Linux 装的 → 两个原生模块是 ELF，`npm test` 加载即失败**

`node_modules/@serialport/bindings-cpp/build/Release/bindings.node` 与
`node_modules/node-pty/build/Release/pty.node` 的文件头是 `7F 45 4C 46`（ELF）。
后果：`npm test` 里 `tests/unit/serial.test.ts` 与 `tests/integration/registry.test.ts`
**加载就失败**（`bindings.node is not a valid Win32 application`），
`npm run mutation:check` 因此把 C2/M11/M12 判成「红了但红的原因不对」——
**3 项是环境假警报，不是守卫失效**。

修法：`node_modules` 里两个模块的 `build/` 目录整个挪走，
让 node-gyp-build 回落到包自带的 `prebuilds/win32-x64/`（PE，NAPI，ABI 稳定）。
挪走后**测试从 178 条涨到 222 条**（之前加载失败的文件里还有用例没跑到）。

> ⚠️ 这条也解释了档案 §六 坑 1 说的「`node_modules` 与宿主的**是同一份**」——
> 沙箱侧验完留下的就是 Linux 版。

**2. `electron-rebuild` 跑不动：MSB8040「此项目需要缓解了 Spectre 漏洞的库」**

node-pty 的 `binding.gyp` 里硬写了 `'SpectreMitigation': 'Spectre'`，
而本机 VS2019 只装了标准 CRT，**没有 Spectre 缓解库**。

- `npx electron-rebuild -f -w node-pty,serialport` → MSB8040 失败。
- `PYTHONUTF8=1` 必要：否则 node-gyp 的 gyp 阶段先死在
  `UnicodeDecodeError: 'gbk' codec can't decode`（档案 §六 坑 6 说的同一类编码坑，
  只是这次在 Python 侧而不是 PowerShell 侧）。

**最终解法（两步，都不需要管理员权限）**：
1. `node-pty/build/deps/winpty/src/*.vcxproj` 里 `SpectreMitigation=Spectre` 是**工程级属性**，
   `Directory.Build.props` 的属性优先级低于它——所以要放在 **`Directory.Build.targets`**
   （在工程体之后导入）才压得住。写在 `node-pty/`、`node-pty/build/`、`build/deps/`、
   `build/deps/winpty/`、`build/deps/winpty/src/` 五处（winpty 子工程在更深一层）。
2. 压住检查之后变成 `LNK1181: 无法打开输入文件"DelayImp.lib"`——
   链接器去找 `lib\spectre\x64`（不存在）。
   **解法**：把标准库复制成 spectre 目录的样子（需管理员）：
   `mkdir lib\spectre\x64` + `copy lib\x64\*.lib`，`onecore` 同理。

做完这两步，`npx electron-rebuild -f -w node-pty,serialport` **exit 0**。

> 提权方式：`Start-Process cmd.exe -Verb RunAs` **可以**（UAC 能过），
> 而 VS 安装器自己的 `setup.exe modify` 过不去（提示框被自动取消）。
> 这是本机与档案 §一 的差别：**Build Tools 本来就在**（VS2019），
> 缺的是 Spectre 组件——而那个组件用 `setup.exe modify` 装不进去。

**3. 装了 VS2022 BuildTools（1.63 GB），但对本任务没用**

档案 §1.3 要求装 VS Build Tools 2022，我照做了。
但**本机早就装了 VS2019 BuildTools**（C++ 工具集 + Windows SDK 都在），
VS2022 装完也没带来 Spectre 库（`lib\spectre` 目录仍然不存在），
而 VS2022 自己的 `setup.exe modify` 又提权失败。
→ **这一步其实可以不装**。Spectre 的问题最终是用第 2 条的「复制标准库」解掉的，
与 VS 版本无关。**下次按档案走之前先看 `vswhere -products * -format value -property installationPath`**。

**4. CDP 合成按键时 `-` 丢了（不是工程缺陷）**

用 DevTools 协议合成 `uname -a` 时，`-` 没被送进去（板子回 `uname: extra operand 'a'`）。
用真键盘不会有这问题。**这条只影响「怎么敲」不影响「能不能跑」。**

**5. `board-serial-tool.py` 的波特率索引 bug 还在**

`90-工具/board-serial-tool.py:225` 是 `dcb.BaudRate = BAUD_MAP.get(baud, 12)`——
**1500000 会被换成索引 12**，正是档案 §六 坑 4 说的那个坑。
`serial-server.py` 已经改对了（`dcb.BaudRate = baud`），
但 `board-serial-tool.py`（以及同大小的 `board-serial.py`）没改。
→ **本机用它探板子会失败**：`SetCommState 失败 Win32 87`。
（`com-probe.py` 是对的，能开 COM3。）

**6. `docs/02` 记的 COM3 与 WMI 查不到**

`Get-CimInstance Win32_SerialPort` 只列出 COM1；
但 `[System.IO.Ports.SerialPort]::GetPortNames()` 与 PnP 都显示
`USB-Enhanced-SERIAL CH343 (COM3)`。**COM3 是在的**，只是 WMI 那条路查不全。
