# 计划 1 · 工程骨架与终端三通道（工程线 M0–M2）

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 交付一个能用的 Electron 桌面工作台：串口 / ADB / SSH 三个通道都能开终端标签页交互，文件能双向互传，会话日志落盘。

**Architecture:** 三层进程模型——`main` 独占设备 I/O（Electron main），`renderer` 只画界面，`preload` 用 contextBridge 暴露白名单。终端分 **pty 模式**（ssh / `adb shell -t`，板子自己回显并出 ANSI）与 **pipe 模式**（`adb shell` 无 PTY，宿主画提示符并自己回显）——这个区分属于 profile 而不是代码。连接层用统一 `Connection` 接口 + 能力协商（`exec` / `pty` / `files` / `exitCode`），UI 依能力降级。

**Tech Stack:** Electron 34.5.8（内置 Node 20.19.1）· electron-vite 5 · React 18.3.1 · TypeScript 5.9.3 `strict` · vitest 4 · xterm 5.3 · node-pty 1.1 · serialport 13 · ssh2 1.17

**Spec:** `docs/00-项目愿景.md`（§三 第一层、§七 双轨并行）· `docs/02-设备事实清单.md`（A1–A8 / S1–S8 / H1–H2 / G1–G5）· `docs/04-架构设计.md`（§2 进程模型、§3 目录结构、§5.1 链路仲裁、§10 IPC、§13 M0–M2）· `docs/05-决策记录.md`（ADR-D1/D2/D8/D9/D11/D20/D23）· `docs/spec/02-board-pack.md`（§10 绑定与能力）

**为什么先做这条线**：愿景 §七 明确「工程线……与契约零依赖，绝不返工」。M1 是全工程**风险集中点**（node-pty 的 Electron ABI、串口 marker 协议），早失败早改。M0–M2 完成后，规格线（M3+）才有地方放代码。
