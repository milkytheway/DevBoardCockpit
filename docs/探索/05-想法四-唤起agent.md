# 05 · 想法四：唤起 agent —— 探测主机上的 agent，然后让它干活

> **作者**：Codex　**日期**：2026-11-17　**性质**：**探索**（不约束任何人 ✓）
> **想法原文**：「如何让软件具有通知某个agent工作的能力？可以向CC switch或其他AI工具那样
> 先探测主机所具有的agent，然后就可以支持上面提到的一键AI造卡能力？」

---

## 〇 · 结论先行

1. **现在是入站的** ✓ —— agent **主动连到宿主**（MCP HTTP 回环 ✓）→ **宿主不需要知道 agent 存在** ✓
2. **出站会**「**安全面方向反过来**」⚠️ —— 入站时「**能力由宿主授予**」✓；
   出站时 agent **以用户的身份在主机上跑** ⚠️ → **它能做的事不受权限区约束** ✗
3. → **出站必须被当成「宿主代替用户启动一个进程」** ✓ → **这件事本身要是权限区里的一个开关** ✓
   （`host:spawn_agent` ✓ —— 与 `host:install_card` 同款 ✓ ✓）
4. **三种形态，代价差很大** ✓：
   **推送**（只告诉人）✓ **最安全** → **投递**（写进 agent 会看的地方，agent 自己做）✓ →
   **拉起**（宿主 spawn agent CLI 当场做）⚠️ **安全面最大**
5. **有一个更好的中间形态** ✓：**宿主替用户打开一个终端窗口** ✓
   → agent **在用户自己的终端里**跑 ✓ → **完全不碰权限模型** ✓ → **用户全程看得见** ✓
6. **⭐ 有一个比下面三个都更安全的第一形态** ⚠️ ——「**让 agent 自己来看**」
   （MCP 上加一条 `list_tasks` ✓）→ **零出站 ✓ · 权限模型一个字不用动 ✓**
   → **所以「探测主机上有什么 agent」应该整个推迟** ✓（它是「拉起」的前置 ✓）
7. **「活」是什么** → **一个流程包 id + 一组输入** ✓ —— **不是新东西** ✓ → **④ 不需要新产物类型** ✓
8. **探测只做两件事** ✓：**可执行文件在不在** ✓ + **版本号** ✓（版本决定参数形态 ✓）· **且整个推迟** ✓
   → **不读它的配置、不读它的历史** ⚠️（隐私面 ✓）

## 二 · 核心洞察：**安全面的方向** ⚠️

### 2.1 入站（今天）🟢

```
用户 ──授权（权限区）──▶ 宿主 ──授予能力──▶ agent
```

→ **能力是宿主给的** ✓ → **agent 越权 = 宿主没给** ✓ → **一句话说得清** ✓

### 2.2 出站（想法④）⚠️

```
用户 ──▶ 宿主 ──交付任务──▶ agent（在主机上，以用户身份跑）
```

→ **agent 拿到的是「用户的机器」** ⚠️ → **它能读写任何用户能读写的东西** ⚠️
→ **而这一路，绕过了整个权限模型** ✗✗
→ **这是本篇最重要的一句话** ⚠️

> ### **所以「唤起 agent」的正确表述不是「给 agent 授权」，而是「替用户启动一个进程」。**
>
> → 后者**可以**被权限区管住 ✓（它是一个**宿主操作** ✓）
> → 前者**管不住** ✗（因为 agent 是**外部进程** ✓ → **宿主管不了它** ✓）

### 2.3 于是有了 ADR-D47/D48 之后的第四条形态 🟢

| 权限区的现有形态 | 是什么 |
|---|---|
| `action:<id>` | 一个板级动作 ✓ |
| `workflow:<id>` | 一个流程 ✓ |
| `host:install_card` / `uninstall_card` / `promote_card` | **宿主操作** ✓ |
| **`host:spawn_agent`（新增）** | **替用户启动一个外部进程** ✓ ← **想法④ 的位置** ✓ |

→ **它与 `install_card` 是同一类东西** ✓ → **进权限区一行** ✓ → **默认关** ✓（危险动作默认关 ✓ · ADR-D47 ✓）

## 三 · 四种形态（**按安全面从大到小排** ✓）

> ⚠️ **这一节是第二轮补的** ✓ —— 对方探索指出**有一个比我原先三个都更安全的第一形态** ✓
> → **「让 agent 自己来看」** ✓ → **零出站 ✓ · 权限模型不动 ✓** → 详见 [`11` §二.4](11-两份探索的对账.md) ✓

| 序 | 形态 | 怎么做 | 出站？ | 要探测 agent 吗 |
|:--:|---|---|:--:|:--:|
| **0** | ⭐ **让 agent 自己来看** | 宿主在 **MCP 上开一条 `list_tasks`** ✓ → **agent 轮询** ✓ | **零** ✓ | **不需要** ✓ |
| 1 | 投递到文件 | 写进 `tasks_dir` ✓（**与 `cards_dir` 同款** ✓） | 零 ✓ | 不需要 ✓ |
| 2 | 推送 | 写一个「有活了」的标记 ✓ → **人自己看** ✓ | 零 ✓ | 不需要 ✓ |
| 3 | 拉起 | 起一个进程 ✓ | **有** ✓ | **要** ✓ |

### 形态 0 · ⭐ **让 agent 自己来看**（最安全 · **方向根本没变**）🟢

> **为什么它最安全** ✓：
> → **方向没变** ✓ —— 仍然是 **agent → 宿主** ✓（**入站** ✓）
> → **权限模型一个字不用动** ✓ → 「宿主给 agent 授权」这件事**根本不存在** ✓
> → **而且它复用了现成的通道** ✓ —— **MCP 就是给 agent 用的** ✓
>   （发现文件 ✓ · token 认证 ✓ · loopback ✓）
> → **宿主是 MCP 服务端** ✓ → **Claude Desktop / Claude Code 就是客户端** ✓
>   → **「通知 agent」= 让它自己来看** ✓ —— **不是宿主去敲门** ✓
>
> **而「活」是什么** ✓ —— **活 = 一个流程包 id + 一组输入** ✓ → **不是新东西** ✓
> → **④ 不需要新的产物类型** ✓ → **不需要新的契约** ✓
> → **而且它让 ② 与 ④ 咬合** ✓：**② 的可复用粒度 = ④ 能派什么活** ✓

> #### ⚠️ **代价**：agent 得**轮询** ✓ —— 不是「推」✓
> → 对**长任务**（编译要几分钟 ✓）**够用** ✓
> → 对「马上要知道」的场景不够 ✓ → **那时才需要形态 2 的推送** ✓


### 形态① · **推送**（最安全）🟢

> 宿主**只告诉人**「有活要干」，**不碰 agent** ✓

```
宿主 → 桌面通知 / 应用内「待办」条 / 一个 inbox 文件
```

| 维度 | 评估 |
|---|---|
| 安全面 | ✅ **零** —— 宿主没执行任何东西 ✓ |
| 进度可见性 | ⚠️ **宿主不知道 agent 做到哪** ✓ → 人自己切过去看 ✓ |
| 自动化 | ❌ 还是要人来点 ✓ |

> → **最安全，也最没用** ✓ → 但它是**其余形态的地基** ✓（先把「有活」这件事表达出来 ✓）

### 形态② · **投递**（agent 自己做）🔵

> 宿主把任务写进 **agent 会自己看到的地方** ✓ → **agent 决定什么时候做** ✓

```
候选落点：
  · 一个 inbox 目录（如 <userData>/agent-inbox/*.md）
  · Claude Code 的 CLAUDE.md / 项目级 instructions
  · Codex 的 AGENTS.md（**本工程就有 AGENTS.md ✓** ← 一个现成的例子 ✓）
  · 一个 MCP 通知（但 MCP 是入站 ✓ → agent 得轮询 ✓）
```

| 维度 | 评估 |
|---|---|
| 安全面 | ✅ **低** —— 宿主只**写了文件** ✓（像 `install_card` 一样 ✓） |
| 自主性 | ✅ 高 —— **agent 用自己的方式做** ✓（用哪个模型、什么计划 ✓ 都是它的事 ✓） |
| 进度 | ❌ 宿主看不见 ⚠️ → 除非 agent 回报 ✓ |
| 宿主怎么知道做完了 | 🔵 **agent 回来调 MCP** ✓（比如 `install_card` ✓）→ **闭环成立** ✓ |

> → **「投递 + agent 回报」= 一个完整的闭环** ✓ —— 而**闭环的那一环已经有了** ✓（MCP ✓）
> → **这一条我推荐** ✓

### 形态③ · **拉起**（宿主 spawn agent CLI）⚠️

> 宿主**当场启动** agent 的 CLI，让它跑一个 prompt ✓

```
claude -p "<prompt>"          /  codex exec "<prompt>"  /  gemini -p ...
```

| 维度 | 评估 |
|---|---|
| 自主性 | ✅ 最高 ✓ |
| 进度可见性 | ✅ **宿主能看 stdout/stderr** ✓（`spawn.ts` ✓） |
| **安全面** | ⚠️ **最大** ✓ —— 宿主在**代替用户执行一个外部进程** ✓ |
| **可移植性** | ⚠️ **每个 agent 的参数形态不同** ✓ → **要一张适配器表** ✓ |
| 交互性 | ⚠️ agent 可能要问问题 → **非交互模式下会卡住或瞎猜** ✓ |
| 凭据 | ⚠️ agent 用**它自己的**登录态 ✓ → 宿主不碰 ✓（好 ✓） |

> → **形态③ 是用户最想要的** ✓（「一键」）✓
> → **但它是最需要设计安全面的** ✓

---

## 四 · 形态③ 的中间解：**「替用户打开一个终端窗口」** 🔵

> **这是本篇我最想推荐的一条** ✓

```
宿主 → 在用户的终端里跑：claude -p "<prompt>"     ← **可见的窗口** ✓
```

| 为什么它比「静默 spawn」好 | 说明 |
|---|---|
| **用户全程看得见** ✓ | 一个真终端窗口 ✓ → **不是黑盒** ✓ |
| **不触碰权限模型** ✓ | 因为它**就是用户在终端里敲了一条命令** ✓ → 语义完全一样 ✓ |
| **agent 看得见人的环境** ✓ | PATH ✓ · 环境变量 ✓ · 用户的 shell 配置 ✓ |
| **交互自然** ✓ | agent 要问问题 → **用户直接回答** ✓ |
| **凭据不经过宿主** ✓ | agent 用自己的登录态 ✓ |
| **宿主只做一件事** ✓ | **起一个可见的终端** ✓ —— 这在权限区里是**一个明确的动作** ✓ |

> → **它把「出站」从「宿主授权 agent」降级成「宿主替用户敲了一条命令」** ✓
> → **安全面几乎等于零** ✓ → **可以进权限区，也可以只在「用户点了之后」做** ✓

### 4.1 但它有个前提 ⚠️

> **宿主在 Windows 上怎么「打开一个可见的终端」？** 🔵
> → `cmd /c start "" powershell -NoExit -Command "..."` ✓（Windows Terminal / PowerShell ✓）
> → **但这需要一个 shell** ⚠️ → **macOS / Linux 上又是另一套** ⚠️
> → **本工程是 Windows 优先** ✓（宿主是 Windows ✓）→ **先做 Windows** ✓ → 其他平台留接口 ✓

## 五 · agent 探测（像 CC Switch）🟢

> ⚠️ **整个推迟** ✓ —— 它是**形态 3「拉起」的前置** ✓，而形态 3 最晚做 ✓
> → **今天完全不用写那行探测** ✓ → 详见 [`11` §二.4](11-两份探索的对账.md) ✓

### 5.1 探测什么

| 项 | 怎么探 | 用来干什么 |
|---|---|---|
| **可执行文件在不在** | `where.exe <name>` ✓（Windows ✓）· 常见目录兜底 ✓ | **列出候选** ✓ |
| **版本** | `<name> --version` ✓ | **决定参数形态** ✓（见 §六 ✓） |
| **能不能非交互跑** | 不探 ✓ —— **用一个极轻的探测命令试** ✓（如 `--help` ✓） | 决定**能不能用这个形态** ✓ |
| **登录态** | 🔵 **不探** ⚠️ —— 读它的配置= **碰用户的隐私** ✓ | |

### 5.2 候选清单（**封闭的** ✓ —— 与契约的封闭词表同款思路 ✓）

```
claude      → Claude Code
codex       → Codex CLI
gemini      → Gemini CLI
aider       → Aider
cursor-agent→ Cursor Agent
cline       → Cline（若是 CLI 形态）
opencode    → OpenCode
```

> → **封闭清单** ✓ → **认不出就不认** ✓ → **不猜、不扫全盘** ✓
> → **扩展方式 = 改那张表** ✓（像 `requires.capabilities` 的封闭词表 ✓）

### 5.3 **不**做什么 ⚠️

| 不做 | 为什么 |
|---|---|
| **不读 agent 的配置/历史/session** | 那是**用户的隐私** ⚠️ |
| **不扫整个磁盘找可执行文件** | 慢 ✓ · 且可能命中恶意文件 ⚠️ |
| **不自动执行 agent** | 那是**形态③** ✓ → **要人点** ✓ |
| **不把探测结果上传任何地方** | 隐私 ✓ |

## 六 · 适配器表（**每个 agent 一行**）🔵

```ts
interface AgentAdapter {
  id: string;                       // 'claude'
  label: string;                    // 'Claude Code'
  binary: string;                   // 'claude'
  /** 非交互跑一个 prompt 的参数形态 ★ */
  runArgs: (promptFile: string) => string[];
  /** 怎么把「让它造卡」的提示词递给它 */
  promptVia: 'arg' | 'stdin' | 'file';
}
```

| agent | 可能的形态 | 备注 |
|---|---|---|
| `claude` | `claude -p "<prompt>"` | 🔵 待实测 |
| `codex` | `codex exec "<prompt>"` | 🔵 待实测 |
| 其他 | 🔵 | **逐个实测** ✓ |

> → **这张表必须实测** ✓ → **不能照抄文档** ✓（CLI 形态会变 ✓）
> → **每行都要有单测** ✓（断言参数形态 ✓）

### 6.1 提示词怎么写 ⚠️

> **提示词里能放什么** ⚠️ —— 这是**数据出宿主**的边界 ⚠️

| 可放 | 不可放 |
|---|---|
| 画布产出的**规格** ✓（流程包 + manifest + 人话 ✓） | **凭据** ⚠️（私钥路径 ✓ · 密码 ✓） |
| `get_card_sdk_docs` 的内容 ✓ | **板子的实时读数** ⚠️（除非人明确勾选 ✓） |
| 卡片落位目录 ✓ | **其他用户的数据** ⚠️ |

> → **提示词必须能被人先看一遍** ✓ → **进权限区之前先显示** ✓
> → 或者：**提示词落成一个文件，让人在编辑器里看** ✓ ← **更安全** ✓

## 七 · 代价

| 项 | 量级 | 说明 |
|---|---|---|
| 探测（可执行文件 + 版本） | 小 | `where.exe` + `--version` ✓ |
| 适配器表 + 单测 | 小 | 每个 agent 一行 ✓ |

## 九 · 一句话

> **「唤起 agent」这件事，本质不是「让 agent 干活」，是「替用户启动一个进程」。**

>
> 而**闭环那一环已经有了** ✓ —— agent 造完卡，**自己调 `install_card`** ✓ → 宿主看得见 ✓。
