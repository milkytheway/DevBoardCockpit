## 〇 · 结论先行

1. **四个想法不是四个独立 feature，是一条链** ✓：
   **① 发现板子 → ② 把能力组装成「一件事」 → ③ 把「一件事」摆成一份规格 → ④ 把规格交出去做** ✓
2. **② 的一半已经存在** ✓ ——「一张卡包含多条流程」**今天就能做** ✓（卡片 manifest 的 `workflows` ✓）
   → **而且想法② 已经在代码里发生了** ✓ —— DSH v0.11（`38946db` ✓）把编译流程拆成三段，
   **同一段步骤被复制了三份** ✓ → **参数已经开始漂** ✓（`build_dir` 在 `build-run` 里必填、
   在 `compile`/`upload` 里是默认值 ✓）→ **详见 [`03` §1.4](03-想法二-流程包可组装.md) ✓**
3. **③ 的正确形态是「画布产出规格，不产出代码」** ✓ —— 因为卡片**没有构建步骤** ✓（沙箱 + CSP ✓）
4. **④ 的安全面是反的** ⚠️ —— 出站唤起 agent **绕过了整个权限模型** ✓ →
   **最安全的形态是「宿主替用户打开一个终端窗口」** ✓（不碰权限模型 ✓）
5. **建议顺序**：**① → ②(fragment) → ③ → ④(推送) → ②(call) → ④(拉起)** ✓
6. **⭐ 想法① 有个关键突破** ✓ ——「**通用元操作 → 试出真相 → 实例化出这个板的包**」✓
   **打破了「先有板型包才能连板」的鸡生蛋** ✓ ✓ → 详见 [`02`](02-想法一-接板向导.md) ✓
   → **而且这条路已实测** ✓：一份 `generic-linux` 草稿**在真板上探出 4/4 全绿** ✓
   （读到了 `ATK-DLRK3588 Board` ✓ 与 `Buildroot 2024.02` ✓）✓
6. **①②③ 全部可以做到「契约零改动」** ✓ —— 它们是**实现层**的事 ✓；
   只有 **②的 call 形态**要动契约（加第 7 种 step kind ✓）

## 三 · 贯穿四个想法的**五条硬约束** 🟢

这五条**不是设计偏好，是工程的既成事实** —— 任何方案都必须绕开它们。

### 约束① **卡片没有构建步骤** 🟢

```
CSP: default-src 'none'; script-src 'self'; connect-src 'none'
卡片 = 免构建 ES Module（ADR-D4 / ADR-D14）
```

→ **任何「生成代码 → 编译 → 打包」的方案都出局** ✓
→ 「一键造卡」只能是**生成几个文件** ✓（`manifest.json` / `index.html` / `card.js` / `style.css` ✓）
→ **画布不能是「可视化编程」** ✓ → 它只能是**脚手架 + 规格** ✓

### 约束② **权限模型只有一个方向** 🟢

```
入站：agent ──HTTP 回环──▶ 宿主   （能力由宿主授予 ✓ · 权限区说了算 ✓）
```

→ **出站（宿主拉起 agent）不在这套模型里** ⚠️
→ 想法④ 必须**另立一条规矩** ✓，否则等于**绕过整个权限模型** ⚠️

### 约束③ **契约层已冻结且有版本纪律** 🟢

`docs/spec/` 六份 + 增量 v2–v6；`devboard/v1` 尚未发布 → 增量走「v1 定稿前的修正」口径（**不升版本** ✓ · ADR-D27 先例 ✓）

→ **①②③ 都能做到契约零改动** ✓（纯实现层 ✓）
→ **②的 call 形态**要加第 7 种 step kind → **要评审** ✓（ADR-D15 ✓）

### 约束④ **契约层冻结的另一个方向：能力是封闭词表** 🟢

`transports: serial | adb | ssh | local`（4 种 ✓）· `requires.capabilities: {shell, exec, files}`（`stream` 未落地 ✓）

→ **「广泛支持接入一张新板」的上限 = 这 4 种传输** ✓
→ **但「板」可以是无限的** ✓ → 关键不在**多接几种传输** ✓，
  而在**「没见过的板也能被接进来」** ✓ → **发现式建板型包** ✓（[`02`](02-想法一-接板向导.md) §五 ✓）

### 约束⑤ **产物与真源分离** 🟢

种子 → 映射 → 别名 三层（+ 材质层 ✓）· 生成脚本 ✓ · 机械判据 ✓

→ **凡是「跑起来才算数」的东西，都要有判据** ✓
→ 想法③ 的「一键造卡」= **写文件 + 校验 + 安装** ✓
→ **已有** ✓：`validate_card` ✓ · `install_card` ✓ · `get_card_sdk_docs` ✓ → **管道 90% 已存在** ✓

## 四 · 依赖链与优先级

### 4.1 依赖链（**这是本篇最重要的一张图**）

```
        ① 接板向导
        │  人只做一件事：选 COM + 波特率 ✓
        │  向导做剩下的：第一个真相 → 通用元操作逐个试 → 真相表
        │  产出：**这块板的初版包**（诚实但粗 ✓）+ **真相表** ✓
        │  缺了它：换一块板 = 手写 JSON
        ▼
   能力（动作 × 15 · 读数 × 7+4）
        │
        ▼
        ② 流程可组装
        │  产出：可复用的「一件事」（读 + 控 + 测）
        │  形态：fragment（参数化片段）→ call（嵌套编排）
        ▼
        ③ 组装画布
        │  产出：**一份规格**（流程包 + manifest 骨架 + 一句人话）
        │  ⚠️ 不产出代码（约束①）
        ▼
        ④ 唤起 agent
           产出：卡文件 → validate_card ✓ → install_card ✓
           形态：推送（最安全）→ 投递 → 拉起（安全面最大）
```

### 4.2 一个**反直觉**的结论

> **④ 看起来是终点，其实是最不该先做的。**
>
> 因为 **③ 产出的「规格」既可以交给人，也可以交给 agent** ✓ →
> **④ 是 ③ 的一个「出口」**，**不是一个前置** ✓。
>
> → **③ 可以先独立落地** ✓（画布 + 规格 + 人照着写 ✓），
> **④ 之后接上只是多一个出口** ✓。
>
> → **别让「等 agent」卡住「画布」** ✓。

### 4.3 优先级建议

| 序 | 事 | 为什么是这个序 | 契约 |
|---|---|---|---|
| **P0** | **① 接板向导** | **价值最高**（换板不用手写 JSON ✓）· **纯实现层** ✓ · 风险低 ✓ | **零改动** ✓ |
| **P0** | **② 的 fragment 形态** | 复用地基 ✓ · **不引入嵌套运行语义** ✓（取消/审计/超时都不用穿一层 ✓） | **零改动** ✓ |
| **P1** | **③ 画布** | 把 ①② 的产物**可视化** ✓ · **规格化** ✓ · **与 ④ 解耦** ✓ | **零改动** ✓ |
| **P2** | **④ 的「推送」形态** | 安全面最小 ✓（只是告诉人「有活」）✓ | 零改动 ✓ |
| **P2** | **④ 的「投递」形态** | 写进 agent 会看的地方 ✓ · agent 自己决定何时做 ✓ | 零改动 ✓ |
| **P3** | **② 的 call 形态** | 嵌套运行语义最重 ✓（取消穿透 / 审计归属 / 递归限深 ⚠️） | **要评审** ✓ |
| **P3** | **④ 的「拉起」形态** | 安全面最大 ⚠️ | **要评审** ✓ |

## 五 · 一条**贯穿性的设计原则**（四个想法共用）

> ## **发现归机器，判断归人，创作归 agent。**

| 环节 | 谁做 | 为什么 |
|---|---|---|
| **发现**（这块板有什么、哪些路能通、哪些读数绿） | **机器** ✓ —— 探针与向导 | **事实不需要人判断** ✓（人判断事实只会出错 ✓） |
| **判断**（选哪种连接、这个流程要不要、这个动作危不危险） | **人** ✓ —— 权限区与向导的确认步 | **这是人的权责** ✓（ADR-D48 的文化 ✓） |
| **创作**（这张卡长什么样、这段流程怎么组织） | **agent 或人** ✓ | 「AI 可造卡」是产品主线 ✓（愿景第三层 ✓） |

> **这四个想法如果各自按这条原则设计，它们会拼成一套** ✓；
> 如果各自为政，就会长成四个互不相干的功能 ✓。

## 六 · 未决问题（**要人拍板** ✓）

| # | 问题 | 我的倾向 | 影响 |
|---|---|---|---|
| **Q1** | **接板向导要不要「自动写盘」**？ | **自动** ✓（第二轮改了 ✓）—— 落的东西要么只读 ✓、要么受权限区管 ✓ → **多问一句就是多一次打断** ✓ | 决定向导是「向导」还是「自动化」✓ |

| **Q5** | **画布的规格用什么格式** —— 新格式还是复用现有的？ | **复用** ✓ —— 流程部分就是**流程包 YAML** ✓ · 卡片部分就是**manifest 骨架** ✓ · 再加**一段人话** ✓ | 决定③ 的存储与 agent 接口 ✓ |
| **Q6** | **唤起 agent 的形态** —— 推送 / 投递 / 拉起？ | **先推送 + 投递** ✓ —— 拉起等「打开一个终端窗口」的方案验证过再说 ✓ | 决定④ 的安全模型 ✓ |
| **Q7** | **agent 探测做到什么程度** —— 只找可执行文件？还查版本？还查登录态？ | **可执行文件 + 版本** ✓ —— **版本决定参数形态** ✓（`claude -p` vs `codex exec` ✓）；**不查它的配置与历史** ⚠️（隐私面 ✓） | 决定④ 的适配器表 ✓ |

## 七 · 现在**不**建议做的事（**写清楚，免得被当成漏做** ✓）

| 项 | 为什么 |
|---|---|
| **先做 ④ 再做 ③** | ③ 的产物**本来就该能给人和 agent 用** ✓ → ④ 是出口不是前置 ✓ |
| **让 ③ 生成代码** | 约束① ✓ —— 卡片**没有构建步骤** ✓ |
| **让 ④ 直接给 agent 授权限** | 约束② ✓ —— **那等于把入站的权限模型倒过来用** ⚠️ |
| **把「发现式建包」做成全自动落盘** | Q1 ✓ —— 自动落盘 = 自动写一个**会执行命令的东西** ✗ → 必须人审 ✓ |
| **在契约层加第 7 种 step kind**（②的 call） | 契约冻结有纪律 ✓ → 先把 fragment 做出来，**证明真的需要 call** ✓ |
