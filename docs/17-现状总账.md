### 1.3 计划 3 · 运行时接进应用（M4.5）✅ 已达成（真机验收已过）

**这是计划 2 之后最重要的一段**：M3/M4 交付的是「一个质量不错的库」，
但那个库的消费者**只有 `probe:board`**。现在**值会自己在动**。

| 模块 | 做什么 | 关键约束 |
|---|---|---|
| `hal/round-trip-queue.ts` | 一次往返的队列（契约 §1.2.1） | **同一时刻只有一次往返在飞**；动作优先；**队列不自己超时** |
| `tags/scheduler.ts` | 按 `interval_ms` 驱动采样组 | **一切经队列**；**跳过本周期，不补发** |
| `tags/binding.ts` | 板型包 ↔ 连接绑定（契约 §十） | 连接指名优先；否则**读一次型号**自动识别；**不猜** |
| `tags/runtime.ts` | 建连接 → 绑包 → 校验 → 起调度器 | 读数**只经 TagStore** 进出；晚订阅**不丢当前值** |
| `ipc-contract.ts` + `preload` + `renderer/tags/ReadingsPanel.tsx` | 两条通道 + 最小读数面板 | 显示规则**照抄契约 §2.1**（`stale`/`error` **要显示旧值**） |

**两个通道都要有**：`tags:readings`（**当前快照**）+ `tags:changed`（**变化推送**）。
只推不取会漏掉晚订阅的人；只取不推则值不会自己动。

### 1.4 计划 4 · 卡片框架（M5）✅ 已达成（**真机实测过**）

**M5 = 让一张 AI 写的 HTML 卡片安全地跑起来。** 这是产品的主线——
看板子的读数不该由人写代码，而该由 AI 造一张卡。

| 模块 | 做什么 | 关键约束 |
|---|---|---|
| `cards/manifest.ts` | manifest 的**封闭 schema** | 未知字段**每一层**都报错（拼错的字段不能静默忽略） |
| `cards/validate.ts` | 契约 §九 的 **13 条**校验 | 「**未验证 ≠ 不合法**」（离线时规则 5 是警告不是错误） |
| `cards/permissions.ts` | 权限集计算 | 读权限按**模式**覆盖判 |
| `cards/roots.ts` + `registry.ts` | 两个根 + 实例分配 | **用户目录优先**（改内置卡即生效）；**不合法就保留上一版** |
| `cards/paths.ts` | 路径解析与**穿越防护** | 词法判据 + **真实路径再判一次**（软链是最常见的绕过） |
| `cards/protocol.ts` | `cockpit://` 处理器 | 每张 HTML 都带 **CSP 响应头**；注入 **bridge + CSP 监听**（带实例 id 的**绝对 URL**） |
| `cards/api-registry.ts` + `bridge-script.ts` | 卡片 API 的**单一真源** | bridge 脚本**由注册表生成** → 两边不可能对不上 |
| `cards/session.ts` + `tags-service.ts` | 会话与**读侧过滤** | 「没权限」与「没有这个 tag」**长得一模一样**（不泄露存在性）；**通配订阅每次推送再判一次** |
| `cards/storage.ts` | 每卡一个命名空间 | 单键 64 KB / 总量 1 MB；**存储在兄弟目录**（不在 watcher 盯着的卡片根里） |
| `cards/runtime-log.ts` + `csp-script.ts` | 运行时日志与 **CSP 违规捕获** | 违规用**卡片文档里的 DOM 事件**抓（`console-message` 归属不到卡，见 ADR-D29 §七） |
| `renderer/cards/broker.ts` | 页面侧经纪人 | **认人两次**（`event.source` + `instanceId`）；每卡一条**私有端口** |

**主题**：token 三层（种子 → 映射 → 别名）+ 生成脚本 + `gen:theme:check` 守着它与种子一致。

> **这一段经过一次整支评审**（`docs/superpowers/plans/2026-11-14-plan4-卡片框架与布局.md`）：
> 评审在沙箱里下了 Linux 版 Electron 真跑，**查出 4 条 Critical + 6 条 Important**——
> 共同点是**症状是「什么都不显示」，而且不报任何错**。
> 已全部修完（`docs/05` ADR-D29），并**用真机复验**：
> 卡片能装上、bridge 能用、CSP 违规三类全中、越权读不泄露存在性。
> **又靠真机查出两条单测查不出来的**：CSP 违规的归属信息（`sourceId` 是空串）
> 与 bridge 顶层方法的形状（`cockpit.capabilities()` 报 TypeError）。

### 1.5 真机实测（计划 3）

| 事 | 结果 |
|---|---|
| `probe:board --profile board-adb` | ✅ **11 个 reader 全绿**（真板子 `f34dca7784396ab2`）——输出存档在 `docs/06` §五·3 |
| `probe:board --profile board-serial` | ✅ **11 个 reader 全绿**（串口 COM3@1500000）——输出存档在 `docs/06` §五·4 |

> **串口第一次跑是 11/11 全部超时**——根因**不是代码**：宿主上计划 1 验收留下的
> `serial-server.py` **独占打开了 COM3**，**回包被它吃掉**（板子是活的、串口是通的，
> 但应用自己的 exec 永远等不到）。停掉它之后同一条命令全绿。
> **这条也证明了契约 §1.2.1 的「一次往返互斥」在串口上真的能用**：
> 三个 reader 的合成命令**一行**发出去（事实 S6），marker 把三段分开，**没有串台**。

### 4.2 计划 3 的裁决（4 条：**设计不许漂移**）

| # | 裁决 | 若错的代价 |
|---|---|---|
| 10 | 往返队列的**接口里没有 `timeoutMs`**——超时是**传输层**的事 | 队列自己判超时 → 传输层还在等 marker 时放行下一次往返 → **下一次认领上一次的残留回包**（RF-2）。**堵住是看得见的，串台是看不见的** |

### 4.4 ADR-D27 的五条（用户委托给我的判断，2026-11-13）

用户明确：「拍板点这几个，就按你觉得合适的来」。这五条**是我的判断**，不是用户逐条选的——
所以每条都带**若错的代价**，方便以后推翻。

| # | 判断 | 若错的代价 | 怎么发现错了 |
|---|---|---|---|
| 18 | **地板认 basename**（`/sbin/reboot` 命中） | 多拦了一些无害命令（假阳性）——**安全侧的错** | 有人抱怨「一个无害动作被要求二次确认」 |
| 19 | **`erase`/`burn` 退回精确** | `erase_all` / `burn_flash` 这类写法**仍然不命中**（假阴性）——**不安全侧的错** | 真机上有人跑这两种命令而没被拦 |
| 20 | **`not_in_pack` 合并进 `not_found`** | 丢掉了「不在包里」这层区分——但它在 `detail` 里 | 卡片作者抱怨分不清「我要错了」与「板子没有」 |
| 21 | **主体 UI 不引 antd** | 组件样式要自己写（工作量变大），而视觉**可能**不如 antd 精致 | 用户看到界面觉得「不如 antd 好用」——**token 层就是换皮的接口** |
| 22 | **`mkfs*` / `flash*` 前缀** | `mkfs_ext4` 之类的变体不命中 | 真机上有 `mkfs` 的变体写法而没被拦 |

**其中 19 与 20 是两个方向的取舍**：19 选了「少假阳性」，
20 选了「少一个码」——**都偏向可用侧**，
而 18/22 偏向安全侧。
**安全侧与可用侧冲突时，地板偏安全**（它是「下限不是上限」），
**错误码偏可用**（它只是提示）。**这个不对称是有意的。**

## 五、已知的坏味道与边界（**不是 bug，但要知道**）

| # | 事 | 影响 |
|---|---|---|
| 1 | **Linux 沙箱与 Windows 宿主共享一份 `node_modules`** | 宿主每次 `npm install` 都会把 Linux 的平台包换成 Windows 的 → 沙箱的 vitest 起不来。**修法**：`scripts/acceptance/linux-natives.sh backup`（宿主 install **之前**）/ `restore`（之后）。已做过一次，现在两个平台的包并存 |
| 2 | **`npm audit` 报 18 个漏洞** | `npm audit --omit=dev` → **0 个**。全在 dev 工具链里（electron/vite/vitest/happy-dom）。**别跑 `npm audit fix --force`**——会动大版本，把钉死的版本弄坏 |
| 3 | **lock 里有 450/540 个条目缺 `resolved`** | 老账（安装前就有 485 个缺）。后果：npm 无法把 `allowScripts` 钉到版本（按名字批准反而更好）。`npm ci` 仍能按 name+version 装 |
| 4 | **串口是独占的**：运行时与终端标签各要一条连接 | 同一个 COM3 上只能有一个。第二个会失败，而失败是**看得见的** |
| 5 | `proc_stat` 的占用率对应一个**未知的采样窗口** | 间隔不固定时那个百分比没有意义——reader 拿不到时间戳（docs/06 C15） |
| 6 | **`gpu.usage` 的「是利用率」仍只有空闲读数** | 缺一次带负载的采样（T3） |
