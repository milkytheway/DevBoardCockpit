### 二、四处分歧（**都带实测数据**）

#### 分歧 1 · 强调色：`#58A6FF`（docs/22） vs `#3CC6D0`（本文）——**建议改**

| | docs/22 | 本文 |
|---|---|---|
| 暗色强调色 | `#58A6FF` | `#3CC6D0`（青） |
| 亮色强调色 | `#3370FF` | `#0C737D` |

**两条理由**：

1. **`#58A6FF` / `#58a6ff` 是 GitHub Primer 暗色的默认强调蓝**——
   它是**最常见的开发者工具默认色**。而 `frontend-design` 明确把
   「近黑底 + 单一饱和强调色」列为 AI 生成设计的常见特征。
   本文主张**换掉它**，理由不是「不一样」，而是下面这条。
2. **蓝色在航空语义里已经有职务**。ECAM 谱系里：
   **蓝色 = 「要执行的动作 / 限制」**（如「禁止起飞」「可放行」）。
   如果强调色是蓝，那么「蓝色的东西」就有两种含义：
   **「这是可交互的」** 与 **「这是需要你执行的操作」**。
   在一个**控制面**产品里这两种含义必须分开。
   → **强调色用青**，语义色（绿/琥珀/红/灰）留给状态。

#### 分歧 2 · 字体：Inter + JetBrains Mono（docs/22） vs **Bahnschrift** + Cascadia Mono（本文）——**建议改**

| | docs/22 | 本文 |
|---|---|---|
| UI | `Inter / Segoe UI Variable / system-ui` | `Segoe UI Variable / system-ui`（正文）+ **Bahnschrift**（仪表标签与数字） |
| 等宽 | `JetBrains Mono / Cascadia Mono / monospace` | `Cascadia Mono / Consolas / monospace` |

**两条理由**：

1. **Inter 不是 Windows 自带的**。它要么**打包进应用**（+几百 KB，且要处理
   `cockpit://` 的字体加载与缓存），要么**走 CDN**（**违背产品的离线属性**——
   这个工具的整个卖点就是「插上板子就能用」）。而 **Bahnschrift 是 Windows 自带的**
   （**本机已核实**：`C:\Windows\Fonts\bahnschrift.ttf`，注册表家族名 `Bahnschrift`），
   **零成本、零打包、离线可用**。
2. **Bahnschrift 就是 DIN 1451 的变量字体**（1931 年的德国工程标准字型，
   用于交通标识与仪表，Windows 10 1709 起随系统分发，Xbox 的 UI 字型）。
   **它就是「仪表标签」这个隐喻的字面答案**。
   它的**窄体变体**（`Bahnschrift Condensed`）正好做密排的丝印标签——
   这是 Inter 给不了的。JetBrains Mono 也可换成 Cascadia Mono（同样系统自带）。

#### 分歧 3 · 暗色基底：`#0A0C0F`（docs/22） vs `#0E1417`（本文）——**建议改（次要）**

`#0A0C0F` / `#12151A` 这一族正是 `frontend-design` 点名的
「近黑 `#0B0B0B` / `#111` 顶替黑色」那一族。
本文的 `#0E1417` **带一点冷青**——纯黑会让发光元素（状态灯、曲线）显得脏。
差别很小，但**它是免费的差异化**，而且实测对比度更好（本文的 text 在 bg 上 15.28，
docs/22 的 `#E6EAF2` 在 `#0A0C0F` 上约 17.6——正文都很好，
差别在**次要色**上，见分歧 4）。

#### 分歧 4 · **浅色主题的对比度：docs/22 的语义色实测不达 WCAG AA** ——**这条必须改**

我把 `docs/22` §7.2 的浅色色板按其自身标注的底色实测：

| token | 值 | 底色 | 实测对比度 | 判定 |
|---|---|---|---|---|
| `--warn` | `#FF7D00` | `#FFFFFF` | **2.57** | ❌ **橙色在白底上几乎读不出来** |
| `--ok` | `#00B42A` | `#FFFFFF` | **2.78** | ❌ |
| `--unknown` | `#8F959E` | `#F5F6F7` | **2.79** | ❌ 而它要承载「不可用 · 原因」 |
| `--text-2`（标注） | `#8F959E` | `#FFFFFF` | **3.02** | ❌ 小标签用色 |
| `--unknown`（暗） | `#6E7681` | `#161A20` | **3.80** | ❌ |
| `--text-2`（暗） | `#6C7787` | `#161A20` | **3.85** | ❌ |

**这是「浅色主题直接复制暗色色板」的典型失败**：暗底上 `#FF7D00` 很醒目，
白底上它几乎消失。**浅色主题的语义色必须单独调过一遍**（降饱和、压明度）。

**本文的浅色主题实测**（§3.6）：全部 ≥ 4.51，
`--warn #8A5A00` 在白底上是 **5.93**，`--unknown #627077` 是 **5.12**。

> **这条不是审美分歧，是可访问性缺陷。**
> 而且 `unavailable` 尤其不能将就 —— 它承载的是「这块板不提供这个能力」这句话，
> 读不到就等于把「不可用」说成了「正常」，**直接违背契约的核心承诺**。

## 〇之二 · 设计主张

> **它是一台仪器，不是一个网页。**

开发板驾驶舱的用户是**整天开着它的嵌入式工程师**。
他们熟悉的东西是：示波器、逻辑分析仪、串口终端、编译器的构建面板、
航空/工业的告警面板。**不是** SaaS 后台。

所以整个设计的落点是三条：

1. **状态先于数字** —— 先看灯，再看数。数会骗人，灯不会。
2. **「不可用」必须不像一个数** —— 这是契约 `unavailable ≠ 0` 的**视觉兑现**，
   也是这个产品与「把板子画成漂亮的仪表盘」之间最本质的区别。
3. **密度是礼貌** —— 工程师的时间按秒算。留白是给海报的，不是给仪表台的。

## 一、调研：参考谱系

我把同类产品的设计翻了一遍，取舍如下。**每一行都写明「取什么 / 不取什么」**——
不取的东西和取的东西一样重要。

| 参考 | 它解决什么 | **取** | **不取** |
|---|---|---|---|
| **航空 EFIS / ECAM**（Airbus A320 告警显示） | 飞行员的五种状态：立即处理 / 要知道 / 正常 / 提示 / 特别 | **状态色语义**（红=立即处理、琥珀=要知道、绿=正常、蓝=要执行的动作、白=标题）+ **failure flag**（数据失效时显示旗标而不是空白） | 复杂的多层 HMI、语音告警 |
| **DIN 1451 / Bahnschrift** | 1931 年的德国工程标准字型，交通与仪表标识用 | **Bahnschrift**（Windows 自带的 DIN 1451 变量字体）做仪表标签与数字 | 全站 DIN（正文可读性不够） |
| **Sigrok PulseView** | 逻辑分析仪 | **「主视图就是波形」**（它明说 most space is used up by the main trace view）+ 细网格 graticule | 多通道协议解码器的复杂度 |
| **Wireshark** | 抓包分析 | **顶栏过滤条**（一条横贯的、即时生效的过滤）+ 「列表/详情」的分割 | 三窗格、逐字段树 |
| **Grafana** | 时序面板 | 面板密度、阈值线的克制 | **它的默认蓝灰色板**（那是我们要避开的） |
| **Renode** | SoC 模拟器的每外设监视器 | 「**板子级能力视图**」的概念 | 模拟器本身 |
| **NASA Web Design System** | 高可达性的语义色 | 「语义色只用于状态，不用于装饰」 | 其品牌蓝 |
| **通用 SaaS 暗色仪表盘**（Dribbble/Behance 那一类） | —— | —— | **整类都不取**：同质圆角卡片、统一柔和阴影、渐变做装饰、居中大数字配小标签 |

> 最后一行是这一版设计的**主要对手**。AI 生成的仪表盘长一个样：
> 同一种圆角、同一种 `rgba(0,0,0,.1)` 阴影、渐变扫光、
> 「一个大数字 + 一个小标签 + 一条渐变强调」的英雄区。
> **本设计刻意不这么做**，理由见 §二与 §六。

## 二、五条设计原则

| # | 原则 | 具体含义 |
|---|---|---|
| **P1** | **状态先于数字** | 任何读数单元里，**状态灯在数字左边**，且灯的形状能单独区分状态。色盲用户只看形状也能读全五种状态 |
| **P2** | **不可用不是零** | `unavailable` 的格子里**不出现数字**——出现的是一条**斜纹**与一行原因。`0` 与「读不到」在视觉上不可能混淆 |
| **P3** | **密度是礼貌** | 正文 13px、行高 1.45、单元间距 8px 的整数倍。数字一律**等宽表格数字 + 右对齐** |
| **P4** | **一套 token，两套皮肤** | 宿主外壳与卡片共用同一份 CSS 变量（契约 `spec/03` §6.5）。换肤 = 换变量值，**不重写任何卡片** |
| **P5** | **动效只回答动作** | 数据自己变**不配动画**（仪表的数字不该跳）。动画只用于「用户刚刚做了什么，结果变了」 |

## 三、色彩系统

### 3.1 两套皮肤

暗色是默认（开发工具常年开着）；亮色跟随 `prefers-color-scheme`。
**两套皮肤的语义色一一对应**，只换明度，不换色相——所以卡片换肤时，
「这个格子是绿的」这件事在两套皮肤里是同一个意思。

### 3.2 基底色板（暗色 · 默认）

| 角色 | 值 | 用在哪 |
|---|---|---|
| `--cockpit-bg` | `#0E1417` | 应用底色。**带一点冷青**，不是纯黑——纯黑会让发光元素显得脏 |
| `--cockpit-bg-elevated` | `#151D22` | 顶栏、状态轨 |
| `--cockpit-surface` | `#1B252B` | 面板、卡片底 |
| `--cockpit-border` | `#27343B` | 分隔线（1px） |
| `--cockpit-border-strong` | `#35464F` | 面板边框、输入框、聚焦前的轮廓 |

### 3.3 基底色板（亮色）

| 角色 | 值 |
|---|---|
| `--cockpit-bg` | `#EEF1F2` |
| `--cockpit-bg-elevated` | `#F7F9FA` |
| `--cockpit-surface` | `#FFFFFF` |
| `--cockpit-border` | `#CFD8DC` |
| `--cockpit-border-strong` | `#93A5AC` |

### 3.4 文字与强调

| 角色 | 暗色 | 亮色 | 用在哪 |
|---|---|---|---|
| `--cockpit-text` | `#E4EAEC` | `#16201F` | 正文、读数数字 |
| `--cockpit-text-dim` | `#A0AEB5` | `#4A5A5F` | 次要文字、标签、单位 |
| `--cockpit-text-faint` | `#84949C` | `#5E6E74` | 弱化文字（空状态、占位） |
| `--cockpit-accent` | `#3CC6D0` | `#0C737D` | **交互强调**：选中、聚焦、链接、图表主序列 |
| `--cockpit-accent-2` | `#C08CE6` | `#7A4BA6` | 图表第二序列、第二块板（M8） |

> **强调色为什么是青而不是蓝**：现有 `tokens.css` 用的是 `#58a6ff`（GitHub Primer 暗色），
> 那是**最常见的开发者工具默认色**。青 `#3CC6D0` 在暗底上更接近
> **仪器面板的背光**，而且与语义色（绿/琥珀/红）**不撞**——
> 强调色和状态色必须能一眼分开，否则「选中了一个红色的告警」会读成「红 = 选中」。

### 3.5 语义色 ↔ tag 五态（**双编码**：颜色 + 形状）

**颜色语义直接取自 ECAM 谱系**（航空告警显示的成熟惯例）：

| tag 五态 | 颜色 | 暗色 | 亮色 | 灯形 | 数字 | 语义出处 |
|---|---|---|---|---|---|---|
| `ok` | 绿 | `#5FD07A` | `#1E7B3C` | **实心圆** | 显示 | ECAM：正常操作 = 绿 |
| `stale` | 琥珀 | `#E8B23C` | `#8A5A00` | **半实心圆**（上实下空） | 显示（旧的）+ 「已过时」 | ECAM：须知但非立即 = 琥珀 |
| `pending` | 白/灰 | `#A0AEB5` | `#4A5A5F` | **空心圆**（缓慢呼吸） | 不显示 | 还没建立基线 |
| `unavailable` | 灰 | `#809098` | `#627077` | **斜杠 ⊘** | **不显示** | 资源不在——不是故障，是「这块板没有」 |
| `error` | 红 | `#F0574B` | `#C0322A` | **叉 ✕** | 无旧值时不显示 | ECAM：需要立即处理 = 红 |

**为什么 `stale` 是琥珀而不是灰**：契约 §2.1 说 stale 是「有值，但上次刷新失败，值可能过时」。
它是**需要知道但不紧急**——正好是琥珀。灰色在本产品里已经被 `unavailable` 占了。

**为什么 `unavailable` 是斜杠而不是灰灯**：它**不是故障**。
板子好好的，是这个能力不存在（`not_found`）或者环境没就绪（debugfs 没挂）。
用红会吓到用户（像出错了），用琥珀会暗示「有点问题」——
**斜杠 ⊘** 是航空仪表「此仪表不可用」的惯用符号：**冷静地划掉，不报警**。

> **双编码是硬要求**：颜色不能是区分状态的唯一手段。
> 约 8% 的男性有色觉辨识困难，而绿/琥珀在暗底上对某些类型也不易分。
> 灯形（实心/半实/空心/斜杠/叉）是**形状**通道，完全独立于颜色。

| 3 | 琥珀 | `#E8B23C` | `#8A5A00` | 温度 |
| 4 | 紫 | `#C08CE6` | `#7A4BA6` | GPU |
| 5 | 品红 | `#E86FB0` | `#A83B77` | NPU |
| 6 | 中性 | `#84949C` | `#5E6E74` | 其他 |

### 3.8 禁止清单

| 禁止 | 为什么 |
|---|---|
| 语义色用于装饰 | 绿色的按钮 = 「正常」还是「这是主按钮」？必须唯一 |
| 渐变作为面板装饰 | 渐变在小尺寸面板上会变成糊状色块，且两套皮肤对不上 |
| 同一层级的元素用同一个圆角 | 现在 `tokens.css` 只有一个 `--cockpit-radius: 4px`。面板 6px、控件 4px、灯 50%（圆）——**形状本身携带信息** |
| 用颜色区分同一层的并列项 | 并列项靠**位置与分隔**区分，颜色留给状态 |
| 阴影作为层级的主要手段 | 暗底上阴影几乎不可见。层级靠**底色明度差 + 1px 边框** |

## 四、字体系统

### 4.1 三套字型，三种角色

| 角色 | 字型 | Windows | 回退 | 用在哪 |
|---|---|---|---|---|
| **仪表字（label）** | **Bahnschrift** | Win10 1709+ / Win11 自带 | `'DIN Alternate', 'Segoe UI Variable', system-ui` | 面板标题、单位、标签、按钮 |
| **数字字（numeric）** | **Bahnschrift**（`font-variant-numeric: tabular-nums`） | 同上 | `'Consolas', monospace` | **读数数字**、序号、时间 |
| **正文字（text）** | **Segoe UI Variable** | Win11 自带；Win10 回退 `Segoe UI` | `system-ui, sans-serif` | 说明文字、空状态、错误消息 |
| **等宽（mono）** | **Cascadia Mono** | Win11 自带（可选字体） | `Consolas, 'Courier New', monospace` | 终端、日志、路径、tag 名 |

> **为什么是 Bahnschrift**：DIN 1451 是 1931 年的德国工程标准字型，
> 用于**交通标识与仪表**，Windows 自带的 Bahnschrift 是它的变量字体数字化版本
> （2016 年随 Win10 1709 发布，Xbox 的 UI 字型就是它）。
> 它是**这个产品字面意义上的字型**——仪表标签。
> 而它**零安装成本**、**Windows 11 原生**、**不是 AI 默认会选的字体**。
>
> **本机已核实**：`C:\Windows\Fonts\bahnschrift.ttf` 存在，注册表家族名 `Bahnschrift` ✓。
>
> **它的窄体变体**（`Bahnschrift Condensed` / `SemiBold Condensed`）
> 正好用来做**密排的仪表标签**（DIN 的 Engschrift）。

### 4.2 字阶

| 名称 | 字号 / 行高 | 字重 | 字距 | 用在哪 |
|---|---|---|---|---|
| `display` | 28 / 32 | 600 | −0.01em | 读数面板的主数值 |
| `title` | 15 / 20 | 600 | 0 | 面板标题 |
| `label` | 11 / 14 | 600 | **0.08em** | 标签、单位、组名（**丝印感**） |
| `body` | 13 / 19 | 400 | 0 | 说明、错误、空状态 |
| `numeric` | 20 / 24 | 500 | 0（`tabular-nums`） | 读数数字 |
| `numeric-sm` | 13 / 18 | 500 | 0 | 次级读数、表格数字 |
| `mono` | 12.5 / 18 | 400 | 0 | 终端、日志、路径 |

> `label` 的 **0.08em 字距**是丝印标签的灵魂：仪表上的丝印字都是
> **小字号 + 拉开字距 + 全大写**。但**全大写只用在 label**，
> 正文绝不全大写（那是 AI 生成的痕迹之一）。

### 4.3 数字排版

```css
.cockpit-num {
  font-family: var(--cockpit-font-numeric);   /* Bahnschrift */
  font-variant-numeric: tabular-nums;         /* 等宽数字：不跳位 */
  font-feature-settings: 'tnum' 1;
  text-align: right;                          /* 右对齐：小数点成列 */
  letter-spacing: -0.01em;
}
```

**规则**：

1. **等宽表格数字**（`tabular-nums`）——数值每刷新一次都跳位是**最难受的**一种噪音。
2. **右对齐**——数量级靠小数点对齐，一眼比大小。
3. **单位降一级**：`12.4`（20px）+ `percent`（11px，`text-dim`）。
   不写成 `12.4 percent` 混排。
4. **小数位按量级定，不按精度定**：百分比 1 位、Hz 取整到 MHz、字节取 MB 整数。
5. **不补零**：`0` 就写 `0`，不写 `0.0`。**「读不到」写「不可用」，不写 `0.00`**。

### 4.4 跨平台

字体栈必须完整降级，且**布局不能依赖字体的具体宽度**：
- Windows：Bahnschrift / Segoe UI Variable / Cascadia Mono
- macOS：`'DIN Alternate'` → `'Avenir Next Condensed'` → `system-ui`；等宽 → `'SF Mono'`
- Linux：`'Roboto Condensed'` → `system-ui`；等宽 → `'JetBrains Mono'` / `'DejaVu Sans Mono'`

> **设计不依赖字体**：所有数字位用 `tabular-nums` 而不是定宽容器；
> 标签不用「填满一行的字距」，而是固定 `letter-spacing`。

## 五、布局架构

### 5.1 三区结构（把「网页」改成「控制台」）

```
┌──────────────────────────────────────────────────────────────────────────────┐
│ ▍STATUS RAIL                                                                │  40px
│  开发板驾驶舱  │  ATK-DLRK3588 · adb · f34dca77  │ ● 采样中 · 2.1s  │  ⚙ ⏻ │
├────────────────────┬─────────────────────────────────────────────────────────┤
│  SIDEBAR  240px    │  WORKSPACE                                              │
│                    │                                                         │
│  ▾ 连接             │  ┌─ 仪表 ─ 终端 ─ 文件 ─┐   ← 模式切换（不是堆叠）      │
│    ● 板子 · ADB     │  │                                                   │  │
│    ○ 板子 · 串口    │  │   [ 卡片网格 ]        或  [ 终端 ]  或  [ 双树 ]    │  │
│    ○ Ubuntu · SSH   │  │                                                   │  │
│    ○ 本机           │  │                                                   │  │
│                    │  │                                                   │  │
│  ▾ 会话             │  │                                                   │  │
│    ● board-adb  ✕  │  │                                                   │  │
│                    │  │                                                   │  │
├────────────────────┴─────────────────────────────────────────────────────────┤
│ ▍STATUS BAR   会话: 已连接 · adb · 1500000 · 上次采样 0.4s 前 · 12 个读数    │  26px
└──────────────────────────────────────────────────────────────────────────────┘
```

**三条结构决定**：

| # | 决定 | 为什么 |
|---|---|---|
| 1 | **仪表 / 终端 / 文件 是并列的模式，不是上下堆叠** | 现在是「读数面板在上、终端在中、文件在下」的三层堆叠 → 纵向空间被切碎，谁都不够用。**「看板子的读数」是主线，终端是附带的** → 仪表必须是**默认且完整**的模式 |
| 2 | **状态轨永远在最上面，状态条永远在最下面** | 无论在哪个模式，**「板子连着没有、采样有没有在跑」一眼可见**。这是「驾驶舱」与「终端模拟器」的区别 |
| 3 | **侧栏常驻**（连接 + 会话） | 连接是这个产品的**第一对象**（契约 §十：连接 ↔ 板型包绑定）。现在连接在顶栏的一排按钮里——多了几个就挤爆 |

### 5.2 仪表台 = Slot 网格

12 列网格，槽位按 `spec/03` 的 `layout.w/h` 声明。
**布局只认槽位，不认实现**（这与 `docs/20` 的 F6 一致）：

```
Slot { id, kind: 'builtin' | 'user', cardId?, connectionId?, layout: {x,y,w,h} }
```

- `kind: 'user'` → sandbox iframe（`cockpit://`）
- `kind: 'builtin'` → 宿主 React 组件（终端卡、文件树、日志）

> **为什么这条必须在 M5 就做**：等 M8 的 promote / 全屏 / 布局分享来了再改，
> 就是**拆布局系统**。现在做是顺手——布局引擎还没写。

### 5.3 最小窗口与响应式

| 宽度 | 行为 |
|---|---|
| < 900px | 侧栏折叠为图标条；网格降到 6 列 |
| 900–1280px | 侧栏 240px；12 列 |
| > 1280px | 侧栏可展开为 320px；12 列 |

**最小窗口**：960×600。低于这个，仪表台一行放不下两个卡片。

## 六、核心组件规格

### 6.1 状态灯 `StatusLamp`

**唯一承载「这个 tag 现在什么状态」的元件。**

```
  ○ pending          实心 = ok
  ◐ stale            半实 = stale
  ● ok               空心 = pending（呼吸）
  ⊘ unavailable      斜杠 = unavailable
  ✕ error            叉 = error
```

| 属性 | 规格 |
|---|---|
| 尺寸 | 8px（紧凑单元）/ 10px（面板） |
| 形状 | CSS 绘制，**不引图标库**（`border-radius: 50%` + `border` + 伪元素） |
| 呼吸 | 仅 `pending`，`opacity 1 → 0.35`，周期 1.6s，`prefers-reduced-motion` 下**改为静态** |
| 形状通道 | `unavailable` 用**斜杠**（`linear-gradient` 45° 遮罩），`error` 用叉（两条 1px 线） |

> **斜杠怎么画不用图标**：一个 8px 的圆，中间一条 1px 的 45° 线，
> `transform: rotate(-45deg)` 的伪元素即可。
> 叉用两条 `::before`/`::after` 的 1px 线。

### 6.2 读数单元 `TagCell`

**仪表台的基本砖块。** 一个 tag 一个单元。

```
┌────────────────────────────────────────┐
│ CPU USAGE                    ● ok      │   ← label(11px, 0.08em) + 灯
│                             │          │
│                          12.4 %        │   ← 数字(20px, tabular) + 单位(11px)
└────────────────────────────────────────┘
```

**规则**：

| 规则 | 理由 |
|---|---|
| **灯在右上角**，不跟在数字后面 | 灯是**状态**，数字是**量**。两者不该抢同一个视觉焦点 |
| 数字右对齐 | 小数点成列 |
| `unavailable` 时**整块变斜纹底** + 一行原因 | **它不能看起来像一个数**（P2）。斜纹底是航空仪表「此仪表不可用」的惯例 |
| `error` 且有旧值 → 数字保留但**加一道下划波浪线** + 角标「读取失败」 | 契约 §2.1.1：stale/error **保留旧值**。所以要显示旧值，但**必须标出它不是当前值** |
| `pending` → 数字位置显示 `—` 且**不闪** | 闪 = 焦虑；pending 是常态 |
| tag 名用 **mono**，不用 label 字型 | tag 名是要被**复制**的（贴给 AI、贴进命令），mono 让它可读可抄 |

### 6.3 状态轨 `StatusRail`

**顶部 40px 的一条。永远在。**

```
▍开发板驾驶舱 │ ● ATK-DLRK3588 │ adb │ ● 采样中 · 0.4s 前 │ [⚙] [⏻]
```

| 元素 | 规则 |
|---|---|
| 板子身份 | `board.model` 的值 + 状态灯。**读不到就显示「未识别板型」**，不显示占位符 |
| 传输 | 小写 mono（`adb` / `serial` / `ssh`） |
| 采样心跳 | **一个 4px 的小点，每采一轮闪一次**（120ms）。这是「活着」的**唯一**证明，比文字管用 |
| 上次采样时刻 | 相对时间（`0.4s 前`），超过 5s 变成琥珀色并标「采样停滞」 |

> **心跳点**是这一版设计里最省事也最有效的元素：
> 用户盯着屏幕时，**余光就能确认板子还在**。

### 6.4 指示牌条 `AnnunciatorStrip`

**只在有异常时出现**，横贯工作区顶部。**平时不占空间。**

```
┌──────────────────────────────────────────────────────────────────────┐
│ ⚠ npu.usage 不可用 · debugfs 未挂载          [挂载 debugfs]   ✕ 忽略 │
└──────────────────────────────────────────────────────────────────────┘
```

| 规则 | 理由 |
|---|---|
| **只显示 `unavailable` 与 `error`**，且**每张卡每条只报一次** | 仪表台不该有 30 条黄色告警。要么聚合，要么不显示 |
| 颜色：琥珀 = 需要知道，红 = 需要立即处理 | ECAM 谱系 |
| **必须给出下一步**（「挂载 debugfs」）或**明确的「为什么」** | 告警不带动作就是噪音 |
| 琥珀 = 可忽略（给 ✕ 忽略），红 = 不可忽略 | 与 ECAM 一致：红是要处理的 |
| 位置在**工作区顶部**而不是浮窗 | 浮窗会被忽略；顶条会挡住视线，用户必须处理 |

### 6.5 曲线面板 `TracePanel`

**这是仪表台的英雄区**（PulseView 的原则：主视图就是波形）。

```
┌─────────────────────────────────────────────────────────┐
│ CPU USAGE                          1s ▾  60s ▾  5m ▾    │  ← 时间窗
│ 100┤                                                 │
│    │      ╭─╮                                        │
│  50┤ ────╯ ╰──╮    ╭──╮                              │
│    │          ╰────╯  ╰────╮                         │
│   0┼─────────────────────────────────────────        │
│    └──────────────────────────────────────────        │
│     00:00        00:10        00:20        00:30      │
└─────────────────────────────────────────────────────────┘
```

| 规则 | 理由 |
|---|---|
| **网格是 graticule**（示波器刻度网格），不是「虚线分隔」 | 1px `--cockpit-border` 横竖 4 等分 |
| **曲线不填充渐变** | 渐变面积图是 SaaS 仪表盘的味道。示波器是**线** |
| 曲线 1.5px，**无阴影** | |
| 采样窗口是**可切换的**，且**明确标出采样窗口** | 契约 §06 C15 指出 `proc_stat` 的百分比**看不到采样窗口**——UI 上必须把窗口标出来，否则那个百分比没有意义 |
| 窗口切换时**不重绘历史**（没有历史就明说） | 第一版没有历史存储。**空就是空**，不造假 |

### 6.6 失败旗标 `FailureFlag`

**借鉴 ECAM 的 failure flag。**

| 场景 | 显示 |
|---|---|
| 卡片 manifest 不合法 | 卡片位显示一块**斜纹底** + `卡片无效 · 规则 3` + 「查看详情」 |
| 卡片 iframe 崩了 | 同上 + `卡片已崩溃` |
| 动作超时 | 动作按钮旁 `超时（124）`，**保留旧值** |
| 动作成功但回读不符 | `命令已发出，未确认生效`（契约 §4.1 的原话） |

> **关键**：失败的显示是**占位**，不是空白。
> 空白 = 「这儿什么都没有」；斜纹 + 旗标 = 「这儿坏了，而且我知道坏在哪」。
> 这正是 ECAM 的 failure flag 机制。

### 6.7 空状态

| 场景 | 文案 | 动作 |
|---|---|---|
| 没有连接 | `还没有连接` + 「串口、ADB、SSH 都可以」 | 连接下拉 |
| 连上了但没有板型包 | `这块板没有板型包` + 「终端和文件仍可用」 | 「安装板型包」（M7） |
| 板型包有，但读不到 tag | `暂无读数 · 正在采样` / 采样停滞时 `采样停滞 · 最后一次 12s 前` | 重连 |
| 卡片位空着 | `拖一张卡到这里` | 「从卡片目录挑选」 |

> 空状态是**邀请**，不是道歉（frontend-design 的原话）。
> 每条都要有**一个动作**。

### 6.8 终端区

| 规则 | 理由 |
|---|---|
| 终端**独占整个工作区**（模式之一），不与卡片上下拼 | 终端要的是**行宽**与**行高稳定**。拼在卡片下面必然窄 |
| 字号 13px，行高 1.2，**等宽** | |
| 背景用 `--cockpit-bg`（不是 surface） | 终端是「深井」，比面板更暗一层 |
| 光标闪烁用 xterm 原生 | 不要自己画 |
| 状态行（传输、波特率、退出码）**放在终端框的下沿**，不是全局状态条 | 状态条是应用的，终端的归终端 |

### 6.9 文件双树

| 规则 | 理由 |
|---|---|
| 左右两棵树**宽度可拖**（默认 1:1），拖过的比例**记住** | 目录深浅差异大 |
| 树的行高 22px，**目录用 ▸ 三角 + 名称**，文件用图标 + 名称 | 现在用 CSS 小方块（`.is-dir` 蓝方块）——**看不出是目录还是文件**。▸ 更像文件管理器 |
| 选中项**用 accent 的左侧 2px 竖条**，不是整行填充 | 整行填充会盖住文件图标 |
| 中间的两个箭头按钮改成 **⇄ 双向箭头**（一个按钮） | 两个箭头按钮占地方，且要人猜哪个是哪 |

### 6.10 图标

**全部手绘 SVG，1.5px 描边，20×20 网格。** 不引图标库。

理由：图标库会带来几千个图标的选择压力，最后全都不用；
而这个产品的图标**总共不超过 20 个**（连接、串口、文件夹、文件、上传、下载、刷新、设置、关闭、告警…）。

**描边 1.5px、圆头端点**（`stroke-linecap: round`）——与 DIN 字形的方头形成柔和对比，
也与小圆角控件（4px）协调。

## 七、动效规范

| 场景 | 动效 | 时长 | 缓动 |
|---|---|---|---|
| **数据自己变** | **无** | — | — |
| 状态灯切换 | 透明度淡入 | 120ms | `ease-out` |
| `pending` 灯呼吸 | opacity 1↔0.35 | 1600ms 循环 | `ease-in-out` |
| 采样心跳点 | 亮度闪一下 | 120ms | `linear` |
| 面板展开/收起 | 高度 + 透明度 | 160ms | `ease-out` |
| 拖拽布局 | 吸附时**边框闪一下**（不是阴影） | 100ms | `ease-out` |
| 失败旗标出现 | 淡入 + 轻微上移 4px | 180ms | `ease-out` |
| 主题切换 | **无**（直接切） | — | — |

> **「数据自己变不配动画」是这一版最重要的一条动效决定**。
> 一个每 200ms 刷新一次的数字，如果带过渡动画，
> **整块仪表会一直在抖**——这是最常见的「AI 生成的仪表盘」的观感问题。
> 仪表的数字就该**跳**（而且用等宽数字让它跳得不难看）。

**`prefers-reduced-motion: reduce`** 时：呼吸停（改为静态半亮）、所有过渡降到 0ms。

## 八、可访问性

| 项 | 要求 |
|---|---|
| 对比度 | 全部文字 ≥ 4.5:1（实测值见 §3.6），大字号（≥18px）≥ 3:1 |
| **不靠颜色单独传达信息** | 五态有形状通道（§3.5）；告警条有图标 + 文案 |
| 键盘 | 所有可交互元素可达；焦点环 **2px `--cockpit-accent` + 2px offset**，**不用 `outline: none`** |
| 焦点环在暗底上要**看得见** | accent 9.0:1 ✓ |
| 屏幕阅读器 | 状态灯带 `aria-label`（「正常」/「已过时」/「不可用：debugfs 未挂载」），**不只靠形状** |

| 触摸目标 | ≥ 24×24（密集工具可 22px，但图标按钮要有 padding 撑到 24） |

## 九、主题 token 契约（与 `spec/03` §6.5 对齐）

**契约里已有的 token 名一律不改**（契约冻结，改名要升 `apiVersion`）：

```
--cockpit-bg / --cockpit-bg-elevated / --cockpit-border
--cockpit-text / --cockpit-text-dim / --cockpit-text-faint
--cockpit-accent / --cockpit-accent-2
--cockpit-ok / --cockpit-warn / --cockpit-danger / --cockpit-unavailable
--cockpit-radius / --cockpit-font-mono / --cockpit-font-ui
```

**本设计需要新增**（建议加进契约 §6.5 的清单）：

```
--cockpit-surface            面板底（与 bg 区分）
--cockpit-border-strong       面板边框 / 输入框
--cockpit-font-label          仪表标签字型（Bahnschrift）
--cockpit-font-numeric        数字字型（Bahnschrift + tabular）
--cockpit-radius-panel        面板圆角（6px）
--cockpit-radius-control      控件圆角（4px）
--cockpit-grid                曲线网格线色
--cockpit-focus               焦点环
--cockpit-series-1..6         图表序列色
```

> **加 token 要改契约**（`spec/03` §6.5）→ 走「v1 定稿前的修正」口径，**不升 `apiVersion`**。
> **这是本设计文档对契约的唯一一处要求**。

## 十、充分利用工具链特性

这一节是「**为什么要用 Electron + React + 这套栈**」的答案。

| 特性 | 用在哪 | 换来什么 |
|---|---|---|
| **Electron 自定义协议 `cockpit://`** | 卡片资源托管 + **CSP 响应头注入** | 卡片的「断网」承诺**由宿主强制**，卡片改不了（`docs/20` F1） |
| **`titleBarStyle: 'hidden'` + `titleBarOverlay`** | 自绘标题栏，与状态轨连成一条 | Windows 上做出 VS Code 那种一体化标题栏，**省 30px 垂直空间** |
| **`nativeTheme`** | 跟随系统亮暗 | 不用自己监听 `prefers-color-scheme`（但 CSS 变量仍要自己定义两套） |
| **`webContents.on('console-message')`** | 抓 **CSP 违规** → 卡片运行时日志 | agent 能看到「这张卡试图联网」（契约 §6.1 承诺） |
| **Web Speech / `Notification`** | 告警条的可选通知（M8） | — |
| **React 18 `useSyncExternalStore`** | 订阅 `TagStore` | **无 tearing**。读数是高频外部源，`useState` + `useEffect` 会在并发渲染下读到不一致的快照 |
| **React 18 `startTransition`** | 切换仪表/终端模式 | 切模式时**终端不闪**（重渲染被标记为可中断） |
| **`useDeferredValue`** | 读数面板的高频更新 | 输入/筛选时不被高频读数卡住 |
| **CSS `color-scheme`** | 滚动条、焦点环、表控件跟随 | 不用为滚动条写伪元素 |
| **`font-variant-numeric: tabular-nums`** | 数字 | 不跳位（§4.3） |
| **CSS `prefers-reduced-motion`** | 全部动效 | 免费拿到可达性 |
| **CSS `forced-colors`** | 高对比度 | 免费的 Windows 高对比度支持 |
| **`text-wrap: balance` / `pretty`** | 告警条、错误消息 | 换行不产生「孤儿词」 |
| **`content-visibility: auto`** | 侧栏折叠时 | 折叠的会话列表不渲染 |
| **xterm.js 的 `ITheme`** | 终端主题 | 终端颜色**跟着 token 走**，不单独一套 |
| **ECharts 的 `theme`** | 卡片内图表 | 卡片图表跟随宿主皮肤（宿主把 echarts 注入给卡片） |
| **react-grid-layout** | 拖拽布局 | 已定（ADR-D3） |
| **`@font-face` + `font-display: swap`** | — | 字体没到位时先渲染（Bahnschrift 是本地的，其实用不上，但字型栈要写对） |
| **`Intl.NumberFormat`** | 数字格式化 | 千分位、精度、locale 正确（不要手写 `toFixed(1) + ','`） |

> **`Intl.NumberFormat` 这一条值得单说**：现在的读数是裸字符串。
> 用 `Intl.NumberFormat(undefined, {maximumFractionDigits: 1})` 格式化，
> 得到的是**按用户系统 locale 的**数字（欧洲用 `,` 做小数点）——
> 硬编码 `.` 会在那些系统上显示错。

## 十二、自检

按 `frontend-design` 的要求，对照「AI 生成设计的常见特征」逐条查：

| 常见特征 | 本文做到了没有 |
|---|---|
| 暖奶油底 + 衬线大字 + 陶土色强调 | ✅ 没有。冷石墨底 + DIN 工程字型 + 青色强调 |
| 近黑底 + 单一荧光绿/朱红强调 | ✅ 没有。强调色是**青色**（仪器背光），绿只用于 `ok` |
| 报纸式细线分栏、零圆角、密排栏 | ⚠️ 部分像 —— 但**分栏是仪表网格**（示波器 graticule），圆角 4–6px，字体是 DIN 不是衬线 |
| SaaS 卡片套壳：统一圆角 + 统一柔和阴影 + 渐变装饰 | ✅ 没有。**卡片不是圆角白块**，是仪表单元；层级靠底色明度差 + 1px 边框；零渐变 |
| 模板化 chrome：全大写 eyebrow + 中点分隔 + 破折号标签 + 近黑 `#0B0B0B` + 小标签用等宽 + 箭头 CTA | ✅ 没有。全大写只用于 11px 标签（丝印惯例）；无中点分隔；无箭头 CTA；底色是 `#0E1417` 不是 `#0B0B0B` |

**「英雄区」检查**：默认视图的主视觉是**实时曲线**（PulseView 的原则），
不是「大数字 + 小标签 + 渐变」。

**克制检查**（Chanel：出门前摘掉一件首饰）：
这一版最容易显得吵的是**指示牌条**。但它**平时不出现**（只在有 `unavailable`/`error` 时），
所以留着——它是「驾驶舱」这个隐喻真正兑现的地方。
