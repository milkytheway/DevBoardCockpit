> **日期**：2026-11-16
> **性质**：**契约增量**（`docs/spec/02-board-pack.md` §10 + `docs/spec/04-mcp-tools.md`）
> **依据**：计划 11 的真板接入（2026-11-16 实测 ✓）+ 用户拍板（2026-11-16 ✓）
> **配套实现**：计划 11（`docs/superpowers/plans/2026-11-16-plan11-收尾与真板接入.md` ✓）

## 〇 · 触发这件事的是**一次实测**（**证据先于断言** ✓）

2026-11-16 实测：宿主 → 板子 `192.168.5.100`（SSH，22 端口）：

```
$ ssh root@192.168.5.100 'uname -r'
Permission denied (publickey,password,keyboard-interactive).
```

→ **网络通** ✓（能连到 22 端口 ✓）· **认证失败** ✓。

**为什么失败** ✓：**那把私钥在客机上** ✓（`alientek@192.168.136.131` 的 `~/.ssh/id_ed25519` ✓）——
流程尖兵（2026-11-15 ✓）把它装进了**板子的 `/root/.ssh/authorized_keys`** ✓（**客机的公钥** ✓）。

→ **宿主没有板子的私钥** ✓ → **宿主直连板子走不通** ✓。
→ **但「客机 → 板子」通** ✓（**那才是尖兵跑通的链路** ✓）。

### 0.1 这暴露了一个**建模问题**（不只是「少一把钥匙」）

现在的流程包（`profiles/workflows/meminfo-user.build-run.yaml` ✓）：

```yaml
roles:
  build:  { profile: ubuntu-ssh }   # 客机
  target: { profile: board-adb }     # 板子（**ADB**）
steps:
  - id: deliver
    kind: file.transfer
    cmd: "scp {from.path} {role:target.user}@{role:target.host}:{to.path}"
```

→ **`{role:target.host}` 取的是 target 角色绑的 profile 的事实** ✓（`runner.ts` 的 `factsOf` ✓）
→ 而 target 绑的是 **`board-adb`** ✓ → **ADB profile 没有 `host`** ✓（封闭 schema ✓）→
→ **`{role:target.host}` 是空串** ✓ → **`scp` 那条命令拼不出来** ✓。

> **但尖兵跑通过了** ✓ —— 因为**尖兵是手工跑的** ✓（它自己知道板子的 IP ✓），
> **不是走这个流程包** ✓。

### 0.2 三个事实凑在一起，指向一个**建模缺口**

| # | 事实 | 含义 |
|---|---|---|
| 1 | **一块板子有多条连接** ✓（ADB ✓ · 串口 ✓ · SSH ✓ —— 三条都指同一块板 ✓） | 「板子」与「连接」**不是一回事** ✓ |
| 2 | **每条连接的传输不同** ✓（ADB ✓ / 串口 ✓ / SSH ✓） | **能力不同** ✓（串口没有退出码 ✓ · ADB 没有 pty ✓） |
| 3 | **跨机器的动作要在客机上发起** ✓（`scp` 在**源**目标上跑 ✓ —— `runner.ts` 的 `runTransfer` ✓） | **命令用到的 SSH 事实属于板子** ✓，**但执行这条命令的机器是客机** ✓ |

→ **现有模型只有「连接 profile」** ✓（一台机器 = 一个 profile ✓）→
**「板子的 SSH 事实」无处安放** ✗。

## 一 · 提案（**三处** ✓）

### 1.1 `spec/02` §10：连接 profile 增加 **`ssh` 事实块**（**可选** ✓）

```jsonc
{
  "id": "board-adb",
  "label": "板子 · ADB",
  "transport": "adb",
  "board_pack": "rk3588-atk",
  "options": { "serial": "f34dca7784396ab2", "pty": false },
  // **这块板的 SSH 事实**（可选 ✓ —— 不是所有传输都要它 ✓）
  "ssh": { "host": "192.168.5.100", "port": 22, "username": "root" }
}
```

| 项 | 规则 |
|---|---|
| **可选** ✓ | 没有它 → 流程包里用不到 SSH 事实的包照跑 ✓ |
| **形状** ✓ | `{ host, port?, username? }` ✓ |
| **封闭** ✓ | 未知字段报错 ✓（同 profile 其余部分 ✓） |
| **它属于「板子」不是「这条连接」** ✓ | ADB 连接 ✓ 与 SSH 连接 ✓ **说的是同一块板** ✓ → **两块板若 SSH 事实不同 → 那是两块板** ✓ |

> **为什么不是加到 `options` 里** ✓：
> `options` 是**传输自己的参数** ✓（`port` / `baudrate` / `serial` ✓ —— 换传输就换 ✓）；
> 而 SSH 事实是**这块板的身份** ✓（换传输**不该**换 ✓）。
> → **放在传输之上** ✓。

### 1.2 `spec/04` §2.1：`list_connections` 给出 **`device`**（**一块板 = 一个设备** ✓）

```
→ [{ id, label, transport, board_pack, device, connected, capabilities }]
```

| 字段 | 含义 |
|---|---|
| **`device`** | **这块板的标识** ✓ —— **同一块板的多条连接给出同一个 `device`** ✓ |

> **为什么现在就需要它** ✓：用户要「**界面支持选择板子**」✓（2026-11-16 拍板 ✓）→
> **界面要按板子分组** ✓ → **得先有「哪些连接是同一块板」这个事实** ✓。

### 1.3 `spec/04` §2.4：`execute_action` 的目标**可以是指定设备**（**不是只有「当前那块」** ✓）

```
execute_action(actionId, params, dry_run, device?)
```

| 项 | 规则 |
|---|---|
| **省略 `device`** | **当前运行时那块板** ✓（与今天一样 ✓） |
| **给了 `device`** | **那一块板** ✓（v1 单连接 → **只有一个设备可选** ✓ —— **多设备是 M8** ✓） |

> **为什么要现在做** ✓：
> 「工具的设计本身就需要支持不同设备」✓（用户 2026-11-16 ✓）→
> **参数位置现在留出来** ✓，**比将来加容易** ✓（加参数是破坏性的 ✓ —— 改现有形状更难 ✓）。

## 二 · 边界（**这一轮不做什么** ✓）

| 不做 | 为什么 |
|---|---|
| **多设备并行** ✓ | `O11` / `O18` 已拍板 **v1 单连接** ✓ —— **参数位置留着** ✓，**行为不做** ✓ |
| **设备清单文件** ✓ | **设备是「派生出来的」** ✓ —— 同一块板的多条连接**共享同一个 `device`** ✓ → **不需要新文件** ✓ |
| **`device` 怎么生成** ✓ | **由 `ssh.host` 决定** ✓ —— 有 `ssh.host` 的连接**用那个 host** ✓；没有的 → **用 profile id** ✓（**一板一连** ✓） |

## 三 · 待评审的点（**请逐条判** ✓）

| # | 问题 | 我的倾向 |
|---|---|---|
| 1 | `device` 放**顶层**（与 `board_pack` 同级 ✓）还是放 `options` 里？ | **顶层** ✓ —— 它与传输无关 ✓ |
| 2 | `device` 的**取值**是什么？ | **`ssh.host`（有的话）✓，否则 profile id** ✓ |
| 3 | `ssh` 块放**顶层**还是 `options` 里？ | **顶层** ✓ —— 它跨传输 ✓ |
| 4 | `execute_action` 的参数叫 `device` 还是别的？ | **`device`** ✓ —— 与 `list_connections` 同名 ✓ |
| 5 | v1 单连接下，`device` 参数**除了「当前那块」还能给什么**？ | **给别的 → `not_found`** ✓（**不许悄悄跑当前那块** ✗） |
| 6 | 要不要给 `execute_action` 的 `device` 加**跨设备授权**（agent 能对没连的板子下动作）？ | **不要** ✓ —— **没连的板子** = **没有回读** ✓ = **执行器没有连接** ✓ → **自然做不到** ✓ |

> **一句话** ✓：**这一轮不是加功能，是把「板子」与「连接」这两件事分开** ✓ ——
> 分开之后，「选板子」✓、「客机中转」✓、「工具支持不同设备」✓ 三件事**才有地方长** ✓。
