## 一、先理解：卡片是什么，UI 要承载什么

### 1.1 卡片的三层身份

| 层 | 事实 | 对 UI 的硬含义 |
|---|---|---|
| **文件层** | 卡片 = 一个目录（`manifest.json` + `index.html` + 资源）；AI 写完即生效、热插拔、无需构建（ADR-D4/D14） | 「生成 / 发现 / 校验 / 热更新」必须是一等公民的界面流程，不是设置里的小功能 |
| **沙箱层** | 卡片跑在独立 iframe；无同源、无网络（宿主注入 CSP）、无宿主 DOM；存储只能走 `cockpit.storage.*`；能力只有 `cockpit.*` 白名单（`spec/03` §六 / §七） | 卡片内容是**不可信内容**；宿主 chrome（标题、连接、权限、状态）必须由宿主渲染，不能让卡片伪造 |
| **能力层** | 读 tag 受 `permissions.read` 过滤；写动作有 danger 分级、授权、参数域、**执行后回读**、审计（`spec/03` §3.2 / §5.3） | UI 必须能表达「新鲜 / 过期 / 未知 / 错误 / 未验证」，不能只画漂亮图表 |

### 1.2 设计哲学（从契约长出来的四条）

1. **驾驶舱而非遥控器**：控件旁边永远是板子的真实值；写操作的结果用**回读值**渲染；回读失败要显式显示「命令已发出，未确认生效」，绝不乐观更新。
2. **AI 是组态工程师**：核心旅程是「让 AI 写一张卡 → 它出现在工作台 → 人一眼看懂并信任它」。卡片库、校验报告、诊断日志、造卡入口比装饰重要。
3. **信任边界可见**：宿主 chrome 与卡片内容视觉上是一个整体，信任上是两层——chrome 永远由宿主画，卡片只能画内容区。
4. **克制的美**：石墨/中性表面、发丝分隔线、等宽数字、唯一信号蓝；层级靠亮度阶梯与留白，不靠阴影和渐变堆叠。

### 1.3 UI 需要回答的六个问题

1. 板子现在怎么样？（连接、采样、健康、异常）
2. 这张卡在说什么？（读数、趋势、五态、降级原因）
3. 这张卡可不可信？（来源、版本、权限、校验状态、运行时错误）
4. 我能对它做什么？（放置、缩放、重载、查看日志、卸载；M6 之后：执行动作）
5. 写操作到底生效了吗？（回读、verified、审计）
6. AI 写的下一张卡从哪来、去了哪？（造卡入口、卡片库、校验、安装）

## 二、设计概念：Deck / 石墨甲板

**一句话**：飞书多维表格「应用模式」的骨架 + 仪表盘的皮肤 + 为 AI 生成内容而生的弹性。

- **Instrument（仪表）**：向 PicoScope 7、车载仪表 HMI 学「暗色 + 网格 + 等宽读数 + 状态灯」的精密感。
- **Calm（安静）**：向 Linear 学克制——近黑/中性表面、发丝边框、单一强调色、键盘优先、120–280ms 动效。
- **Card-native（卡即组件）**：向 Home Assistant 自定义卡学「卡必须跟随宿主主题、不能各画各的」；向 Node-RED Dashboard 2.0 学 12 列分组与断点。
- **Base-like（应用模式）**：向飞书多维表格学「同一份数据、多种视图、组件自由布局、配置面板、权限模型」。
- **数据密度**：向 Grafana 学信息层级（健康/关键指标在上，细节在下）、7±2 面板、阈值配色。

**刻意不做**：Grafana 式 20+ 面板密集墙（本产品是工作台不是监控大屏）；HA 的 masonry（卡片可拖拽缩放，需要确定性栅格）；antd（ADR-D27，全部自有 token 层）。

## 三、从飞书多维表格借鉴什么（以及不借鉴什么）

### 3.1 核心判断：借「应用模式」，不借「卡片视图」

飞书多维表格的**卡片视图/画廊视图**是把一条记录渲染成卡片；我们的卡片是**应用级组件**。真正对应 DevBoardCockpit 的是飞书的**「应用模式」**：在同一份数据之上，用自由布局的组件、页面、标签页搭出一个后台系统，组件可配置、受权限控制。官方定位是「把视图的排列方式和数据看板的自由布局结合，搭出 ERP/CRM 这类系统」。

四层结构一一对应：

| 飞书多维表格 | 作用 | Cockpit 对应 | 现状 |
|---|---|---|---|
| 数据表 / 字段 / 记录 | 数据层（字段有类型、选项、权限） | TagStore / 板型包 / tag 五态 | 计划 3 已落地 |
| **视图**（表格/看板/画廊/日历/仪表盘） | 同一份数据的多种呈现；**每个视图独立保存筛选、分组、排序、字段显示** | **布局视图（View）**：总览 / 监控 / 调试 / 演示，各自保存槽位、可见卡片、状态筛选、密度 | 本文新增设计（M5b） |
| 应用模式（普通列表/详情列表/卡片列表/聚合列表/标签页） | 自由布局搭后台；组件有配置面板 | 卡片工作台**运行时 + 编辑态**：卡片=组件、栅格=页面、检查器=配置面板 | M5 运行时、M5b 布局、M6 编辑态 |
| 高级权限（角色/字段/记录/视图） | 细粒度授权 | 卡片权限矩阵：只读 tags、可写动作、danger、guard 范围 | M5 展示、M6 授权交互 |

### 3.2 值得直接借鉴的 8 个模式

| # | 飞书做法 | Cockpit 落点 | 期次 |
|---|---|---|---|
| 1 | **视图 = 保存的配置**（切视图不换数据） | 布局文件升级为 `views[]`：`总览`（全部卡）、`监控`（大图表 + 目标）、`调试`（终端/日志/审计）、`演示`（隐藏元信息、大字号）；每个视图独立保存可见槽位、状态筛选、密度 | M5b 数据结构 + 2 预设 |
| 2 | 主区顶部**视图标签栏** + 视图配置 | 工作区第二行：`总览 ▾ | 监控 | 调试 | 演示`；右侧「视图配置」打开检查器配置段 | M5b |
| 3 | 工具栏：筛选 / 分组 / 排序 / 字段显示 | 工作台工具条：状态筛选 chips（全部/异常/降级/stale）、按连接/板型筛选、显示隐藏卡片、密度切换、暂停采样 | M5b |
| 4 | **卡片列表**：封面 + 显示字段 + 卡片大小（小/中/大 = 8/6/4 列） | 卡片库画廊视图：预览图 + 名称/版本/状态/权限/尺寸；卡片壳尺寸档 S/M/L 映射列数；`manifest.layout` 仍是权威 | M5b |
| 5 | **详情列表**：左列表 + 右详情联动，不跳新页 | 卡片库左列表 + 右预览；工作台选中卡片 → 右侧 SideSheet 检查器（概览/数据/权限/活动四段） | M5b |
| 6 | **标签页**：按状态切换，省掉重复建视图 | 视图内状态页签（全部 / 异常 / 降级）；审计页按 level/danger 页签 | M5b（轻量） |
| 7 | **组件库 + 配置面板** | 「添加卡片」面板 = 卡片库按类别分组（内置 / AI 生成 / 模板），带预览说明；选中卡片 → 检查器配置段（尺寸、连接、显示项） | M5b 添加；M6 配置 |
| 8 | **高级权限弹窗**：角色、字段级勾选、可见视图 | 授权 sheet：左「能力」右「范围」——读取 tags（模式）、执行动作（danger 徽章 + guard 范围 + 每次确认），分组呈现，不做成一堆 checkbox | M6 |

另两点产品灵感：

- 飞书「AI 智能搭建助手，一句话生成业务系统」→ 我们的**「AI 造卡」入口**：卡片库顶部输入框（自然语言描述 + 推荐模板 + 复制造卡 prompt）；M5 走手工流程，M7 接 MCP 自动生成。
- 「聚合列表」按字段聚合 → 留给 M8 的多板聚合视图。

### 3.3 明确不借鉴的 5 点（防止跑偏）

1. **不把主工作台做成宽表**：数据是实时 tag，不是记录集合；表格只出现在审计/日志里。
2. **不做协同**：头像、评论、在线状态、分享链接——桌面单机工作台不需要（M7 最多是 MCP 会话状态）。
3. **不做任意低代码搭建**：飞书应用模式能自由摆组件；我们的卡片是受 CSP/契约约束的**文件**。编辑态只允许「布局 + 显示项 + 连接绑定」，不允许把卡片变成可拖拽表单组件（那会绕开校验与授权）。
4. **不照搬字段/公式/关联字段体系**：tag 是契约词汇表的封闭集合，UI 不能暗示用户可以随意造字段。
5. **安全与回读优先于搭建自由度**：回读确认、审计、降级可见必须比配置项更显眼。

### 4.1 全局壳（一屏四区）

顶部状态带 / 左侧图标栏 / 主工作区 / 右侧检查器；全局命令面板 `Ctrl/Cmd+K` 串起一切。

- **顶部状态带（40px）**：当前目标/传输/板型包、采样节奏与最后心跳、全局暂停、命令面板入口；同时是 Electron 标题栏拖拽区（`titleBarOverlay` 融合，无第二条标题栏）。
- **左侧 rail（56px）**：工作台 / 卡片库 / 终端 / 文件 / 审计 / 设置；hover 出文字，键盘可达。
- **右侧检查器（320px SideSheet）**：选中卡片的概览 / 数据 / 权限 / 活动；也是「复制诊断信息给 AI」的出口。
- **命令面板**：搜卡片、搜 tag、执行「添加卡片 / 校验卡片 / 打开卡片目录 / 切换目标 / 暂停采样」；键盘优先。

### 4.2 页面清单

| 页面 | 内容 | 期次 |
|---|---|---|
| 工作台 | 视图栏 + 工具条 + 卡片栅格 + 检查器 | M5b |
| 卡片库 | 左「详情列表」+ 右画廊 / 预览；校验、安装、卸载、打开目录 | M5b |
| 终端 | 现有终端会话（M5b 后作为内置卡进栅格；保留全屏工作区） | M5b |
| 文件 | 现有文件互传（同上） | M5b |
| 审计 | 动作/回读/授权时间线 | M6 |
| 设置 | 主题、采样、连接、卡片目录 | M5b（基础） |

### 4.3 内置卡与用户卡统一为 Slot

呼应 `docs/21` §4.6：终端、文件、日志、目标切换器都是 `kind:'builtin'` 的格子，用户卡是 `kind:'user'` 的格子；外观统一 Card Shell，信任边界不同。这同时解决现有 `App.tsx` 里「tabs + flex」与未来栅格两套 IA 打架的问题——M5b 迁移时把 tabs 降级为终端/文件卡内的局部标签，而不是顶层导航。

## 五、布局与栅格（M5b）

- **12 列栅格**，行高 **56px**，间距 **12px**，页面边距 **20px**。
- 断点：≥1600 12 列；1200–1600 12 列（卡片按列宽自适应）；900–1200 8 列；<900 4 列。
- 卡片尺寸预设（与 manifest `layout.w/h` 对齐）：`S 3×3`（单指标）、`M 4×4`（多指标）、`L 6×5`（图表）、`XL 8×6`（终端/大图）。
- 默认布局「总览」：目标与链路(4×3) + 金指标(8×4) + 终端(8×5) + 文件(4×5) + 日志(4×3) + 审计(4×3)；用户卡从第二屏开始。
- 拖拽：卡片抬起 1px、边框提亮、右下出现手握；落点用 8% 信号蓝虚线占位；resize 实时显示 `6×5` 尺寸 chip。
- **焦点模式**：双击卡片标题或按 `F` 放大到主区，`Esc` 还原，布局不丢；终端卡可全屏。
- 布局持久化归 main（ADR-D2/Q7）；UI 只读 `get_layout` / `set_layout`。

## 六、视图模型（本次新增的设计）

`docs/21` §6.7 当前的布局模型是单布局。建议升级为「多视图」，这是从飞书借来的最有价值的一层：

```ts
// 建议形状（示意，不是契约；落盘由 main 负责）
interface LayoutFile {
  version: 1;
  views: Array<{
    id: string;            // "overview" | "monitor" | "debug" | "demo" | uuid
    name: string;
    slots: Array<{
      id: string;
      kind: 'builtin' | 'user';
      cardId?: string;        // kind === 'user'
      builtin?: 'target' | 'terminal' | 'files' | 'logs' | 'audit';
      connectionId: string;
      x: number; y: number; w: number; h: number;
      config?: { density?: 'comfortable' | 'compact'; hidden?: boolean };
    }>;
    filter?: { status?: Array<'live' | 'stale' | 'error' | 'unavailable' | 'degraded'> };
    density?: 'comfortable' | 'compact';
  }>;
}
```

- **视图 = 保存的配置**，切换视图不重载卡片、不重订数据；只改哪些槽位可见、筛选与密度。
- 内置预设（M5b 只读，不允许用户新建）：`总览`（默认）、`监控`（大图表 + 目标 + 审计）、`调试`（终端/文件/日志 + 采样暂停提示）、`演示`（隐藏权限元信息、字号 +1、暗色）。
- 「新建/编辑视图」留 M6 编辑态；M5b 只把数据结构和预设落地，成本很低但把扩展点留出来。
- 对 `docs/21` 的影响：§6.7 的布局模型需要补「视图」一层，并在 ADR-D3/Q7 的说明里记一句「布局从单布局升级为多视图，仍归 main」；**不涉及契约层**（布局不是契约）。

## 七、视觉语言

### 7.1 双主题（本次修正）

上一版偏 Linear 暗黑；飞书/Semi 的经验是**中性灰阶 + 浅色/深色双主题 + 桌面密度**。开发者白天浅色、深夜深色是常态，**双主题从 M5b 就要做**，否则后拆会返工组件层。主题跟随系统（Electron `nativeTheme`），设置里可手动锁定；卡片 iframe 通过宿主注入的 `__host/theme.css` 拿到当前 token，所以 **AI 写的卡自动适配两套主题**。

### 7.3 状态语言

圆点 + 文字 + 形状三重编码（色盲友好）：`● live` / `◌ pending` / `◐ stale` / `✕ error` / `— unavailable` / `⚠ degraded`。stale 的数值灰显并标「最后 00:12:03」，绝不假装最新；`unavailable` 不显示 0。

### 7.4 图标与插画

16px inline SVG，统一 1.5px 描边、圆角端点；**不用 emoji**；空状态用线性小插画（内置 SVG，离线可用）。所有视觉资源必须走协议同源，禁 CDN（CSP `connect-src 'none'` 与 `script-src 'self'` 决定）。

## 八、卡片壳与内容沙箱

### 8.1 结构（关键决策：chrome 归宿主）

```
┌──────────────────────────────────────────────┐
│ ◉ CPU 曲线      RK3588 · 2.1      ⟳  ⋯      │ 44px host chrome（可信、不可伪造）
├──────────────────────────────────────────────┤
│  iframe（sandbox / CSP / bridge / kit.css）   │
│   42.8 %   48.1 %   1.9 W   62 °C            │ ← 等宽大数字 + sparkline
│   ▁▂▃▅▆▇█▇▆▅                                  │
├──────────────────────────────────────────────┤
│ 只读 · 4 tags · v0.3.1 · 已校验 · 来自 AI      │ 22px footer（hover / 降级时出现）
└──────────────────────────────────────────────┘
```

- 卡片不能画自己的标题栏/权限标——防止伪造；宿主 chrome 让所有卡（含 AI 生成）**天生一致**。
- 卡片体背景透明；Card Shell 提供统一下限高度、padding、hover/selected 光晕；滚动在卡片内部。
- 卡片菜单：重新加载 / 查看日志 / 在资源管理器中显示 / 复制诊断信息 / 放大 / 移除（卸载保留存储）。

### 8.2 卡片状态

| 卡片状态 | 视觉 | 文案 |
|---|---|---|
| live | 绿点 + 数值正常 | — |
| pending | 蓝点脉冲 + 骨架屏 | 「等待首个采样」 |
| stale | 灰点 + 数值降饱和 | 「链路忙，显示最后值 00:12:03」 |
| error | 红点 + 保留最后值 + 条纹底 | 「读取失败：串口超时」 |
| unavailable | 灰点 + 「—」 | 「板型包未提供该 tag」 |
| degraded | 琥珀 footer | 「缺少 2 个 tag · 查看」 |
| broken | 整卡遮罩 | 「卡片已隔离」+ 错误摘要 + [重新加载] [查看日志] |

### 8.3 生命周期交互

- **热更新**：文件变化 → 校验 → 通过则 iframe 淡入替换（180ms），布局不动，toast「已更新 · v0.3.2」；校验失败保留上一版并标「无效」。
- **崩溃/CSP 违规**：整卡遮罩「卡片已隔离」+ 错误摘要，不影响其他卡；违规详情进检查器「活动」段。
- **骨架屏**：按 manifest 的 w/h 出对应比例的骨架，不做全屏 spinner。

## 九、卡片库

### 9.1 双模式布局（借飞书「详情列表 + 卡片列表」）

```
┌ 卡片库 ─────────────────────────────────────────────────────────────────────┐
│ [+ 从文件夹安装] [AI 造卡 ▸] [全部|内置|AI 生成|无效]            [画廊|列表]  │
├────────────────────┬────────────────────────────────────────────────────────┤
│ ▸ CPU 曲线     ●   │  ┌─────────────┐  CPU 曲线                  v0.3.1      │
│ ▸ 内存水位     ●   │  │  （预览图）  │  只读 · 6 tags · 已校验              │
│ ▸ 温控仪表     ◐   │  └─────────────┘  尺寸 M · 连接 RK3588 · 最后修改 2h  │
│ ▸ 目标切换器   内置 │  [放置到当前视图] [查看 manifest] [打开目录] [卸载]    │
└────────────────────┴────────────────────────────────────────────────────────┘
```

- 缩略图由宿主 `webContents.capturePage` 生成并缓存（不额外开 iframe）。
- 卡片信息：名称 / 版本 / 状态灯 / tags 数 / 权限标（只读 / 可写）/ 尺寸 / 最后修改。
- 筛选：全部 / 内置 / AI 生成 / 无效；排序：最近修改 / 名称 / 最近使用。

### 9.2 发现 / 校验 / 授权三个流程

1. **发现**：卡片目录出现新卡 → 右下 toast「发现新卡片：CPU 曲线 · 校验通过」→「放置到工作台」；不过 → 「发现 2 个问题」→ 打开报告。
2. **校验报告**：`ok / issues[] / unverified[]` 三区分开展示；unverified（连不上板、动作未核实）用琥珀而非红色——**未验证 ≠ 不合法**（`docs/21` §4.10）。
3. **授权（M6，读卡不需要）**：卡片身份 + 人类语言的能力清单——「读取：`cpu.*`、`mem.*`」「执行：`cpu.governor.set`（危险，范围 0–7，每次执行需确认）」；底部「取消 / 允许这些动作」；guard 范围可视化。

### 9.3 空状态与首启

- 没有连接：显示检测到的目标列表 + 「连接」按钮，而不是空白画布。
- 没有用户卡：内置「总览」卡先垫底 + 「AI 造卡」hero（三步说明、复制造卡 prompt、打开卡片目录）。
- 首次启动：3 步清单（连接板子 → 绑定板型包 → 放置第一张卡），完成即消失。

## 十、工作台工具条与筛选（视图配置）

左侧：视图名（可切换）、状态页签「全部 / 异常 / 降级」。
右侧：状态筛选（五态多选）、连接筛选、密度（舒适/紧凑）、暂停采样、添加卡片、视图配置。

## 十一、控制面与回读（M6 的 UI 预留）

- **动作按钮三级**：中性（reversible）、描边危险（destructive）、禁用（无权限/降级）。
- **确认 sheet**：最终命令/参数（已编码）+ guard 范围 + 预期回读 + 危险等级；destructive 每次执行都要这一步（`spec/03` §3.2）。
- **执行中**：按钮进入 pending 态，卡片其余区域不变。
- **结果三态**：
  - `已回读确认（42 → 48）`
  - `命令已发出，未确认生效（回读不符：期望 48，实际 42）`
  - `失败（reason）`
  - 审计 id 可点，跳审计页。
- 绝不做乐观更新，绝不在未回读时显示「已生效」。

## 十三、AI 造卡设计套件（让好看成为默认值）

只给契约不够，AI 写出来的卡会「能用但丑」。方案：

1. 宿主在卡片源内注入 `__host/theme.css`（当前 token 值）、`__host/kit.css`（组件库）、`__host/kit.js`（小工具）；CSP `'self'` 正好允许这些同源资源。
2. Kit 组件：`ck-stat`（大数字 + delta）、`ck-sparkline`、`ck-chart`（封装宿主 ECharts 主题）、`ck-meter`、`ck-table`、`ck-row`、`ck-badge`、`ck-banner`、`ck-empty`、`ck-skeleton`；全部吃 token，不硬编码颜色。
3. `kit.js` 小工具：`fmt.unit/percent/bytes/duration`、`tags.use()`（自动订阅/清理/渲染五态）、`degraded()`（降级态渲染）。
4. `card-template/` 四件套（manifest + index.html + card.js + style.css，带注释），卡片库一键「从模板新建」。
5. 校验器加一条 M6 设计检查（warning 级）：硬编码 `#rrggbb`、未使用 kit、没有空/错/降级三态 → 提示但不拦。
6. MCP 侧 `get_card_sdk_docs` 把 kit 文档喂给 agent，形成「生成 → `validate_card` → 出现在库 → 人授权」的闭环；UI 对应一个安静的「AI 正在写卡…」胶囊。

## 十四、与工具链的映射

| 工具链特性 | 设计用法 |
|---|---|
| Electron `titleBarOverlay` | 状态带即标题栏，`app-region: drag`，无第二条栏 |
| `nativeTheme` | 明暗主题跟随系统 + 手动锁定 |
| React 18 + CSS variables | 宿主 chrome 用 React + 原生 CSS token；主题切换只改 `:root` |
| 自定义协议 + CSP | 卡片资源离线：系统字体栈、inline SVG、canvas；`connect-src 'none'` 断网 |
| 宿主注入 bridge + kit | 同一 API 注册表驱动 `bridge.js` 与 `kit.js`，AI 卡零配置继承设计 |
| `react-grid-layout` | 12 列 / 56 行 / 12 间距；拖拽与 resize 手感统一（M5b） |
| ECharts（宿主提供） | 统一 theme（token 派生），卡片不各自配色（归属 M5b/M6，见 §17） |
| xterm.js | 终端主题从 token 派生，字号 12.5 / 行高 1.35 |
| `webContents.capturePage` | 卡片库缩略图缓存，不牺牲性能 |
| Playwright 外壳（M5 起） | 9 条隔离判据自动化 + UI 视觉快照的载体 |

**性能预算**：工作台常驻 iframe ≤ 12–16；离屏卡片暂停订阅（IntersectionObserver）；图表 ≤ 1 图/卡、采样推送按 poll group 合并；首屏 shell < 300ms 可交互。

**可访问性**：焦点环 2px 信号蓝；rail / 栅格全键盘可达；`prefers-reduced-motion` 全关动效；正文 AA 4.5:1；状态同时用颜色 + 文字 + 形状。

## 十六、对 `docs/21` 与后续计划的具体修改建议

1. `docs/21` §6.7：布局模型从单布局升级为 `{ version, views[] }`（§六）；`Slot` 模型补 `kind: 'builtin' | 'user'` 的早期落地顺序（M5b 先迁终端的读侧，再迁文件）。
2. `docs/21` §6.4 卡片运行时日志：补「检查器活动段」与「复制诊断信息」的字段清单（日志条数上限、CSP 违规标记）。
3. `docs/21` §6.2 桥接协议：UI 不需要改协议；但握手失败/超时要能在卡片壳上显示「连接宿主失败」错误态（M5 必备）。

5. 新增 ADR（与 `docs/21` §七 的 ADR-D28 同批）：布局从单布局升级为多视图；双主题；卡片壳 chrome 归宿主。
6. M5 计划里预留「卡片库最小版」（列卡片 + 打开目录 + 重新加载）；完整画廊/校验报告排 M5b。
