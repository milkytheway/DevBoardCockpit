## 一 · 已经在实现层修掉的（2026-11-15）

| # | 问题 | 修法 | 守卫 |
|---|---|---|---|
| **1** | **回读的 `verify` 命令不过危险地板** → 包能借「验证」之名在板上跑 `rm -rf /` | 执行器与流程层的 `exec` 都**先过地板**，命中就**不执行**（`PACK_INVALID`） | **M103** |
| **2** | **确认凭据只绑动作参数** → 流程的自由命令没有动作参数 → 摘要恒为空 → **换一组 inputs 就能复用同一张凭据** | 凭据摘要**并入这一步的输入**（`input:<名>` 前缀 ✓） | **M104** |
| **3** | **`action` 步永远无法被确认**（不传 confirm_id） | 动作步也带 `confirmIds[step.id]` ✓ | — |
| **4** | **角色事实原样插进命令** → 手写的 profile 里塞 `; reboot` 就带出去了 | 角色事实**按类型编码的规矩包引号**（数字类的 `port` 不包 ✓） | **M105** |
| **5** | **跨目标判据给 destructive 步塞 `kind: none`** → 违反 `spec/02` §4.4.1（「destructive 禁止 none」） | 改用 **`command_ok`**（命令自己的退出码 ✓）；跨目标那部分**由流程层另外验** ✓（两个事实、两行账 ✓） | — |
| **6** | **「角色不许绑到 `local`」没有执行者** | 目标登记处**拒掉 `local` 传输**（它是宿主自己的 shell ✓）；假设备因此**改成假装 ssh 目标** ✓ | — |
| **7** | **`readback.role` 对形式 1 被静默丢弃** | 流程层**不支持形式 1（tag）** → **直接报错**（tag 属于板型包的核心词表，流程层查不了 ✓） | — |
| **8** | **`await`/`assert` 没说得出在哪个角色上读** | 校验器**要求**（`step.role` 或 `readback.role` ✓） | — |
| **9** | **动作步的参数只许字符串** → 整数/布尔参数不可达 | 参数**允许标量**（字符串/数字/布尔 ✓），值走**值模式**替换 ✓ | — |

> **真机复验**：改完引号规则后，**真板上的直传流程重跑了一遍** ✓（scp 带引号的事实照样通 ✓）。
