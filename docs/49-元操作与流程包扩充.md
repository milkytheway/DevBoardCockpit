## 2 · 顺带修掉的三个真缺陷

### 2.1 adb 路径：**收进唯一的建连接入口** ✓

| | 之前 | 之后 |
|---|---|---|
| 应用 | `loadSettings(app.getAppPath())` → `resolveAdbPath` ✓ | 同上 ✓ |
| **CLI** | **不读设置** ✗ → `'adb'` ✗ → ENOENT ✗ | **同样读设置** ✓ |

```ts
// src/main/hal/registry.ts
const adbPath = opts.adbPath ?? resolveAdbPath(loadSettings(settingsPath()));
```

> → **谁来建连接，谁就按同一条路拿 adb 路径** ✓。
> 顺带补了 `Downloads/platform-tools_*/platform-tools/adb.exe` 的查找 ✓
> （这台机器的 adb 在**带版本号的目录**里 ✓ —— 原来那两条常见路径都找不到 ✓）。

### 2.2 CLI 也能跑 `action` 步了 ✓

CLI 现在按**角色绑的 profile 的 `board_pack`** 静态加载那份板型包 ✓，
把 `actionDef` 交给流程层 ✓。

> ⚠️ **回读形式 1（读 tag）在 CLI 里查不了** ✓ —— 流程层没有板型包的运行时 ✓
> → `readTag` 返回 undefined ✓ → 那种动作在 CLI 里**回读不过** ✓（**诚实** ✓）。

### 2.3 `action` 步**能传带类型的参数**了 ✓

> **这是今天撞出来的一个真缺口** ✓ ——
> **流程里的参数值只能是字符串** ✓（流程包形状封闭 ✓ —— `spec/05` §4.2 ✓），
> 而**动作的参数带类型** ✓（`integer` / `number` / `boolean` / `enum` ✓ ——
> `spec/02` §4.3 ✓）。**两边对不上** ✗ →
> **带类型的动作在流程里根本调不动** ✗（`invalid_params：参数「value」要 integer` ✓）。

→ 流程层**按动作自己声明的类型转一遍** ✓（转完仍然由授权层按 schema 校验 ✓）。
判据：`tests/unit/workflows/runner.test.ts`（3 条 ✓）。

### 3.1 三条**值得说**的设计决定

**① `cpu.governor.set_all` 为什么必须有** ✓

RK3588 是 **policy 制** ✓（`policy0`=核0-3 · `policy4`=核4-5 · `policy6`=核6-7 ✓），
而 `cpu{N}/cpufreq` 是**软链** ✓ → **写 cpu0 实际写的是 policy0** ✓ → **只管 4 个核** ✓。
手册 §2.17 明确说「**全部核心都建议开启**」✓ → 只设一个核**不够** ✓。

**② `camera.snapshot` 的回读为什么是 `command_ok` 而不是 `verify`** ✓

没接相机时 gst 会报 `not-negotiated (-4)` ✓ —— **那才是有用的诊断** ✓。
用 `verify`（轮询 `test -s`）只会等满 30 秒然后说「**超时**」✗ → **把真正的原因盖住了** ✗。
→ **让 gst 自己说话** ✓（它的 stderr 会进报告 ✓）。
（「文件非空」由流程层那条 `camera-capture.capture` 断言 ✓ —— **两层分工** ✓）

**③ `sysclock.set` 为什么是真需求** ✓

**板子的系统时间是 1970-01-01** ✓ —— 因为 **RTC 读不出来** ✓
（`hwclock` 报 `RTC_RD_TIME: Invalid argument` ✓）且出厂没跑 NTP ✓（没联网就不对 ✓）。
→ 不设时间，**板子上所有日志的时间戳都是 1970** ✓。

> ⚠️ **格式自己填** ✓ —— 不替用户猜「现在几点」✓
> （**宿主的时间也不一定对** ✓ —— 两个都不对的时候，**人填的那个才是真的** ✓）。

### 4.3 两条**写法上**的教训（都写进包里了 ✓）

| 坑 | 现象 | 写法 |
|---|---|---|
| **`v4l2-ctl --list-devices`** | 它**去打开每个设备节点** ✓ → 没插相机的节点让它**整体失败** ✓ | **读 sysfs** ✓（`/sys/class/video4linux/video*/name` ✓） |
| **`dd` 的统计在 stderr** | 产出槽**是空的** ✓（执行器只取 stdout ✓） | **命令自己加 `2>&1`** ✓ |
| **`pkill -f "iperf3 -s"`** | **把自己的 shell 也杀了** ✓ | **`pkill -x iperf3`** ✓ |
| **输出里有换行** | 拼进下一步的命令被**注入防线拒绝** ✓（那是对的 ✓） | **只取需要的单行** ✓（`\| grep receiver` ✓） |

> ⚠️ 最后一条尤其值得记住：**注入防线两次拦住了我** ✓ ——
> 一次是 device-tree 的**尾随 NUL** ✓，一次是 **iperf 的多行输出** ✓。
> **它是对的** ✓ —— 该改的是**取数的写法** ✓，不是防线 ✓。

## 6 · **没做**的（写清楚，免得被当成漏做 ✓）

| 项 | 为什么 |
|---|---|
| **`hwclock.write`（写硬件时钟）** | **这块板读不出 RTC** ✓（`RTC_RD_TIME: Invalid argument` ✓）→ 做了也是**一条必然失败的动作** ✓ → **不做** ✓ |
| **`wifi.connect` / `wifi.disconnect`** | connmanctl 的连接是**多步** ✓（`enable` → `scan` → 找到 service id → `connect` ✓）→ **一条动作装不下** ✓ → **该做成流程** ✓（**还没做** ✓ · 见 §7 ✓） |
| **`factory.selfcheck`（一条动作跑全部自检）** | 厂商脚本**名字各不相同** ✓ → 一条命令没法分发 ✓ → **做成流程** ✓（每个脚本一步 ✓） |
| **`mic` / `loudspeaker` 自检** | 厂商那两份脚本是 `for i in {1..1000}` 的**死循环** ✓ → **不列** ✓ |
| **相机的自动选路** | 四个节点的 name 都是 `rkisp_mainpath` ✓ → **型号认不出来** ✓ → **靠丝印对照** ✓（枚举 ✓） |
| **板子 → 客机的文件回传** | **板子到客机不通** ✓（`Network is unreachable` ✓）→ 抓帧留在板上 ✓（用**文件浏览器**拉 ✓） |
