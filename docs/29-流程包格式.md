# 流程包（workflow pack）格式 · 宿主层

> **日期**：2026-11-15
> **性质**：**宿主层的数据格式**——**不是契约**。
> `docs/spec/` 五份**一个字不改**（ADR-D31 R1：真板跑通**两条**流程后才谈晋升契约）。
> **校验器**：`src/main/workflows/format.ts`（本文与它**必须一致**；不一致时**以校验器为准**，本文要改）。
> **黄金样本**：`profiles/workflows/*.yaml`（**当测试跑**——样本是活文档）。

## 〇 · 它回答什么

| 包 | 回答 | 在哪 |
|---|---|---|
| 板型包（board pack） | **这块板有什么**（能产生哪些量、能接受哪些写） | `docs/spec/02-board-pack.md` |
| **流程包（workflow pack）** | **这件事怎么做**（多目标、多步骤、有判据、可追责） | **本文** |

> **它不是脚本**。脚本里可以藏任意命令；流程包是**声明**——
> 每个写步骤都要**过同一张危险地板**、**按动作授权**、**有回读判据**、**留一行审计**。

---

## 一 · 顶层

```yaml
formatVersion: 1          # 宿主层格式版本（**不是契约的 apiVersion**——免得混淆）
kind: Workflow            # 固定
id: hello-kernel.build-run
name: 编译内核模块 → 直传板子 → 装 → 跑
version: 1.0.0
description: …            # 可选

inputs: { … }             # 参数（封闭类型表）
roles:  { … }             # 角色 → 连接 profile
steps:  [ … ]             # 步骤（有序）
```

**封闭 schema**：顶层只认这 8 个字段，**未知字段一律报错**。
（流程包是声明——拼错的字段被静默忽略 = 流程照跑，只是少做了一件事。）

---

## 二 · `inputs`（参数）

类型表**照 `spec/02` §4.3，不另造一套**：

| type | 额外必填 | 说明 |
|---|---|---|
| `string` | `maxLength` | 不许开口 |
| `path` | `maxLength` | 同上 |
| `integer` | — | 可选 `min` / `max` |
| `number` | — | 可选 `min` / `max` |
| `boolean` | — | |
| `enum` | `values`（封闭取值表） | 不在 `values` 里 → **报错** |

其余字段：`required`（布尔）、`description`（字符串）。

**占位符** `{input:名字}` → 参数的值。
**替换后的最终命令要过地板与编码**（ADR-D31 R4）——
参数是 `string` 就按 `spec/02` §4.6 单引号包裹 → **注入面是关着的**。

---

## 三 · `roles`（角色 → 连接）

```yaml
roles:
  build:
    purpose: 编译所在（客机）
    profile: ubuntu-ssh        # **只许引用既有 profile id**
  target:
    purpose: 板子
    profile: board-adb
```

- **只许引用 profile id，不许覆写字段**（ADR-D31 R7）——
  凭据、地址、端口**全是宿主的账**。
- **角色不许绑到 `local`**（ADR-D31 R2）：`local` 是宿主自己的 shell。
- 角色名可出现在占位符里：`{role:target.host}` / `.port` / `.user` / `.key` / `.profile_id`
  （**封闭事实表**，不许翻 profile 的任意字段）。

## 四 · `steps`（步骤）

### 4.1 六种 kind（**封闭**）

| kind | 干什么 | 必填 |
|---|---|---|
| `exec` | 在某个角色上跑一条命令 | `role` `cmd` |
| `discover` | **产物发现**（按规则，不写死文件名） | `role` `pattern` `out`（+ 可选 `dir`） |
| `file.transfer` | **搬运**（源 → 目的地） | `from` `to` `cmd`（+ 可选 `out`：目的地路径进槽 ✓） |
| `action` | 引用**板型包里已声明的动作** | `role` `action` |
| `await` | 等一个判据成立 | `readback` |
| `assert` | 判据 + 不符时怎么办 | `readback`（`on_mismatch`: `fail`（默认）/ `continue`） |

> **`exec_script` 连「留位置」都不留**（ADR-D31 R11）——
> 逃生门一旦写进表项，agent 就会去用。

### 4.2 端点（`from` / `to`）

```yaml
from: { role: build,  path: "{output:artifacts}" }
to:   { role: target, path: "/opt/x" }        # ① 用户指定的路径
to:   { role: target, placement: kernel-module }   # ② 语义默认（**封闭词表**）
```

- **目的地三形态**：`path`（用户指定）\| `placement`（语义默认）\| `ask`（现场问，首版不做）。
- **placement 词表（封闭）**：

  | placement | 落位 | 依据 |
  |---|---|---|
  | `kernel-module` | `/usr/lib/modules/<版本>/extra/` | `docs/02` §3.5 |
  | `user-program` | `/usr/local/bin/` | `docs/02` §3.5 |

  拼错 → **报错**（不能默默回落到「随便放」→ 流程报成功而东西不在该在的地方 ✗）。

### 4.3 判据（`readback`）：**复用 M6 的五形式**

与 `spec/02` §4.4 **完全一致**（不新增第六种形式，ADR-D31 R3）：

```yaml
readback: { tag: some.tag, expect: true }          # 形式 1
readback: { kind: file_equals, path: …, expect: …, tolerance: 1 }   # 形式 2
readback: { kind: command_ok }                     # 形式 3（串口上没有退出码 → 被拒）
readback: { kind: verify, command: …, timeout_ms: … }              # 形式 4
readback: { kind: none, consequence: … }           # 形式 5（必填非空）
```

**唯一的扩展：多一个 `role`** → **「在哪个角色上读」**。

```yaml
readback:
  kind: verify
  role: target          # ← **在板子上读**，不是在本步自己的角色上
  command: "test -f {to.path}"
```

**为什么必须能指名角色**：板型包的回读**只验「目标自己」**——
「客机跑完 scp 之后，**板子上**真的有那个文件了吗」**验不了**（ADR-D32 D32-1/D32-2）。
→ **跨目标的验证词汇由流程层出** ✓，而且**不新增回读形式**，只是多一个「在哪读」✓。

## 五 · 占位符（**封闭的五种**）

| 写法 | 指什么 |
|---|---|
| `{input:名字}` | 一个参数的值 |
| `{role:角色.事实}` | 角色的连接事实（`host` / `port` / `user` / `key` / `profile_id`） |
| `{output:槽}` | **前面某一步**产出的槽（`discover` 的 `out` / `file.transfer` 的 `out`） |
| `{output:槽.name}` | 那个文件名**去掉扩展名**（`hello.ko` → `hello`） |
| `{from.path}` / `{to.path}` | **这一步自己的**源 / 目的地（**只有 `file.transfer` 步里有**） |

**静态检查**（解析时就查，不留到运行时）：
指到没声明过的 input / 没声明过的 role / 没产出过的槽 → **报错**。
（拼错到运行时才炸 = 流程跑到一半才失败 ✗。）

**两种替换模式**（`src/main/workflows/substitute.ts` ✓）：

| 模式 | 用在哪 | 输入值 | 角色事实 | 槽里的路径 |
|---|---|---|---|---|
| **命令模式** | 步骤的命令、回读的二次验证命令 | **按类型编码过**（整数不带引号、字符串单引号 ✓） | **原样**（它是宿主自己的连接信息 ✓） | **单引号包住** ✓ |
| **值模式** | 回读的 `expect` / `path`、发现的 `dir` / `pattern` / `exclude` | 原样 | 原样 | 原样 |

→ **命令模式就是注入防线**：`; reboot` 这种输入值**被当字面量** ✓（`spec/02` §4.6 的同一套规则 ✓）。
→ **值模式不给引号**：那些地方比的是**值**，不是 shell 片段 ✓。

## 五·补 · 产物发现的两条实测教训（2026-11-15 真板）

| # | 教训 | 处置 |
|---|---|---|
| 1 | **一个工程可能产出好几个东西**（实测：`meminfo_static` + `meminfo_dynamic` ✗） | 首版：产物名做成**输入**（工程产物叫什么是**工程的事** ✓，ADR-D33 D33-3）；「按 `-u+x` 权限位找」**未做**（HAL 的 `FileEntry` 不带权限位 ✗） |
| 2 | **中间产物必须排除干净**（`.o` / `.cmd` / `.order` / `.mod.c`） | `exclude` 表**必须**有 ✓；漏一个就可能把中间文件当产物送上去 ✗ |

## 六 · 这份格式**不做**的事

| 不做 | 为什么 |
|---|---|
| **进 `docs/spec/`** | ADR-D31 R1：真板跑通**两条**流程后才谈晋升 |
| **卡片 API / MCP 工具** | 同上；且**卡片侧选目标**正是待裁决的 **D7** |
| **时间线的 push 通道** | ADR-D31 R9：首版 **poll**（`spec/00` §七 的流契约还没定死） |
| **`ask` 形态的落位** | 首版只做 `path` / `placement` |
| **流程包里的条件分支 / 循环** | 首版是**一条直线**；分支属于流程层的后一期 |
