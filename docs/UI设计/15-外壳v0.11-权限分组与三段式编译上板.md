## 一、设置 · 权限区

- 按 `kind` 分组：**元操作**（`action:*`）、**流程**（`workflow:*`）、**宿主**（`host:*`）。每组一个标题、条数徽标与一句说明，组内一行一个 op。
- 每行右侧两个 **Ant Design 风格的 switch**（按钮 `role="switch"`，36×20 圆角轨道 + 14px 滑块），分别代表 **卡片**与 **agent**；不再使用 checkbox。
- 顶部的「元操作 / 流程」总开关复用同一个 switch。总开关只对 **card** 生效：打开的类目一次性把 card 权限写全；**危险动作不跟随**，必须逐条打开。
- 危险动作行显示「危险」chip；总开关下方列出需要逐条打开的危险动作名字。
- 开关只调 `onPermission(actor, op, allowed)`，不另存一份权限——列表仍是唯一真源（ADR-D47）。

## 二、SSH 连接板子

- 现象：`板子 · SSH` 一直显示连不上。
- 根因：`profiles/targets/board-ssh.json` 的 `options` 只有 host/port/username，**没有 `key_filename`**。`sshArgs()` 因此不带私钥，ssh2 报 `All configured authentication methods failed`。
- 修复：给 profile 增加
  `"key_filename": "C:\\Users\\Administrator\\.ssh\\id_ed25519_codex_board"`。
- 验证：同一私钥直连 `root@192.168.5.100:22` 成功（`Linux ATK-DLRK3588 6.1.141 aarch64`）；`npm run validate:profiles` 0 错 0 警。

## 三、编译上板卡片（v2.0.0）

视觉语言改成**流程**，不再是「一条流程 + 一堆表单」：

1. 顶部三段步骤条：**1 编译 → 2 上传 → 3 运行**，步骤之间用细线连接；当前阶段高亮强调色，完成打勾变绿，失败变红。
2. 三个输入：**构建目录 / 项目 / 模块名**，都可以留空；留空时不传该键，让流程包里的默认值生效。
3. 每个步骤本身就是一个按钮：编译只跑 `hello-kernel.compile`，上传只跑 `hello-kernel.upload`，运行只跑 `hello-kernel.load`。
4. 运行后下方显示每一步的判据：`verified: true` 打勾，`verified: false` 用点表示「跑过但没验过」，失败用叉并附原因。
5. 权限面只有这三条 workflow；卡片自己不执行命令，只调 `cockpit.workflows.run/status`。

新增三个流程包（原来只有 `hello-kernel.build-run` 一条大流程）：

| 流程 | 做什么 | 默认值 |
|---|---|---|
| `hello-kernel.compile` | `cd {build_dir}/{project} && make`，再找 `*.ko` | `/home/alientek/kernel-build`、`01-hello` |
| `hello-kernel.upload` | 编译产物 `scp` 到板端核模块目录 | 同上 |
| `hello-kernel.load` | `depmod -a && modprobe {module}`，再 `lsmod` 验证 | `hello` |

三段都能单独重跑，失败时不用从头再来。
