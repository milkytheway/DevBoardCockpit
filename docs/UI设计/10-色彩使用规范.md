## 0. 结论先行

1. **色彩只有三个合法来源**：`--cockpit-*`（语义）、`--shell-mat-*`（材质）、`color-mix()` 里的白/黑明暗调节。
   其余一切写法（hex、rgb()、hsl()、颜色关键字直接上色）**一律禁止**。
2. **非生成产物的 CSS 里，一个颜色字面量都不许有** —— 已落地，由测试守着，不靠人记。
3. **`--shell-mat-*` 是外壳专有，卡片拿不到** —— 名字上就写着（`--shell-` vs 契约的 `--cockpit-`）。
   卡片一旦能自己造材质，「统一皮肤」当场就破。
4. **颜色只表达状态，不表达身份。** GPU 是蓝、NPU 是紫——这是**身份色**，禁止。
   身份用**文字标签**表达，颜色留给「正常 / 过时 / 危险」。
5. **数量上限**：一屏之内语义色 ≤ 3（正常 / 过时 / 危险）+ 强调色 1（选中）；
   背景**只允许一个主光晕**（当前有 4 个 → 见 §8 待拍板）。

> ⚠️ **这一版没有改动任何观感。** 材质层是**登记**，不是**重画**：
> 迁移前后 `visual.css` 的每一条声明解析成具体值后逐条比对，**零差异**
> （核验脚本见 §9.1）。

## 1. 「乱用色彩」到底从哪来

实测（迁移前）三个来源，**都不是审美问题，是治理问题**：

| # | 症状 | 实测 | 后果 |
|---|---|---|---|
| **a** | 色值没有登记处 | `visual.css` 43 处硬编码 / **31 个不同值** | 换一次底色要改 43 个地方；没人说得清哪些是刻意的 |
| **b** | 两套命名并存 | `--ui-*`（**270 处**）与 `--cockpit-*`（契约）混在同一文件 | 「这个颜色该用哪个」没有答案 → 随手选 → 漂 |
| **c** | 同一概念两个来源 | 终端主题有**两套**：<br>`shell/theme.ts` 用种子值；<br>`TerminalView.tsx` 存着计划 1 时代的回落色 `#14171c` / `#dfe4ec` / `#58a6ff` / `#1c2027` | 两套都在，只是没同时生效过 —— **这正是「迟早会漂」的样子** |

三个症状的**共同点**：色彩没有**唯一真源**，也没有**判据**。
所以这一版的做法不是「规定大家要克制」，而是**把真源和判据都装上**。

## 2. 三张色表

### 2.1 语义层 `--cockpit-*`（**契约层**，卡片可依赖）

机器可读权威：`src/shared/theme/alias.ts`　渲染结果：`src/shared/theme/seed.ts`（换皮改这里）

| 变量 | 角色 | 契约 | 含义 |
|---|---|:--:|---|
| `--cockpit-bg` | bg-0 | ✅ | 应用底色 |
| `--cockpit-bg-elevated` | bg-2 | ✅ | 面板抬头 / 输入框 / 悬浮 |
| `--cockpit-surface` | bg-1 | — | 面板与卡片底 |
| `--cockpit-surface-active` | bg-3 | — | 选中面 |
| `--cockpit-border` | border | ✅ | 发丝分隔线 |
| `--cockpit-border-strong` | border-strong | — | 面板边框 / 输入框（≥ 3:1） |
| `--cockpit-text` | text-0 | ✅ | 正文 / 读数数字 |
| `--cockpit-text-dim` | text-1 | ✅ | 次要文字 / 单位 / 标签 |
| `--cockpit-text-faint` | text-2 | ✅ | 弱化文字 / 空状态 |
| `--cockpit-accent` | accent | ✅ | **唯一强调色**：选中 / 聚焦 / 链接 |
| `--cockpit-accent-2` | accent-2 | ✅ | 第二强调 / 图表第二序列 |
| `--cockpit-ok` | ok | ✅ | 正常 / live |
| `--cockpit-warn` | warn | ✅ | 降级 / stale |
| `--cockpit-danger` | danger | ✅ | 错误 / destructive |
| `--cockpit-unavailable` | unknown | ✅ | **不可用**：这块板不提供这个能力 |
| `--cockpit-series-1…7` | series-* | — | 图表序列 |
| `--cockpit-radius` / `--cockpit-font-mono` / `--cockpit-font-ui` | 几何 | ✅ | 圆角 / 等宽 / 界面字体 |

> **契约里的 18 个别名一个都不能少**（`tests/unit/theme/map.test.ts` 守着）。
> 卡片**只许**用这些（`spec/03` §6.3）。

### 2.2 材质层 `--shell-mat-*`（**外壳专有**，卡片拿不到）

机器可读权威：`src/shared/theme/material.ts`　**25 条档位**，5 个族：

| 族 | 干什么 | 档位（举例） |
|---|---|---|
| **veil** 遮罩 | 叠在内容**下面**的半透明底 | `veil-code`（JSON 块底）、`veil-terminal`（终端窗格底）、`veil-canvas`（画布环境光） |
| **edge** 边缘 | 描边、上沿高光、发丝线 | `edge-highlight`（面上沿 1px 高光）、`edge-bright`（主按钮强高光）、`edge-hairline`（发丝线掺白） |
| **sheen** 面光 | 面板/卡片面上的那一层渐变 | `sheen-card`（玻璃卡片面）、`pure-white`（浅色皮肤纯白） |
| **lift** 投影 | 浮起、压下、拖拽 | `shadow-card`、`shadow-glass`、`shadow-glass-hover`、`shadow-detail`、`shadow-lift`、`shadow-active`、`shadow-selected` |
| **canvas** 画布 | 最底下那一层 | `canvas`（玻璃画布底） |

**为什么叫 `--shell-mat-*` 而不是 `--cockpit-mat-*`**：
`--cockpit-` 是**契约前缀**，卡片能依赖。
材质层是外壳自己的事——一旦卡片也能用，它就会开始造第二套材质。
→ **名字上就把边界写着**，比写文档可靠。

**材质层的两条规矩**：

| 规矩 | 为什么 |
|---|---|
| 值**只许出现在这一层**（CSS 里不许再抄一遍） | 否则又一份真相 |
| 材质**不表达语义** | 「这个红是危险」还是「这个红是玻璃反光」？必须只有前者 |

### 2.3 组合层 `--ui-*`（**visual.css 局部**，18 个 / 270 处引用）

这是 `visual.css` 的**局部变量层**，不是新的色源：

| 类别 | 变量 | 规矩 |
|---|---|---|
| 几何 | `--ui-statusbar-h` `--ui-rail-w` `--ui-secondary-w` `--ui-radius-*` `--ui-gap` | 随便改 |
| **材质** | `--ui-highlight` `--ui-shadow-card` `--ui-shadow-float` `--ui-hairline*` `--ui-surface-*` | **必须**由 `--shell-mat-*` / `--cockpit-*` 派生，**不许引入新色** |

判据：`tests/web/visual-material.test.ts` 里「CSS 里不许**重新定义** `--shell-mat-*`」。

## 3. 规则（全部可机械判定）

| # | 规则 | 判据在哪 |
|---|---|---|
| **R1** | 非生成产物的 CSS 里**不许出现** hex / `rgb()` / `rgba()` / `hsl()` | `visual-material.test.ts` |
| **R2** | 颜色关键字（`white` `black` …）**只许出现在 `color-mix()` 里**——那是明暗调节，不是上色 | 同上 |
| **R3** | CSS 里用到的每个 `--shell-mat-*` **必须**在材质层登记过（不许影子变量） | 同上 |
| **R4** | 材质层**不许有孤儿**（登记了没人用 = 又一份真相） | 同上 |
| **R5** | `--shell-mat-*` **只许在生成产物里定义一次** | 同上 |
| **R6** | **卡片拿不到材质层**（`themeCss()` 不含 `--shell-mat-`） | 同上 |
| **R7** | 卡片 CSS 里**不许有颜色字面量**，也不许用 `--shell-mat-*` | 同上 |
| **R8** | 主题的**产出方**（终端主题 / ECharts 主题 / 卡片基础样式）**不许手写色值** | 同上 |
| **R9** | 终端的兜底色**必须等于种子真值**（不许另抄一份） | 同上 |

> **R1–R9 是判据，不是建议。** 违反 = 测试红。

## 4. 允许 / 禁止清单

### ✅ 允许

| 写法 | 用在哪 | 为什么行 |
|---|---|---|
| `var(--cockpit-accent)` | 一切强调 | 换皮跟着变 |
| `var(--shell-mat-shadow-glass)` | 玻璃卡片投影 | 材质有名字、有用途、有归属 |
| `color-mix(in oklab, var(--cockpit-surface) 96%, var(--shell-mat-pure-white))` | 浅色卡面 | 白是**调节**，不是**上色** |
| `color-mix(in oklab, var(--cockpit-accent) 30%, transparent)` | 选中态的淡强调 | 同上 |
| `var(--cockpit-text-dim)` / `--cockpit-text-faint` | 层次 | 中性三档，不加色相 |

### ❌ 禁止

| 写法 | 为什么禁 |
|---|---|
| `#58A6FF` / `rgba(255,255,255,0.06)` | 第一份真相之外的任何一份 |
| `color: white` / `background: black` | 直接上色。颜色关键字只许当**明暗调节**用 |
| `linear-gradient(90deg, var(--cockpit-accent), var(--cockpit-accent-2))` 当**数据编码** | 渐变让「这段有多长」读不准；渐变只该在**材质**上 |
| 卡片里定义 `--cockpit-*` 或 `--shell-mat-*` | 影子变量 |
| 卡片里用 `--shell-mat-*` | 卡片拿不到 → `var()` 落空 → 静默失效 |
| 用**颜色**区分身份（GPU 蓝 / NPU 紫） | 颜色是**状态**的通道，身份用**文字** |
| 常态发光（`drop-shadow` / `box-shadow` 彩色） | 常态发光 = 常态抢注意力 = 一屏就乱 |

## 5. 数量上限（"一屏最多几种色"）

| 层 | 上限 | 理由 |
|---|---|---|
| **语义色** | ≤ 3（`ok` / `warn` / `danger`） | 三态够表达「好 / 注意 / 出事了」。`accent` 不算语义，算**交互** |
| **交互色** | 1（`accent`，只给选中 / 聚焦 / 链接） | 「唯一强调色」是 `seed.ts` 里写死的 |
| **身份色** | **0** | 身份用文字标签 |
| **中性色** | 3 档（`text` / `text-dim` / `text-faint`）+ 3 档面（`bg` / `surface` / `bg-elevated`） | 层次靠**明度**不靠色相 |
| **背景光晕** | **1 个**（当前 4 个 → §8） | 四团彩色光晕 = 「乱用色彩」的直观来源 |
| **一张卡内** | 语义色 ≤ 2 + 身份色 0 | 见 `11-卡片内部设计规范.md` §3 |

## 6. 卡片侧 vs 宿主侧（分列）

| | 宿主（外壳） | 卡片 |
|---|---|---|
| 能用的色 | `--cockpit-*` 全套 + `--shell-mat-*` | **只有契约的 18 个 `--cockpit-*`** |
| 能定义色 | 只有 `seed.ts`（换皮的人改那里） | **不能定义任何色** |
| 能用 `color-mix` 的白/黑 | 能（材质调节） | 能（明暗调节），但不得当上色 |
| 能发光 | 只在交互反馈（hover / 拖拽） | **常态不许发**；越界时才发 |
| 能用渐变 | 只在材质（面高光、投影） | **不许用在数据编码上** |
| 状态怎么表达 | 宿主注入 `.cockpit-*` 类 | **必须选宿主给的类**，不许自己写状态色 |

## 9. 判据与核验

### 9.1 「观感零变化」的核验方法（可复现）

迁移前后，把 `visual.css` 的**每一条声明**解析成具体值（`var()` 全部展开，
`--shell-mat-*` 展开成材质值），再逐条比对：

```
[dark]  removed=1 added=0
   - box-shadow: -24px 0 48px rgba(30, 40, 55, 0.16)     ← 浅色专属规则，折叠进材质层
[light] removed=1 added=0
   - box-shadow: -24px 0 48px rgba(0, 0, 0, 0.42)        ← 暗色规则，被材质层的浅色值取代
```

每套皮肤里唯一「消失」的那条，**都是在该皮肤下本来就不生效的那条**；
取代它的新值与它**逐字相同**。
→ **两套皮肤的最终计算样式完全一致。**

| 文件 | 管什么 |
|---|---|

| [`tests/unit/theme/map.test.ts`](../../tests/unit/theme/map.test.ts) | 别名齐全、对比度、生成产物一致 |
