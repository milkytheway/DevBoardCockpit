## 一 · 你要做的是什么（一句话）

> **给一个刚接上、还不认识的板子，配一个属于它的包。**
> 人只做一件事：**选串口 + 波特率** ✓ → 剩下全自动 ✓。

---

## 二 · 这个界面长什么样（**流程有五段** ✓）

```
① 选参数  →  ② 建立「第一个真相」  →  ③ 试元操作  →  ④ 生成包  →  ⑤ 成了 / 没成
   人做          机器做                机器做          机器做        说人话
```

### ⓪ 先问一句：**走哪条通道？** ✓

| 通道 | 什么时候选它 | 要填什么 |
|---|---|---|
| **串口** | 板子的**调试口**接上了 ✓ | 串口号 ✓ + 波特率 ✓ |
| **ADB** | 板子**插着 USB** ✓ | **什么都不用填** ✓（**零凭据** ✓） |

→ ⚠️ **默认是串口** ✓（用户定的是「**先从串口开始**」✓）。
→ ⚠️ **别做成两个并列的大按钮** ✗ → **一个小的切换** ✓（**串口 / ADB** ✓）就够 ✓。

### ① 选参数（**唯一人做的一步** ✓）

| 字段 | 说明 |
|---|---|
| **串口号** | **手动填** ✓ —— **不自动枚举** ✓（用户已定 ✓）。**placeholder 给个例子**（`COM3` ✓）<br>⚠️ **选了 ADB 时这个字段要变灰** ✓（**不是隐藏** ✓ —— **让他看见「这条路不需要它」** ✓） |
| **波特率** | **下拉** ✓ —— 常用值在前（**115200 / 921600 / 1500000 / 460800 / 921600 …** ✓）· **1500000 标一句「这块板是这个」** ✓（`docs/02` 事实 ✓）· 允许手填 ✓<br>⚠️ **选了 ADB 时也要变灰** ✓ |
| **板子的名字** | 文本框 ✓ —— **中文要能用** ✓（实测过 ✓ · 中文 id 合法 ✓） |

**⚠️ 别做的事**：
- ❌ **不要自动枚举 COM** —— 用户明确说**不要** ✓（`docs/探索/02` §一·1.2 ① ✓）→ **也别加「扫描串口」按钮** ✗
- ❌ **不要加「试试其他波特率」的循环** ✗ —— **不试** ✓（同一条 ✓）
- ❌ **不要在这一步放任何「高级」选项** ✗ —— **这一步只有三个字段** ✓

### ② 建立「第一个真相」

→ **一条真的能跑命令的连接** ✓ —— 不是「连上了」✓，是「**命令真的返回了东西**」✓。

### ③ 试元操作

→ **把 13 个通用元操作一个个在这块板上试** ✓ → **绿/红 = 这块板的真相表** ✓。

### ④ 生成包

→ **自动完成** ✓ —— 人不参与 ✓。

### ⑤ 成了 / 没成（**这里最见功力** ✓）

→ **四种结果，四种说法** ✓ —— **它们是不同的故障** ✓ → **修法完全不同** ✓：

| 结果 | 界面上要说什么 | 要给什么提示 |
|---|---|---|
| **成了** ✓ | 「**这块板现在有自己的包了**」✓ + **多少个元操作可用 / 不可用** ✓ + **包在哪** ✓ | ⚠️ **一定要说清楚**：**「这是自动探出来的初版包 —— 说得准的地方是事实（有没有 ✓ · 几个 ✓），说不准的是命名与语义（哪个温区是 SoC ✓）」** ✓ |
| **串口打不开** ✓ | 「**串口打不开**」✓ | ⚠️ **最常见的不是口错，是「有别的程序正独占着那个口」** ✓ → **这条必须说** ✓（`docs/02` 事实 ✓ —— `serial-server.py` 会把回包吃掉 ✓ → **板子是活的、串口是通的** ✓ → **但每个 reader 都报超时** ✓ → **说清楚人才不会往「板子死了」查** ✓） |
| **板子没说话** ✓ | 「**板子没说话**」✓ | ⚠️ **不许说「连接失败」** ✓ —— **连上了，只是它没回话** ✓ → 三种常见原因：波特率不对 ✓ · 不是调试口 ✓ · 回包被吃了 ✓ |
| **一个数都没出来** ✓ | 「**那条连接一次都没通**」✓ | ⚠️ **这不是那些元操作的问题** ✓ → **先把连接查对，再查元操作** ✓ |

## 三 · 接口（**是真的** ✓ · 你直接调 ✓）

```ts
// src/shared/ipc-contract.ts ✓ 已加好 ✓
wizardRun(input: {
  port: string;        // 串口号（手动选 ✓）
  baudrate: number;    // 波特率（不试 ✓）
  boardName: string;   // 板子名（中文要能用 ✓）
  transport?: 'serial' | 'adb';   // 缺省 = 串口 ✓
}): Promise<WizardRunResult>;

// WizardRunResult 的形状 ✓
{
  ok: boolean;
  kind: 'ok' | 'port-unopenable' | 'no-reply' | 'connection-dead';
  message: string;        // 一句话（**说人话** ✓）
  hints: string[];        // 下一步查什么（**空数组 = 没什么要提醒的** ✓）
  greenCount: number;     // 多少个元操作可用 ✓
  redCount: number;       // 多少个不可用 ✓
  installedDir?: string;  // 包落在哪（**成了才有** ✓）
  boardId?: string;       // 这块板的 id（**成了才有** ✓）
}
```

**⚠️ 三条你必须知道的**：
1. **它只给宿主** ✓ —— **卡片与 agent 都拿不到** ✓（它会写用户的目录 ✓）
2. **它不返回进度** ⚠️ —— **一次调用跑完全程** ✓（**几十秒** ✓）→ **所以界面必须能「等着」** ✓（见 §四·3 ✓）
3. **失败时 `ok: false` 但 `message` 仍然有话** ✓ → **别只看 `ok`** ✓ → **四种 `kind` 要分开画** ✓

## 四 · 界面要求（**这一节是重点** ✓）

### 1 · 它是**一个向导**，不是一个表单页 ⚠️

→ **五段是一条线** ✓ → **要让人一眼看出「走到哪了」** ✓
→ **但别做成一堆步骤条** ✗（**这产品克制** ✓）→ **一条细的进度轨 + 当前段的名字** ✓ 就够 ✓。

### 2 · **等待态是这块界面最难的地方** ⚠️

→ **一次调用几十秒** ✓ → **期间界面必须活着** ✓：
- **要有「正在做什么」的当前动作** ✓（**「建立第一个真相」** / **「试 13 个元操作」** / **「生成包」** ✓）
- **不许是一个转圈** ✗ —— **转圈不说是哪一步** ✓ → **说清楚是哪一步** ✓
- **不许让按钮看起来还能点** ✗ —— **跑着的时候要禁用** ✓（否则用户会重复提交 ✓）
- ⚠️ **别自己编进度百分比** ✗ —— **宿主不给进度** ✓ → **只说「第几步 / 共几步」这类能说准的** ✓（**「试元操作 13 个」** ✓）

### 3 · **失败态要说「下一步查什么」** ⚠️

→ `hints` **不是装饰** ✓ → **逐条列出来** ✓
→ **每条是一个可执行的动作** ✓（「先停掉那个进程，再重试」✓ 而不是「请检查串口」✗）。

### 4 · **成功的画面要克制** ⚠️

→ **主视觉是「成了」** ✓ → 下面一行「N 个可用 · M 个不可用」✓ → 再下面 **包在哪** ✓（**路径可以复制** ✓）
→ ⚠️ **别做成一个大表格列出 13 个元操作** ✗ —— **那是「运行日志」页该干的** ✓（**别重复** ✓）
→ ⚠️ **但「那 13 个里哪几个不可用」是有用的** ⚠️ → **折叠起来** ✓ / **一句话概括** ✓ → **想看细节的人点开** ✓。

### 5 · ⚠️ **那句「这是初版」必须出现在成功画面上** ⚠️

→ 「**自动探出来的初版包** ✓ —— **说得准的是事实** ✓（有没有 ✓ · 几个 ✓），
**说不准的是命名与语义** ⚠️（哪个温区是 SoC ✓ · 那要 agent 去补 ✓）」
→ **这是产品的诚实** ✓ —— **不能因为「成功了」就把它藏起来** ✗。

### 6 · 视觉纪律（**已有规范，照着做** ✓）

| # | 规矩 | 出处 |
|---|---|---|
| 1 | **不许自己写 CSS 变量体系** ✓ | `docs/UI设计/10-色彩使用规范.md` §六·1 ✓ —— 三层 `--cockpit-*` / `--shell-mat-*` / `--ui-*` ✓ |
| 2 | **不许在 CSS 里写 hex / `rgb()` / `rgba()` / `hsl()`** ✓ | 同上 **R1** ✓ —— **有机械判据** ✓（`visual-material.test.ts` ✓）→ **你写完它会红** ✓ |
| 3 | **颜色只表达状态** ✓；**身份用文字** ✓ | `11-卡片内部设计规范.md` §0·5 ✓ |
| 4 | **常态不许发光** ✓ | 同上 §0·6 ✓ |
| 5 | **每块区域最多 1 个视觉重心** ✓ | 同上 §0·2 ✓ —— **注意力是零和的** ✓ |

### 7 · **别造新的视觉语言** ⚠️

→ **外壳已有 `visual.css` 的一套** ✓（`.rail` / `.secondary` / `.page-head` / `.live-dot` / `.state-chip` …✓）
→ **你的向导页要用它们** ✓ → **别开一套新的** ✗ → **两套语言放在一起，大脑要切换两次** ✓（**这是「卡片一多就乱」的同一个病** ✓）。

### 8 · 动效只回答动作 ⚠️

→ **数据自己变不配动画** ✓ → **数字用 `tabular-nums`** ✓
→ **但「进度轨往前走」是动作** ✓ → **那个可以动** ✓。

## 九 · 一句提醒（**这个产品最容易犯的错** ✓）

> **「探针成功了」不等于「界面成功了」** ✓
> → **用户看到的是：三个字段 ✓ · 几十秒的等待 ✓ · 一次说人话的结果 ✓**

> → **所以「正在做什么」这行字，比任何装饰都值钱** ✓。
