## 2. 二级侧边栏的卡片行

- 卡片行不再统一用 LayersIcon：新增 `CardGlyph`（cpu / gpu / memory / thermal / board / bolt / activity），每一行画**自己的图标**。
- 每张卡的图标放进 **28×28 的色块**，色块颜色来自 `--card-tone`（10% 底、24% 边、78% 图标色）；这个 tone 只是**识别色**，不表达状态。
- 行结构：`图标 | 名称 / 主区 + cardId · 动作提示 | 置顶星`；「主区」chip 放在第二行提示语前，避免挤压名称（名称不再被截成 `GPU / N...`）。
- 置顶/分组/折叠逻辑不变；e2e 钩子（`data-cockpit-card-id`）不动。

## 3. 卡片：流程与板级操作

### 3.1 `build-deploy`（编译上板）

- manifest：`w4 h3 / min 3×2`，只声明两条编译流程：`hello-kernel.build-run`、`meminfo-user.build-run`。
- 卡内只有：流程下拉 → 该流程声明的输入 → 运行 → 阶段列表；没有解释段落，没有命令。
- 阶段列表沿用守卫要求的 `deck__step` 类：`--ok`（验证过）、`--warn`（发出但未验证）、`--bad`（失败）。

### 3.2 `workflows`（流程，新增）

- manifest：`w4 h4 / min 3×3`，声明其余六条真板流程：板子体检、厂商出厂自检、相机抓帧、网络测速、authorized_keys、存储测速。
- 同样只有下拉 / 输入 / 运行 / 阶段；卡片内的允许清单与 manifest 同步，**真正的闸仍在 main**（未声明的流程调用会返回 `denied`）。
- 需求点「真板上的流程与操作接进来」落在两张卡上：编译类归 `build-deploy`，体检/测量类归 `workflows`，避免一张卡堆 8 条流程。

### 3.3 `board-actions`（板级操作，新增）

- manifest：`w4 h4 / min 3×3`；`permissions.write = led.set / backlight.set / cpu.governor.set`；只读 `cpu.governor`、背光亮度。
- 三行控件：LED 开关、背光滑杆（16–255）+ 应用、调频策略下拉（走 `cpu.governor.set_all`）+ 应用。
- 每次结果按宿主回读显示：`已生效` / `已发出 · 未确认` / `回读不符` / `没有被授权` / `没有这个动作`。不自己执行命令、不假装成功。
- fake 板型包没有 `led.set`（真板有），所以假设备下 LED 会诚实显示「没有这个动作」；背光在假设备上可回读。

## 4. 设置页：授权总开关

- 权限卡顶部新增两个总开关：
  - **元操作**：`kind === 'action'` 且 `danger !== 'destructive'` 的全部行；
  - **流程**：`kind === 'workflow'` 的全部行。
- 打开 = 把该类每一行的 `card` 权限设为 `true`；关闭 = 全部 `false`。**危险动作不跟总开关走**，必须逐条打开；卡片里显示 `n / m 条对卡片开放`。
- 下方逐行 `卡片 / agent` 复选框仍是权威；总开关只是批量写入（复用既有 `permissions:set`，契约不改）。
- `PermissionRow` 增加可选 `danger` 回传，用于把「重启板子」排除出总开关。
