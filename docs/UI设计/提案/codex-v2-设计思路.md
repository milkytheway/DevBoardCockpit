## 一、这一版的主张

> **驾驶舱不是仪表盘，是一张多维表格。**

上一版（见 `codex-02`）把驾驶舱做成**深色仪器台**：石墨底、示波器波形、状态灯。
它有专业感，但用户看完说不出「这东西是干什么的」。

这一版换了个参照系：**飞书 / 钉钉多维表格**。
理由不是它好看，是它**匹配这个产品真正的使用动作**：

> 开发板驾驶舱的日常是**看一张不断变化的表**，偶尔点开一行看细节，偶尔插一张自己的卡。

多维表格就是这个动作的最成熟形态：字段列、类型图标、分组行、状态胶囊、
点行出详情。**把板子的实时状态做成一张表，比做成十个仪表盘更诚实也更好用。**

## 二、参考谱系

| 参考 | 借了什么 | 不借什么 |
|---|---|---|
| **飞书 / 钉钉多维表格** | 浅色圆角白卡、主蓝、视图导航、两级侧栏、表格（字段列 / 类型图标 / 分组行 / 状态胶囊）、点行出详情 | 它的「记录」语义（这里一行是一**个读数**，不是一条业务记录） |
| **航空 EFIS / ECAM** | 状态色谱系：红=立即处理、琥珀=须知、正常=绿、白=标题 | 复杂的多层 HMI 与语音告警 |
| **多维表格的应用模式** | 一级图标栏 + 二级内容栏 + 主区 + 右侧检查器 | 低代码搭建器那套编排 UI |
| **PulseView / Wireshark** | 曲线是示波器网格上的波形；顶栏一条过滤/排序工具条 | 三窗格、逐字段树 |
| **通用 SaaS 暗色仪表盘**（Dribbble 那类） | —— | **整类不取**：同质圆角卡、统一阴影、渐变装饰 |

## 三、五条原则

1. **状态先于数字。** 状态用胶囊/灯表达，数字用等宽表格数字右对齐。
2. **「不可用」必须不像一个数。** `unavailable` 那格显示 `—`，不显示 `0`，
   状态胶囊写「不可用」—— 这是契约 `unavailable ≠ 0` 的 UI 侧兑现。
3. **密度是礼貌。** 表格行高 34px，正文 13px，数字等宽；工程师按秒算时间。
4. **一套 token，宿主与卡片共用。** 卡片只允许用 CSS 变量，不许硬编码颜色。
5. **动效只回答动作。** 数据自己变**不配动画**；只有面板开合、拖拽吸附、状态切换有反馈。

## 四、色彩系统

### 4.1 基底（浅色为主，深色为辅）

取自多维表格的浅色体系：

| 角色 | 值 | 用在哪 |
|---|---|---|
| `--f-bg` | `#F2F3F5` | 画布 |
| `--f-surface` | `#FFFFFF` | 卡片 / 面板 |
| `--f-surface-2` | `#FAFBFC` | 表头、分组行 |
| `--f-border` | `#E5E6EB` | 发丝线 |
| `--f-border-2` | `#DDE0E5` | 面板描边、输入框 |
| `--f-text` / `-2` / `-3` | `#1F2329` / `#646A73` / `#8F959E` | 正文 / 次要 / 标注 |
| `--f-blue` | `#3370FF` | **唯一强调色**：选中、主按钮、AI 造卡 |

### 4.2 状态色（五态）

| 状态 | 胶囊 | 底色 | 语义出处 |
|---|---|---|---|
| `ok` 正常 | `#00B42A` | `#E8FFEA` | ECAM：正常 = 绿 |
| `stale` 已过时 | `#FF7D00` | `#FFF3E8` | ECAM：须知不紧急 = 琥珀 |
| `pending` 等待 | `#8F959E` | `#F2F3F5` | 还没基线 |
| `unavailable` 不可用 | `#8F959E` | `#F2F3F5` | **不是故障**，是「这块板不提供」 |
| `error` 读取失败 | `#F53F3F` | `#FFECE8` | ECAM：需立即处理 = 红 |

### 4.3 对比度（实测，WCAG 2.1）

浅色皮肤上语义色全部达标（**这是「浅色主题直接复制暗色色板」最常翻车的地方**）：

| token | 实测 | 判定 |
|---|---|---|
| `--f-text` `#1F2329` on `#FFFFFF` | 16.66 | ✅ AAA |
| `--f-text-2` `#646A73` on `#FFFFFF` | 7.19 | ✅ AA |
| `--f-text-3` `#8F959E` on `#FFFFFF` | 3.02 | ⚠️ **只用于 11px 以上的标注，且不承载关键信息** |
| `--f-blue` `#3370FF` on `#FFFFFF` | 4.94 | ✅ AA |
| `--f-green` `#00B42A` on `#FFFFFF` | 5.31 | ✅ AA |
| `--f-orange` `#FF7D00` on `#FFFFFF` | 2.57 | ❌ **不可用作正文色**（只作胶囊底上的深字，见下） |
| `--f-red` `#F53F3F` on `#FFFFFF` | 5.63 | ✅ AA |

> **一条实测教训**：把暗色皮肤的 `#FF7D00` 直接搬到白底上，对比度只有 **2.57** ——
> 橙色在白底上几乎读不出来。**浅色皮肤的语义色必须单独调一遍，不能复制暗色值。**

## 五、字型

| 角色 | 字型 | 说明 |
|---|---|---|
| UI / 表格 | `'Segoe UI Variable'` → `'Microsoft YaHei UI'` → `system-ui` | 多维表格同款；中文优先落到雅黑 UI |
| 数字 | 同上 + `font-variant-numeric: tabular-nums` | **等宽表格数字，不跳位** |
| 路径 / tag 名 | `Consolas` / `Cascadia Mono` | tag 名要能复制进命令，等宽才可读可抄 |

> 这一版**没有**用 DIN / Bahnschrift（上一版用过）。
> 多维表格的观感是「现代办公软件」，DIN 是「仪表标识」，二者气质相反；
> 既然选了办公软件那条线，字型就该跟上。**DIN 留给卡片里的仪表类图形，不进宿主 UI。**

## 六、布局架构

```
┌──────────────────────────────────────────────────────────────────────┐
│ 顶栏 58   [RK] ATK-DLRK3588 ▾   已连接·adb   板型包   采样 1s      │
│                          [✨ AI 造卡]  (我)(AI)  分享  ⋯            │
├──────┬───────────────┬──────────────────────────────┬──────────────┤
│ 一级 │ 二级侧边栏     │ 主区                          │ 详情抽屉      │
│ 72px │ 212px         │                              │ 288px         │
│      │               │  指标卡 ×4                   │              │
│ 仪表 │ 连接          │  ┌────────────────────────┐  │  状态/类型/   │
│ 读数 │  会话          │  │ 读数表                  │  │  单位/取值域/ │
│ 终端 │  卡片          │  │ 字段列·类型图标·分组行  │  │  来源/采样    │
│ 文件 │               │  │ 状态胶囊                │  │  最近 10 次   │
│ 卡片 │               │  └────────────────────────┘  │  权限         │
│ 库   │               │                       [+]  │              │
│ 设置 │               │                              │              │
└──────┴───────────────┴──────────────────────────────┴──────────────┘
```

**四个结构决定**：

1. **一级侧边栏（72px 图标栏）取代横向视图标签栏** —— 横向标签栏一多就挤，
   而纵向图标栏可以一直挂着，不占垂直空间。
2. **二级侧边栏是「一级选中项的内容」** —— 选中「仪表」出连接/会话/卡片；
   选中「终端」出会话列表；选中「卡片库」出卡片分类。
   **它不是常驻的连接树**（那是旧模型）。
3. **详情抽屉按需出现** —— 点表格某一行才滑出，带关闭按钮与左侧淡阴影。
   它不是第三根固定列。
4. **板名是顶栏主角** —— 放大到 17px、带色块与下拉箭头、可点击换板；
   「AI 造卡」是右上角唯一的实心主按钮（这个产品的主张是「AI 是组态工程师」，
   它不该藏在二级菜单里）。

## 七、组件规格

### 7.1 读数表（最像多维表格的地方）

- **字段列头**：`位号 / 当前值 / 单位 / 状态 / 更新`
- **字段类型图标**：`#` 数字（蓝）、`T` 文本（青）—— 小色块，一眼分清类型
- **分组行**：`● 运行指标   12 项`，色点区分分组（核心 / 板型私有）
- **状态胶囊**：正常 / 已过时 / 不可用 / 读取失败
- **选中行**：浅蓝底 `#E8F0FF`，与右侧抽屉联动

### 7.2 状态胶囊的语义分工

| 胶囊 | 承载什么 |
|---|---|
| 正常 | 有值且在刷新周期内 |
| 已过时 | 旧值仍显示（契约 §2.1.1：stale 保留旧值） |
| 不可用 | **值显示 `—`**，原因写进胶囊 tooltip |
| 读取失败 | 保留旧值 + 红胶囊（不假装成功） |

### 7.3 详情抽屉

点一行 → 右滑：位号 + **语义原文**（这一行最重要 —— 它是给 AI 读的说明书）、
状态、类型、单位、取值域、**来源 reader**、采样周期、最近 10 次柱状、被几张卡引用。

### 7.4 卡片壳（沙箱 chrome 归宿主）

宿主画：卡片标题、来源 `cockpit://card/<id>/`、权限 chip、重载按钮。
卡片只画内容区。**这是安全边界在视觉上的兑现** —— 卡片骗不了用户的「这卡读了什么」。

## 八、动效

| 场景 | 动效 |
|---|---|
| **数据自己变** | **无**（等宽数字让它跳得不难看） |
| 状态胶囊切换 | 120ms 淡入 |
| 详情抽屉 | 滑出 180ms |
| 拖拽吸附 | 边框闪一下 100ms |
| 主题切换 | 无（直接切） |

`prefers-reduced-motion: reduce` 下全部降到 0ms。

---

## 九、可访问性

- 正文对比度 ≥ 4.5:1（实测值见 §4.3）
- **颜色不单独承载信息**：状态胶囊**有文字**，不靠色块区分
- 键盘可达，焦点环 2px 主蓝 + 2px offset，**不用 `outline: none`**
- 状态胶囊与表格行都有 `aria-label` / `role`
- 缩放 125% / 150% 不破版（表格用 grid + `minmax`）
- `forced-colors` 下用系统色

## 十、与 DSH v2 的关系（取舍，不是对错）

本目录里有两份并行提案。**两者不是同一条路**：

| | **DSH v2** | **Codex（本版）** |
|---|---|---|
| 材质 | 车机质感：深色渐变卡 + 顶部高光 + 14px 圆角 | 多维表格：浅色白卡 + 1px 描边 + 8px 圆角 |
| 主角 | **卡片画廊**（一屏 10 张卡，仪表为主） | **数据表**（卡片是容器，表格是主角） |
| 导航 | rail 58 + 视图标签栏 46 | 一级侧栏 72 + 二级侧栏 212 |
| 密度 | 高（60px 行高，12 列密集） | 中（34px 行高，可扫读） |
| 强项 | 卡片类型学丰富（半圈表盘、位幅值、寄存器组）、控制卡形态 | 状态语义表达到位、数据可扫读、AI 造卡入口显性 |
| 弱项 | 一屏信息量大，**初次使用者找不到入口** | 表现力弱，**做不出漂亮仪表** |

**我的建议**：**以本版为骨架，把 DSH v2 的卡片类型学搬进卡片内容区。**

理由：

1. 宿主外壳（导航 / 数据 / 详情）**要的是可扫读与可扩展**，多维表格的形态更合适；
2. 「好看」这件事**应该发生在卡片里，而不是发生在外壳里** —— 卡片是 AI 生成的，
   外壳是产品定的；**外壳越克制，AI 的卡片越有发挥空间**；
3. DSH v2 的卡片类型学（半圈表盘、幅值条、寄存器位组）是**内容层**的东西，
   与外壳形态不冲突，可以直接吸收。

**要合并才完整的三处**（DSH v2 更强）：

- **卡片类型学** → 进 `__host` 组件 kit，成为 AI 造卡的默认件
- **控制卡的凭据链**（每个写动作带 guard chip + 回读结果 + 审计）→ 与 M6 的执行器对齐
- **dock 形态**（终端/文件/日志收进底部 dock，而不是占卡片槽）→ 与 `docs/22` 的工具面收敛一致

## 十一、未拍板

1. **双主题优先级**：浅色与深色同时进 M5b，还是先上一套？
2. **「AI 造卡」按钮的行为**：开模板库？直接进对话？复制一段造卡 prompt？
3. **一级侧栏的项**：仪表 / 读数表 / 终端 / 文件 / 卡片库 —— 这五个是不是终局？
   要不要再加「连接管理」？
4. **读数表要不要虚拟滚动**：26 项没问题，几千项（M8 多板 + 高频 tag）就得虚拟化。
5. **详情抽屉 vs 独立页面**：抽屉适合「看一眼」，独立页适合「研究一下」。两种都要吗？
