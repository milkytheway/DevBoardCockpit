## 一、这一轮要解决什么

用户对 v1 四屏（总览暗/浅、卡片库、授权弹层）的反馈：

| 保留 | 要改 |
|---|---|
| 卡片质感好、有独立感、圆角合适 | 卡片与背景的对比再加强，参考智能车车机界面 |
| 一屏多卡、卡片间可自由分配空间 | 终端不要单独成卡，放进侧栏「终端」；文件传输同样 |
| 点卡片从侧边弹出详情 | 显示状态卡的内容要更多样（扇形半圈图、条形幅值图等） |
| 「已发现卡片」有质感、功能有用 | 除显示卡外，要带控件的卡（可拖动条、开关、寄存器组等） |
| AI 造卡按钮好 | 再做几版 |

v2 的回应可以概括成一句话：**把「驾驶舱」从卡片画廊推进到仪表台——卡片仍是主角，但信息形态和操作形态都要长出来；同时把终端/文件这类「工具面」从卡片槽里请出去。**

## 二、设计判断：车机质感 ≠ 玻璃堆叠

参考理想车机 UI 的讨论（[原文](https://www.sina.cn/news/detail/5310581345095691.html)，外部资料、仅作灵感）：玻璃拟态 + 大范围弥散阴影容易显得「脏」和「糊」，更可靠的做法是——

1. **清晰 1px 边界**：卡片与画布之间靠描边区分，而不是靠一层又一层投影。
2. **顶部白色高光**：`inset 0 1px 0 rgba(255,255,255,.05)` 给表面一条极细的「受光边」，立刻有材质感。
3. **亮度阶梯**：背景（最暗）→ 卡片表面（+1 级）→ 卡片内嵌控件（+2 级），用表面亮度而不是阴影表达层级。
4. **颜色区分容器与内容**：卡片容器保持中性，状态/波形/控件才用颜色；强调色仍然唯一（蓝）。
5. **极轻环境光**：画布上一团很淡的径向渐变即可，不做大面积模糊背景。

最终落成的卡片材质（v2 实际参数）：

```css
background: linear-gradient(178deg, #21262e 0%, #1a1f26 46%, #171c22 100%);
border: 1px solid rgba(255,255,255,.095);
box-shadow: inset 0 1px 0 rgba(255,255,255,.065),
            0 1px 2px rgba(0,0,0,.30);
border-radius: 14px;
```

浅色主题同一套结构，只换 token：白面 + `#DEE0E3` 描边 + `#FFFFFF` 顶部高光 + 更浅的投影。

**选中态**是这套语言里最重要的交互信号：`1px #58A6FF` run + 外发光 + 四角 8×8 缩放柄，和「未选中只差一个亮度等级」区分开，避免整屏都在喊。

## 三、信息架构

```
┌──────────────────────────────────────────────────────────────────────────┐
│ 状态带 44  品牌 · 连接 chip · 采样状态 · 最后更新 · 命令面板(Ctrl K)      │
├──────┬─────────────────────────────────────────────────────────┬─────────┤
│ rail │ 视图标签栏 46：总览 / 监控 / 调试 / 演示  ·  筛选/连接/密度 · 添加卡 │ 检查器  │
│ 58   ├─────────────────────────────────────────────────────────┤ 344     │
│ 工作 │                                                         │ 概览/数据 │
│ 卡片 │   12 列栅格（行高 60px，间距 12px）                       │ 权限/活动 │
│ 台账 │   ┌──────────┐ ┌───────────────┐ ┌──────────────┐        │ 回读历史  │
│ 终端 │   │ 卡片      │ │ 卡片           │ │ 卡片          │        │ 依赖      │
│ 文件 │   └──────────┘ └───────────────┘ └──────────────┘        │         │
│ 日志 ├─────────────────────────────────────────────────────────┤         │
│      │ dock（底部工具面）：终端 / 文件传输 / 运行日志 + 传输队列/待确认 │         │
└──────┴─────────────────────────────────────────────────────────┴─────────┘
```

- **视图 = 保存的配置**：每个视图有自己的卡片集合、位置尺寸、可见槽位；切视图不换数据源（沿用 `docs/22` 的视图模型）。
- **卡片是栅格里的唯一一等公民**：显示卡、控制卡、容器卡同一套 12 列网格、同一套卡壳。
- **终端/文件/日志是「工具面」**：收进底部 dock，三页签可切；dock 可折叠/拉高，但不参与卡片栅格。这正好回答反馈②——它们不该和「板卡状态卡」抢同一层注意力。
- **检查器是第二层**：点卡片右侧滑出（SideSheet），不占栅格；概览/数据/权限/活动/回读历史/依赖，回答「这张卡凭什么读、改了什么、验证没有」。
- **页面清单**：总览（默认）、监控（大屏/演示）、调试（控制与协议）、卡片库（管理面）、授权 sheet（M6）、设置。

### 4.1 Token（暗/浅两套，同一语义名）

| `--srf-2` 卡内控件 | `#1E242C` | `#F7F8F9` |
| `--hairline` 描边 | `rgba(255,255,255,.09)` | `#DEE0E3` |
| `--text-0` 主文字 | `#E6EAF2` | `#1F2329` |
| `--text-1` 次文字 | `#9AA4B2` | `#646A73` |
| `--text-2` 弱文字 | `#6E7887` | `#8F959E` |
| `--accent` 强调 | `#58A6FF` | `#3370FF` |
| `--ok` / `--warn` / `--danger` / `--unknown` | `#3FB950` / `#D29922` / `#F85149` / `#6E7681` | `#00B42A` / `#FF7D00` / `#F53F3F` / `#8F959E` |
| 图表 6 色 | 蓝/绿/橙/紫/青/黄（低饱和、同亮度） | 同序降明度 |

字体：UI 用 `Inter / Segoe UI Variable / system-ui`，数据与终端用 `JetBrains Mono / Cascadia Mono`；字号 11–13px 为主，仪表值 40–56px，表格 11.5px。动效 120ms（hover）/180ms（控件）/280ms（面板），统一 `cubic-bezier(.22,1,.36,1)`；只做位移与透明度，不做弹跳。

### 4.2 状态语义（卡片 footer / 状态点）

`live`（绿点，正常）· `pending`（灰，首采样）· `stale`（琥珀，显示旧值+时间）· `error`（红，保留旧值+原因）· `unavailable`（灰，不显示 0）· `degraded`（琥珀，缺 tag/缺能力）· `broken`（红，manifest 校验失败/沙箱崩）。

### 4.3 卡壳解剖

```
┌ 44px 宿主 chrome ──────────────────────────────┐
│ 图标  标题        sub(canonical id)   [状态chip] [控制chip] [⋯] │
├────────────────────────────────────────────────┤
│ iframe 内容（卡片自己的 HTML/CSS/JS）           │
│   · 仪表 / 环 / 条幅 / 波形 / 表格 / 控件        │
├ 22px footer ───────────────────────────────────┤
│ 状态 · 采样 2s · 回读 ✓ · 审计 · 更新时间        │
└────────────────────────────────────────────────┘
```

卡壳是宿主的，内容是被沙箱隔离的；卡片只能拿 `__host/theme.css` 的 token，保证双主题与视觉一致（对应 `docs/23` 的「卡必须和宿主一致」）。

## 五、卡片类型学（v2 的核心增量）

### 5.1 显示卡：不是只有折线图

| 形态 | 用在哪 | 交互/说明 |
|---|---|---|
| **半圈仪表** | CPU 使用率、SoC 温度、单值阈值类 | 弧形分区（正常/警告/危险）、指针、min/p95/max；一眼判断「是否越线」 |
| **双环** | GPU/NPU 利用率并排 | 环心显示数值；环下小字频率/回读状态 |
| **分段条幅** | 内存、存储、Swap | 10 段式而不是细进度条；缺数据段留灰，不用 0 填充 |
| **柱状幅值** | 中断分布、TOP-N 频次 | 柱高即数值，底部标 min/last/max |
| **双向镜像频谱** | 中断/IO 双向速率 | 上正下负，30s 窗口；适合「有没有突发」的扫视 |
| **多线曲线** | 频率/负载、多 tag 对比 | 三条线以内、图例即开关；阈值虚线标注 |
| **统计行 + 表格** | TOP 进程、峰值/阈值、回读历史 | 数据密集但安静；表格只用 1px 分隔线 |

每张卡都保留「状态 chip + 采样周期 + 读到的最后时间」——驾驶舱的底线是**你看到的是板子的真实状态**，不是乐观动画。

### 5.2 控制卡：写动作必须有回读和审计

| 控件 | 示例 | 规则 |
|---|---|---|
| 开关 Toggle | 风扇自动模式、GPIO 输出 | 开关旁显示当前值；危险动作走确认 |
| 滑块 Slider | PWM 127/255、频率上限 | 滑块气泡显示目标值；右侧显示范围；底部「写入 → 回读 → 审计」 |
| 分段 Segmented | governor（powersave/ondemand/performance） | 选中即目标态；应用按钮显式提交 |
| 寄存器位组 | GPIO1_IO 8 bit | 位开关 + 0x 十六进制 + 「写入 0x3C / 回读」+ 最近写入 |
| 动作按钮 | 全部拉高/拉低、总线扫描 | 批量动作给 guard 提示；执行后回读实际值 |

控制卡统一的「安全三件套」：**guard 范围**（卡头 chip）、**回读状态**（footer `回读 ✓ / 回读未确认`）、**审计**（最近写入行 + 检查器回读历史）。写失败/回读不一致时，卡片必须显示实际值而不是成功动效（对应 `spec/03` §5.3）。

### 5.3 容器卡（把信息组织起来的卡）

- **目标与链路**：板型/连接/传输/仲裁优先级/心跳——「我现在连着谁、链路活不活」。
- **TOP 进程**、**峰值/阈值**、**最近事件**：不是状态值，而是「正在发生什么」。
- **卡片库/检查器**不算卡片，是管理面与详情面。

### 04 · 调试（暗）
