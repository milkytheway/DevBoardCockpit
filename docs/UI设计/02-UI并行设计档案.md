## 一、两轨为什么能并行（实测）

```
src/main/  ──►  src/shared/  ◄──  src/renderer/
```

| 事实 | 怎么验的 | 含义 |
|---|---|---|
| `src/renderer/` **一处 import main 都没有** | `grep -rn "from '\.\./main" src/renderer/` → 无输出 | UI 轨**不依赖** core 轨的实现 |
| renderer 只 import `src/shared/ipc-contract` | 同上 | 两轨的公共面**只有 shared** |
| `src/shared/` 只 import 自己的文件 | `grep -n "^import" src/shared/*.ts` | shared **不依赖任何一侧** → 它是**契约面** |
| 计划 4 的 13 个任务里，只有 T8 / T11 / T12 碰 renderer | 见计划文件 | **core 轨的 10/13 个任务一行 UI 都不动** |

**结论**：物理上可并行。**剩下的全是「约定」上的耦合**，不是代码依赖。

## 二、三类耦合（不是代码依赖，是约定依赖）

| # | 耦合 | 表现 | 怎么解 |
|---|---|---|---|
| **1** | **形状耦合** | UI 要的数据形状 / API 形状 / 通道名一变，UI 的类型就变 | **形状必须在计划里写死**（计划 4 的 Interfaces 块已经写死）→ UI 轨**照着计划做**，不等实现 |
| **2** | **机制耦合** | UI 的某些效果**依赖 main 提供机制**（协议、注入、桥接、主题下发） | UI 轨只做「不依赖机制」的部分；依赖机制的部分**等** |
| **3** | **文件耦合** | 两轨都改同一个文件 → 并行到一半打架 | **文件所有权表**（§六） |

## 四、轨道 B（UI）：**现在就能做的 9 件事**

**判据：每件都只用「已有的东西」——现有 IPC 通道、现有契约、假数据、纯 CSS/TS。**

| # | 事 | 产物 | 为什么现在能做 | 判据 |
|---|---|---|---|---|
| **B1** | ~~token 三层骨架 + 生成脚本~~ → **划给 core 轨**（计划 4 的 **T11**：main 要注入主题，**注入端就得先有真源**） | `src/shared/theme/**` + `scripts/gen-theme.ts` | **core 轨拥有**（见下「所有权」一节的更正） | `npm run gen:theme:check` |
| **B2** | **对比度对拍测试** | 扩展 `tests/web/terminal-theme.test.tsx` | 纯读 token 文件 | 全部 token × 两套皮肤 × 三种底色 ≥ 4.5（或 ≥3 的控件边框） |
| **B3** | **五态零件** | `src/renderer/ui/StatusLamp.tsx`、`TagCell.tsx`、`StatTile.tsx`、`Sparkline.tsx` | 纯 renderer；五态语义**契约已冻结** | 每个零件的**五态矩阵**测试（视觉快照 + 类名断言） |
| **B4** | **数字格式化** | `src/renderer/ui/format.ts` | 纯函数 | `Intl.NumberFormat` 用例；小数点按 locale |
| **B5** | **卡片壳的静态部分** | `src/renderer/cards/CardShell.tsx`（header / footer / 状态遮罩，**不含 iframe**） | 纯 renderer，iframe 部分留空槽 | 快照测试；不含 iframe 也能渲染 |
| **B6** | **kit 静态资产** | `src/main/cards/kit/{kit.css,kit.js}` | **只写 `var(--cockpit-*)`，不写色值** → 静态、与皮肤无关 | 断言 kit.css 里**没有**任何 `#rrggbb` 字面量 |
| **B7** | **一屏四区的外壳零件** | `src/renderer/app/{StatusBar,Rail,Inspector,CommandPalette}.tsx` | 用**假数据**渲染；真实接线留到 T11 | 快照测试；假数据与真数据**接口相同** |
| **B8** | **读数明细表 / 卡片库列表（静态部分）** | `src/renderer/views/ReadingsTable.tsx`、`src/renderer/library/CardList.tsx` | 读数走**已有的** `tags:readings` | 用现有 API 的快照测试 |
| **B9** | **图标集** | `src/renderer/ui/icons/*.tsx`（≤ 20 个） | 纯 SVG | 数量 ≤ 20；统一 1.5px 描边 |

**⇒ B1–B9 全部是「纯新增文件」或「只读现有文件」→ 与 core 轨零冲突。**

## 五、轨道 B：**不要先做的 9 件事**

**这一节是本档案最重要的部分。** 每一条都写清「为什么现在做是浪费」和「什么时候解锁」。

| # | 不要先做 | 为什么现在做会浪费 | 什么时候解锁 |
|---|---|---|---|
| **N1** | **iframe 容器与 broker** | 要猜协议（握手格式、端口转移、instanceId 比对）——**猜错就是返工** | core 的 **T7 + T8** 落地后 |
| **N2** | **卡片内容区的样式** | 要等**别名层名字** + **状态类名**定死；卡片作者按名字取值，名字一改全废 | 别名进契约（ADR-D28 同批）后 |
| **N3** | **kit.js 的运行时部分**（`tags.use()` 等） | 它要调 `cockpit.*`——**API 形状在 core 的 T6** | core 的 **T6** 落地后 |
| **N4** | **栅格落盘 / 视图模型** | 要等 core 的 **T12** 与 `LayoutFile { views[] }` 进 ADR；**布局不是契约**，但落盘格式是 main 的 | core 的 **T12** 落地后 |
| **N5** | **工作区真实接线**（把真数据灌进外壳） | 要等 `cards:list` / `cards:hello` 等通道 | core 的 **T8** 落地后 |
| **N6** | **卡片库缩略图** | `capturePage` 需要**真有卡片可截**；且它属于 M5b | M5b |
| **N7** | **ECharts 接入** | 要等宿主提供 `__host/echarts.js` + 主题 JSON（Q3 定在 M5b） | M5b |
| **N8** | **命令面板里的卡片命令**（校验 / 安装 / 打开目录） | 要等 **M7 的 MCP 工具** | M7 |
| **N9** | **改 `src/renderer/App.tsx` / `index.html` / `tokens.css`** | **这三个是 core 轨的文件**（T11 / T12 会改）→ 并行必打架 | core 的 **T11** 之后 |

> **N9 尤其重要**：`App.tsx`（外壳重构）、`index.html`（外壳 CSP）、
> `tokens.css`（别名层）——**core 轨拥有**。
> UI 轨要碰它们，**先跟 core 轨打招呼**。

## 七、汇合点与建议顺序

```
        现在                        core 轨推进                     汇合
  ┌──────────────┐        ┌────────────────────────┐        ┌──────────────┐
  │ UI 轨 B1–B9  │        │ T1–T7（main 侧）        │        │ T11 接线      │
  │ 纯新增文件    │        │ T8 broker              │───────▶│ T12 栅格      │
  │ 不碰现有文件  │        │ T9–T10（main 侧）       │        │ M5b 视图/卡片库│
  └──────────────┘        └────────────────────────┘        └──────────────┘
         │                                                          │
         └──── 形状约定（计划 4 的 Interfaces 块）已写死 ────────────┘
```

| 汇合点 | 谁接 | 内容 |
|---|---|---|
| **M-1** | core T8 | UI 轨的 `CardShell` 接到真 iframe；broker 落地 |
| **M-2** | core T11 | UI 轨的外壳零件接到真通道；第一张卡跑起来；**外壳 CSP 生效** |
| **M-3** | core T12 | UI 轨的栅格接到 `get_layout` / `set_layout` |
| **M-4** | M5b | 视图预设、卡片库、kit v0、双主题收尾 |

**建议**：UI 轨在 M-2 之前**不接线**，只交「零件 + 假数据」。
理由：接线要等通道，而通道是 core 的产物；**提前接线 = 猜形状**。

## 八、判据怎么自动验

### 8.1 UI 轨自己的判据（不依赖 core）

| # | 判据 | 怎么验 |
|---|---|---|
| U1 | 生成的 CSS 与种子一致 | `npm run gen:theme:check`（与 `gen:vocabulary:check` 同套路） |
| U2 | 对比度达标 | 扩展 `tests/web/terminal-theme.test.tsx`：全部 token × 两套皮肤 × 三种底色 |
| U3 | 零件的五态正确 | 每个零件的**五态矩阵**快照（vitest + happy-dom；视觉快照用 Playwright） |
| U4 | kit 不硬编码颜色 | 断言 `kit.css` 里没有 `#rrggbb` 字面量（只有 `var(--cockpit-*)`） |
| U5 | 图标数量与描边一致 | 断言图标 ≤ 20 且 `stroke-width` 统一 1.5 |
| U6 | 数字格式正确 | `Intl.NumberFormat` 的 locale 用例；小数点右对齐（`tabular-nums`） |

### 8.2 汇合后（core 轨）的判据

沿用 `docs/21` §10.1 的**十条隔离判据**（Playwright 自动化）+ M5b 的三尺寸截图走查。

### 8.3 两轨都要做的

**每次改完都跑**：`npm run typecheck` · `npm run lint` · `npm test`。
**UI 轨额外跑**：`npm run gen:theme:check` · 对拍测试。

## 九、一句话版

> **core 轨做「板子怎么说话」，UI 轨做「人怎么读这句话」，两条轨在 `src/shared/` 那一层握手。**
> UI 轨现在就能做完 **9 件事**（全是纯新增文件）；
> **9 件事不要先做**（每一条都写清了什么时候解锁）；
> **文件所有权表**保证两边不打架；
> **唯一真正的硬阻塞**是：别名层的名字与卡片 API 的形状——
> 前者已在本轮拍板（进契约，与 ADR-D28 同批），后者已在计划 4 的 Interfaces 块里写死 ✓
