## 一、这个产品是什么

**DevBoardCockpit 是开发板驾驶舱**：一台电脑上打开它，能看到板子此刻的真实状态，
并且能对它做受控的写入。

**用户是整天开着它的嵌入式工程师**。他们熟悉的东西是：串口终端、编译器的构建面板、
示波器、逻辑分析仪、车机 HMI。**不是** SaaS 后台。

所以三条落点：

1. **驾驶舱而非遥控器**——控件旁边永远是板子的**真实值**；写操作的结果用**回读值**渲染；
   回读失败要显式显示「命令已发出，未确认生效」，**绝不乐观更新**。
2. **AI 是组态工程师**——核心旅程是「让 AI 写一张卡 → 它出现在工作台 → 人一眼看懂并信任它」。
   卡片库、校验报告、诊断日志、造卡入口**比装饰重要**。
3. **信任边界可见**——宿主 chrome 与卡片内容视觉上是一个整体，信任上是两层：
   **chrome 永远由宿主画，卡片只能画内容区**。

## 二、卡片的三层身份

| 层 | 事实 | 对 UI 的硬含义 |
|---|---|---|
| **文件层** | 卡片 = 一个目录（`manifest.json` + `index.html` + 资源）；AI 写完即生效、热插拔、无需构建（ADR-D4/D14） | 「生成 / 发现 / 校验 / 热更新」必须是一等公民的**界面流程**，不是设置里的小功能 |
| **沙箱层** | 卡片跑在独立 iframe；无同源、无网络（宿主注入 CSP）、无宿主 DOM；存储只能走 `cockpit.storage.*`；能力只有 `cockpit.*` 白名单（`spec/03` §六/§七） | 卡片内容是**不可信内容**；宿主 chrome（标题、连接、权限、状态）必须由宿主渲染，**不能让卡片伪造** |
| **能力层** | 读 tag 受 `permissions.read` 过滤；写动作有 danger 分级、授权、参数域、**执行后回读**、审计（`spec/03` §3.2/§5.3） | UI 必须能表达「新鲜 / 过期 / 未知 / 错误 / 未验证」，**不能只画漂亮图表** |

**UI 要回答的六个问题**：① 板子现在怎么样？② 这张卡在说什么？③ 这张卡可不可信？
④ 我能对它做什么？⑤ 写操作到底生效了吗？⑥ AI 写的下一张卡从哪来、去了哪？

## 三、设计方向：**车机质感 ≠ 玻璃堆叠**

**这是本设计的视觉总纲**，也是它与「通用深色后台」的分水岭。

**不做的**：玻璃拟态 + 大范围弥散阴影。那种做法容易显得**脏**和**糊**。

**做的**（五条，按优先级）：

| # | 原则 | 落地 |
|---|---|---|
| **1** | **清晰 1px 边界** | 卡片与画布靠**描边**区分，不是靠一层又一层投影 |
| **2** | **顶部白色高光** | `inset 0 1px 0 rgba(255,255,255,.065)` 给表面一条极细的「受光边」，立刻有材质感 |
| **3** | **亮度阶梯** | 画布（最暗）→ 卡片表面（+1 级）→ 卡内控件（+2 级）。**用表面亮度表达层级，不用阴影** |
| **4** | **颜色区分容器与内容** | 卡片容器保持中性；状态 / 波形 / 控件才用颜色；**强调色仍然唯一（蓝）** |
| **5** | **极轻环境光** | 画布上一团很淡的径向渐变即可，**不做大面积模糊背景** |

**卡片材质（暗色）**：

```css
background: linear-gradient(178deg, #21262e 0%, #1a1f26 46%, #171c22 100%);
border: 1px solid rgba(255, 255, 255, .095);
box-shadow: inset 0 1px 0 rgba(255, 255, 255, .065),
            0 1px 2px rgba(0, 0, 0, .30);
border-radius: 14px;
```

浅色主题**同一套结构**，只换 token（白面 + `#DEE0E3` 描边 + `#FFFFFF` 顶部高光 + 更浅的投影）。

**选中态是这套语言里最重要的交互信号**：`1px` 信号蓝描边 + 外发光 + 四角 8×8 缩放柄，
与「未选中只差一个亮度等级」区分开——**避免整屏都在喊**。

| 区 | 宽 | 职责 |
|---|---|---|

| **左侧 rail** | 58px | 工作台 / 卡片库 / 终端 / 文件 / 日志 / 设置；hover 出文字，键盘可达 |

| **右侧检查器** | 344px SideSheet | 概览 / 数据 / 权限 / 活动 / 回读历史 / 依赖——回答「这张卡凭什么读、改了什么、验证没有」 |
| **底部 dock** | 可折叠 | **终端 / 文件传输 / 运行日志** 三页签 + 传输队列 / 待确认动作 / 回读结果 |

### 4.1 三个关键结构决定

| # | 决定 | 为什么 |
|---|---|---|
| **1** | **终端 / 文件 / 日志是「工具面」，收进底部 dock，**不占卡片槽** | 它们是**工具**，不是**仪表**。混进卡片栅格 → 板卡状态卡与工具抢同一层注意力。dock 可折叠 / 拉高，但不参与栅格 |
| **2** | **卡片是栅格里的唯一一等公民** | 显示卡 / 控制卡 / 容器卡同一套 12 列网格、同一套卡壳。工具面不参与 → 「卡」的语义干净 |
| **3** | **视图 = 保存的配置** | 切换视图**不重载卡片、不重订数据**；只改哪些槽位可见、筛选与密度 |

### 4.2 页面清单

| 页面 | 内容 | 期次 |

| **总览**（默认） | 视图栏 + 工具条 + 卡片栅格 + 检查器 | M5b |

## 五、视图模型

```ts
// 建议形状（示意，不是契约；落盘由 main 负责）
interface LayoutFile {
  version: 1;
  views: Array<{
    id: string;            // "overview" | "monitor" | "debug" | "demo" | uuid
    name: string;
    slots: Array<{
      id: string;
      kind: 'builtin' | 'user';
      cardId?: string;        // kind === 'user'
      builtin?: 'target' | 'terminal' | 'files' | 'logs' | 'audit';
      connectionId: string;
      x: number; y: number; w: number; h: number;
      config?: { density?: 'comfortable' | 'compact'; hidden?: boolean };
    }>;
    filter?: { status?: Array<'live' | 'stale' | 'error' | 'unavailable' | 'degraded'> };
    density?: 'comfortable' | 'compact';
  }>;
}
```

**内置预设**（M5b 只读，不允许用户新建）：`总览`、`监控`、`调试`、`演示`。
「新建 / 编辑视图」留 M6 编辑态；M5b 只把数据结构和预设落地——**成本很低，但把扩展点留出来**。

> **落盘归 main**（ADR-D2 / Q7）；UI 只读 `get_layout` / `set_layout`。
> **布局不是契约**，但**落盘格式是 main 的**。

## 六、栅格与 Slot

- **12 列栅格**，行高 **60px**，间距 **12px**，页面边距 **20px**
- 断点：≥1600 → 12 列；1200–1600 → 12 列（卡片按列宽自适应）；900–1200 → 8 列；<900 → 4 列
- **Slot 模型**（呼应 `docs/21` §4.6）：

```
Slot { id, kind: 'builtin' | 'user', cardId?, builtin?, connectionId, x, y, w, h, config? }
```

- `kind:'user'` → sandbox iframe（`cockpit://`）；`kind:'builtin'` → 宿主 React 组件
- **外观统一 Card Shell，信任边界不同**
- 尺寸预设（与 manifest `layout.w/h` 对齐）：`S 3×3`（单指标）、`M 4×4`（多指标）、
  `L 6×5`（图表）、`XL 8×6`（终端 / 大图）
- **默认布局「总览」**：目标与链路(4×4) + CPU 半圈仪表(3×4) + 温度仪表(2×4) + GPU/NPU 双环(3×4)
  + 频率多线(6×4) + 内存/存储分段条幅(3×4) + 风扇控制(3×4) + CPU 调频(4×4)
  + 寄存器位组(4×4) + 最近事件(3×4)；**用户卡从第二屏开始**
- 拖拽：卡片抬起 1px、边框提亮、右下出现手握；落点用 8% 信号蓝虚线占位；resize 实时显示 `6×5` 尺寸 chip
- **焦点模式**：双击卡片标题或按 `F` 放大到主区，`Esc` 还原，**布局不丢**

## 七、视觉系统

### 7.1 双主题

**双主题从 M5b 就要做**，否则后拆会返工组件层（组件要支持两套皮肤）。
主题跟随系统（Electron `nativeTheme`），设置里可手动锁定；
卡片 iframe 通过宿主注入的 `__host/theme.css` 拿到当前 token，
所以 **AI 写的卡自动适配两套主题**。

> **v1 精做暗色**（2026-11-14 拍板）：两套皮肤的**架构**齐备（种子值两套都在、切换机制在），
> 但 v1 只把**暗色**做到可交付；浅色皮肤的**色值已实测达标**（§7.3），组件层的双皮肤支持随 M5b 交付。

### 7.2 token 的三层架构

**换皮不应该改代码，用户换皮更不应该改代码。** 模型取自 Ant Design 的 Seed / Map / Alias 三层推导。

```
① 种子层  seed.ts      手挑的值（两套皮肤各一份）
      ↓  （纯函数映射）
② 映射层  map.ts       角色：bg / srf-1 / srf-2 / hairline / text-0..2 / accent / ok / warn / danger / unknown / chart-1..6
      ↓  （查表）
③ 别名层  alias.css    --cockpit-*：宿主与卡片共用的语义名（**契约面**）
```

**为什么映射必须是纯函数**：因为它要**同时**产出四样东西，而它们**必须永远一致**：

```
映射(seed) ──┬─→ 应用自己的 CSS 变量
             ├─→ 卡片注入的 <style>（__host/theme.css）
             ├─→ ECharts 主题 JSON（给卡片）
             └─→ xterm 的 theme 对象（终端）
```

**四处各自维护一份 = 迟早对不上**（终端和卡片颜色不一样，是这类产品最常见的破相）。
**一处映射，四处产出 = 换一次皮肤，全应用连着换。**

> **实现上不手抄**：映射函数放 `src/shared/theme/`（main 与 renderer 共用），
> CSS 由**生成脚本**产出（与仓库已有的 `gen:vocabulary` 同一套路，见 `03-UI代码位置.md`）。

**相邻不撞**（绿与橙不相邻——红绿色盲下最难分）。

### 7.4 状态语义（七态 · 圆点 + 文字 + 形状 **三重编码**）

| 状态 | 颜色 | 形状 | 数值 | 文案 |
|---|---|---|---|---|
| `live` | 绿 | 实心圆 ● | 显示 | — |
| `stale` | 琥珀 | 半实心 ◐ | **显示（旧值）+ 降饱和** | 「已过时 · 最后 00:12:03」 |
| `pending` | 中性 | 空心 ◌（脉冲） | **不显示** | 「等待首个采样」 |
| `unavailable` | 灰 | **斜杠 ⊘** | **不显示**（**绝不显示 0**） | 「板型包未提供该 tag」 |
| `error` | 红 | 叉 ✕ | 有旧值才显示 + 条纹底 | 「读取失败：串口超时」 |
| `degraded` | 琥珀 | —— | —— | footer：「缺少 2 个 tag · 查看」 |
| `broken` | 红 | 整卡遮罩 | —— | 「卡片已隔离」+ 错误摘要 |

**为什么 `stale` 是琥珀而不是灰**：契约 §2.1 说 stale 是「有值，但上次刷新失败，值可能过时」——
**需要知道但不紧急**，正好是琥珀。灰色在本产品里已经被 `unavailable` 占了。

**为什么 `unavailable` 是斜杠**：它**不是故障**——板子好好的，是这个能力不存在
（`not_found`）或环境没就绪（debugfs 没挂）。用红会吓到用户，用琥珀会暗示「有点问题」。
**斜杠是航空仪表「此仪表不可用」的惯用符号：冷静地划掉，不报警。**

**三重编码是硬要求**：颜色不能是区分状态的唯一手段（约 8% 的男性有色觉辨识困难）；
**形状通道**（实心/半实/空心/斜杠/叉）与颜色完全独立。

### 7.5 数字与排版

| 角色 | 字型 | 字号 / 行高 | 用在哪 |
|---|---|---|---|
| 正文 | `Segoe UI Variable / Segoe UI / system-ui` | 13 / 19 | 说明、错误、空状态 |
| 标签 | 同上 · 600 · 0.06em | 11 / 14 | 面板标题、单位、组名（**丝印感**） |
| **读数** | `Cascadia Mono / Consolas` + `tabular-nums` | 40–56 仪表值 / 20 次级 | **读数数字** |
| 等宽 | `Cascadia Mono / JetBrains Mono / monospace` | 12.5 / 18 · 表格 11.5 | 终端、日志、路径、**tag 名** |

> **字型一律用系统自带的**：这个工具的卖点是「插上板子就能用」——
> **走 CDN 或打包几百 KB 的 webfont 都违背离线属性**。
> 需要「设计感」时用**系统自带的那一款**（Windows 自带 Bahnschrift = DIN 1451，做丝印标签）。

**数字的四条硬规则**（每条都对应一个真实的坏体验）：

1. **等宽表格数字**——每刷新一次就跳位，是最难受的一种噪音。
2. **右对齐**——小数点成列，量级一眼可比。
3. **单位降一级**——`37.2`（40px）+ `%`（13px，`text-dim`）。不写成 `37.2 percent` 混排。
4. **精度按量级定**——百分比 1 位；Hz 取整到 MHz；字节取 MB 整数。
   **不补零**：`0` 就写 `0`。**「读不到」写「不可用」，不写 `0.00`**（契约 §2.1.1）。

### 7.6 图标与插画

16px inline SVG，统一 **1.5px 描边、圆角端点**；**不用 emoji**；
空状态用线性小插画（内置 SVG，离线可用）。
**所有视觉资源必须走协议同源，禁 CDN**（CSP `connect-src 'none'` 与 `script-src 'self'` 决定）。

图标**总共不超过 20 个** → **全部手绘，不引图标库**。

## 八、卡片壳与内容沙箱

### 8.1 结构（**chrome 归宿主**）

```
┌ 44px 宿主 chrome ──────────────────────────────┐
│ 图标  标题        sub(canonical id)   [状态chip] [控制chip] [⋯] │
├────────────────────────────────────────────────┤
│ iframe 内容（卡片自己的 HTML/CSS/JS）           │
│   · 仪表 / 环 / 条幅 / 波形 / 表格 / 控件        │
├ 22px footer ───────────────────────────────────┤
│ 状态 · 采样 2s · 回读 ✓ · 审计 · 更新时间        │
└────────────────────────────────────────────────┘
```

- **卡片不能画自己的标题栏 / 权限标**——防止伪造；宿主 chrome 让所有卡（含 AI 生成）**天生一致**。
- 卡片体背景透明；Card Shell 提供统一下限高度、padding、hover/selected 光晕；**滚动在卡片内部**。
- 卡片菜单：重新加载 / 查看日志 / 在资源管理器中显示 / 复制诊断信息 / 放大 / 移除（卸载保留存储）。

### 8.2 生命周期交互

- **热更新**：文件变化 → 校验 → 通过则 iframe 淡入替换（180ms），**布局不动**，
  toast「已更新 · v0.3.2」；校验失败**保留上一版**并标「无效」。
- **崩溃 / CSP 违规**：整卡遮罩「卡片已隔离」+ 错误摘要，**不影响其他卡**；
  违规详情进检查器「活动」段。
- **骨架屏**：按 manifest 的 w/h 出对应比例的骨架，**不做全屏 spinner**。

## 九、卡片类型学（**这一版的核心增量**）

**卡片不能只有折线图。** 三类卡：

### 9.1 显示卡：不是只有折线图

| 形态 | 用在哪 | 交互 / 说明 |
|---|---|---|
| **半圈仪表** | CPU 使用率、SoC 温度、单值阈值类 | 弧形分区（正常/警告/危险）、指针、min/p95/max；一眼判断「是否越线」 |
| **双环** | GPU / NPU 利用率并排 | 环心显示数值；环下小字频率 / 回读状态 |
| **分段条幅** | 内存、存储、Swap | **10 段式**而不是细进度条；**缺数据段留灰，不用 0 填充** |
| **柱状幅值** | 中断分布、TOP-N 频次 | 柱高即数值，底部标 min/last/max |
| **双向镜像频谱** | 中断 / IO 双向速率 | 上正下负，30s 窗口；适合「有没有突发」的扫视 |
| **多线曲线** | 频率 / 负载、多 tag 对比 | **三条线以内**、图例即开关；阈值虚线标注 |
| **统计行 + 表格** | TOP 进程、峰值 / 阈值、回读历史 | 数据密集但安静；表格只用 1px 分隔线 |

每张卡都保留「**状态 chip + 采样周期 + 读到的最后时间**」——
驾驶舱的底线是**你看到的是板子的真实状态**，不是乐观动画。

### 9.2 控制卡：写动作必须有回读和审计

| 控件 | 示例 | 规则 |
|---|---|---|
| **开关 Toggle** | 风扇自动模式、GPIO 输出 | 开关旁显示当前值；危险动作走确认 |
| **滑块 Slider** | PWM 127/255、频率上限 | 滑块气泡显示目标值；右侧显示范围；底部「写入 → 回读 → 审计」 |
| **分段 Segmented** | governor（powersave/ondemand/performance） | 选中即目标态；应用按钮**显式提交** |
| **寄存器位组** | GPIO1_IO 8 bit | 位开关 + `0x` 十六进制 + 「写入 0x3C / 回读」+ 最近写入 |
| **动作按钮** | 全部拉高 / 拉低、总线扫描 | 批量动作给 guard 提示；执行后回读实际值 |

**控制卡统一的「安全三件套」**：

| 件 | 位置 | 内容 |
|---|---|---|
| **guard 范围** | 卡头 chip | 「16–255」「0–7」——用户批准的是**范围**，不是动作名 |
| **回读状态** | footer | `回读 ✓` / `回读未确认`——**永远不说「已生效」除非回读确认** |
| **审计** | footer + 检查器「回读历史」 | 最近写入行 + 可点开的审计 id |

**写失败 / 回读不一致时，卡片必须显示实际值，而不是成功动效**（`spec/03` §5.3）。

### 9.3 容器卡：把信息组织起来的卡

- **目标与链路**：板型 / 连接 / 传输 / 仲裁优先级 / 心跳——「我现在连着谁、链路活不活」
- **TOP 进程**、**峰值 / 阈值**、**最近事件**：不是状态值，而是「**正在发生什么**」
- 卡片库 / 检查器**不算卡片**，是管理面与详情面

点卡片右侧滑出（SideSheet），**不占栅格**。六段：

| 段 | 内容 |
|---|---|
| **概览** | 名称 / 版本 / 状态 / 权限 / tags 数 / 缺失数 / 来源 |

┌ 卡片库 ─────────────────────────────────────────────────────────────────────┐

### 11.2 发现 / 校验 / 授权三个流程

1. **发现**：卡片目录出现新卡 → 右下 toast「发现新卡片：CPU 曲线 · 校验通过」→「放置到工作台」；
   不过 → 「发现 2 个问题」→ 打开报告。
2. **校验报告**：`ok / errors[] / warnings[]` 三区分开展示；
   **未验证**（连不上板、动作未核实）用**琥珀而非红色**——**未验证 ≠ 不合法**。
   ⚠️ 返回形状照契约 `spec/04` §2.3（`{ ok, errors, warnings, resolved }`），**不另造字段名**。
3. **授权（M6，读卡不需要）**：卡片身份 + **人类语言**的能力清单——
   「读取：`cpu.*`、`mem.*`」「执行：`cpu.governor.set`（危险，范围 0–7，每次执行需确认）」；
   底部「取消 / 允许这些动作」；guard 范围可视化。

### 11.3 空状态与首启

- **没有连接**：显示检测到的目标列表 + 「连接」按钮，**而不是空白画布**。
- **没有用户卡**：内置「总览」卡先垫底 + 「AI 造卡」hero（三步说明、复制造卡 prompt、打开卡片目录）。
- **首次启动**：3 步清单（连接板子 → 绑定板型包 → 放置第一张卡），完成即消失。
- **首屏不是空的**（借鉴 Home Assistant：它的仪表盘「automatically generated from the devices you add」）：
  **按当前板型包声明的 tag 自动生成**指标块，**按语义重要度排序**（不按字母序），
  agent 写的卡片之后**替换 / 扩展**它。

## 十二、AI 造卡设计套件（**让好看成为默认值**）

**只给契约不够，AI 写出来的卡会「能用但丑」。** 方案：

1. 宿主在卡片源内注入 **`__host/theme.css`**（当前 token 值）、**`__host/kit.css`**（组件库）、
   **`__host/kit.js`**（小工具）；CSP `'self'` 正好允许这些同源资源。
2. **Kit 组件**：`ck-stat`（大数字 + delta）、`ck-sparkline`、`ck-chart`（封装宿主 ECharts 主题）、
   `ck-meter`、`ck-gauge`（半圈）、`ck-ring`（双环）、`ck-bar`（分段条幅）、`ck-spectrum`（双向频谱）、
   `ck-table`、`ck-row`、`ck-badge`、`ck-banner`、`ck-empty`、`ck-skeleton`；
   **全部吃 token，不硬编码颜色**。
3. **`kit.js` 小工具**：`fmt.unit/percent/bytes/duration`、`tags.use()`（自动订阅 / 清理 / 渲染五态）、
   `degraded()`（降级态渲染）。
4. **`card-template/` 四件套**（manifest + index.html + card.js + style.css，带注释），
   卡片库一键「从模板新建」。
5. **校验器加一条设计检查（warning 级）**：硬编码 `#rrggbb`、未使用 kit、
   没有空 / 错 / 降级三态 → **提示但不拦**。
6. MCP 侧 `get_card_sdk_docs` 把 kit 文档喂给 agent，形成
   「生成 → `validate_card` → 出现在库 → 人授权」的闭环；
   UI 对应一个安静的「AI 正在写卡…」胶囊。

> **kit 的关键性质**：`kit.css` **只写 `var(--cockpit-*)`，不写任何色值** →
> **一份 kit，任何皮肤**。皮肤由宿主注入的 `__host/theme.css` 决定。

## 十三、主题怎么实时下发（**机制修正**）

**计划 4 的 Task 11 原写「换主题时重载 iframe」——这是错的**：

1. **卡片会闪**（重载 = 白屏一帧 + 重新订阅 + 状态全丢）。
2. **技术上做不到「直接改」**：卡片在**不透明源**里（契约 §六不给 `allow-same-origin`），
   宿主**碰不到它的 DOM**——跨源，`contentDocument` 是 `null`。

**正确做法：走卡片自己的通道**（不需要新契约——「宿主 → 卡片」方向本来就有）：

```
宿主改主题
  → main 把新的别名值经卡片已有的私有端口推给那张卡
  → 卡片的 bridge 执行 document.documentElement.style.setProperty('--cockpit-text', v)
  → 卡片实时换肤，不重载、不闪、状态不丢
```

| 时机 | 机制 | 特点 |
|---|---|---|
| **首次打开卡片** | 协议 handler 在入口 HTML 注入 `__host/theme.css`（别名 + 基础样式） | **无闪烁**（第一帧就在） |
| **运行中换主题** | main → 私有端口 → `style.setProperty` | **实时，不重载** |
| **卡片自己覆盖局部变量** | 卡片 CSS 里的 `:root { --cockpit-accent: … }` | 层叠顺序保证它赢 |

## 十四、用户可定制

**「可自定义」的第一个落点：改几行 JSON 就换一张皮。**

```json
{
  "name": "深夜台",
  "seed": { "bg": "#08090C", "accent": "#7CC4FF", "ok": "#3FB950" }
}
```

| 规则 | 说明 |
|---|---|
| 文件位置 | `<userData>/theme.json` |
| 只写**种子**层 | 写映射 / 别名层会被**拒绝并报错**（用户改的是审美，不是实现） |
| 没写的种子 | 用内置值 |
| 文件损坏 / 字段不认识 | **报错并回落到内置暗色**，**不静默**（界面给一条提示） |
| 生效范围 | 应用 + 全部卡片（卡片跟着变，§十三） |
| 卡片可覆盖 | 卡片 CSS 里可以声明自己的局部变量（对应 HA 的「逐卡主题」） |

> **为什么只允许改种子**：允许改别名层，用户就能把「不可用」改成绿色——
> 而**颜色在这个产品里携带语义**（§7.4）。能改的是「整体气质」，不能改的是「含义」。

| **M8** | 多板 / 聚合 / promotion | 多板 tabs、聚合视图、布局分享 | 布局隔离与迁移测试 |

**并行的部分与不能先做的部分**：见 `02-UI并行设计档案.md`。

## 二十、待决问题

| # | 问题 | 建议 |
|---|---|---|
| Q1 | **dock 的默认形态**：常驻半高，还是默认收起只留页签条？快捷键 `Ctrl+\`` | 默认收起（收窄垂直空间），点标签展开 |
| Q2 | **写动作确认粒度**：所有控制卡的写都走确认 sheet，还是只有 destructive / 超 guard 走 | **只有 destructive / 超 guard 走**（其余直接执行 + 审计）——与契约 §3.2 一致 |
| Q3 | 视图编辑深度（M5b 只做拖放 + 缩放 + 保存，还是带「显示项 / 筛选 / 密度」） | M5b 只做拖放 + 缩放 + 保存；筛选与密度 M6 |
| Q4 | 卡片库：总览 / 监控是否共用「左详情列表 + 右画廊」，还是按新卡形态重做预览 | 共用画廊，但**预览用卡片的真实形态**（半圈表盘 / 条幅）而不是统一缩略图 |
| Q5 | **图表实现归属**：ECharts 与 SVG 仪表 / 条幅是否都进 `__host` kit，作为 AI 造卡的默认组件 | **都进**：SVG 形态（半圈 / 条幅 / 频谱）由 kit 提供，ECharts 只负责复杂曲线 |
| Q6 | **M5 / M5b 分期**：M5 只做宿主 + 沙箱 + CSP，还是先把「卡壳 + token」作为 M5 的最小视觉外壳 | **卡壳 + token 放 M5**（否则 M5 的卡片没有宿主 chrome 可验） |
| Q7 | 密度与最小尺寸：是否在 `layout{w,h,min_w,min_h}` 之外增加「紧凑 / 舒适」两档 | 加**显示层**的密度（不写进 manifest）——manifest 只描述尺寸 |
| Q8 | 双主题优先级：浅色与深色同时进 M5b，还是先上一套 | **暗色先上**（v1 精做），浅色架构齐备、M6 补 |
| Q9 | **别名层的 15 个 token 进不进契约** | **进**（§七 的第 7 条） |
| Q10 | `theme.json` 的种子名怎么暴露给用户 | 设置页列出**可改的种子**（不是全部别名）；其余由推导得出 |
