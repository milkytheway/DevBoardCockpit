## 二、当前取哪条

**2026-11-14 用户拍板：取 A（车机质感，DSH v2）。**

**理由**（按重要性）：

1. **它是唯一一条把「卡片类型学」做出来的**——半圈仪表、双环、分段条幅、柱状幅值、
   双向镜像频谱、多线曲线、统计表；控制卡还有开关 / 滑块 / 分段 / 寄存器位组 / 动作按钮。
   **这个产品的卖点是「看板子的读数」，而读数的主要形态不是折线图。**
2. **「好看」是它做到的**，不是它承诺的。
3. 它的 **dock 决定**（终端 / 文件 / 日志收进工具面、不占卡片槽）**比 v0.2 的
   「终端作为内置卡进栅格」更对**——工具与仪表不该抢同一层注意力。
4. 它的**车机质感判据**（§三）是可执行的，不是形容词。

### B 与 C 的东西没有被丢掉

| 来源 | 被吸收的部分 | 去哪 |
|---|---|---|
| **B（Codex v2）** | 状态语义表达到位；**数据可扫读**的表格密度（读数明细表用它的 34px 行高） | 总纲 §7.4 / §十一 |
| **B** | AI 造卡入口**显性**（卡片库顶部的输入框，不藏在设置里） | 总纲 §十二 |
| **C（Codex v1）** | **五态双编码 + failure flag 的方法论**（形状通道） | 总纲 §7.4 / §八 |
| **C** | 对比度**实测方法**（把不合格的色值揪出来） | 总纲 §7.3 的 ⬆ 标记 |

## 三、A 的材质判据（**不是形容词，是四条可执行的规则**）

| # | 规则 | 落地 |
|---|---|---|
| 1 | **清晰 1px 边界** | 卡片与画布靠描边区分，**不靠一层又一层投影** |
| 2 | **顶部白色高光** | `inset 0 1px 0 rgba(255,255,255,.065)` 给表面一条极细的「受光边」 |
| 3 | **亮度阶梯** | 画布 → 卡片面 → 卡内控件，**用表面亮度表达层级，不用阴影** |
| 4 | **颜色区分容器与内容** | 卡片容器中性；状态 / 波形 / 控件才用颜色；**强调色唯一（蓝）** |
| 5 | **极轻环境光** | 画布上一团很淡的径向渐变，**不做大面积模糊背景** |

**为什么不用玻璃拟态**：那种做法容易显得**脏**和**糊**。

## 四、还没定的（**视觉相关的**）

| # | 问题 | 现状 | 建议 |
|---|---|---|---|
| 1 | **双主题优先级** | 浅色主题的**色值已实测达标**，但 v1 只精做暗色 | **暗色先上**（v1 精做），浅色架构齐备、M6 补 |
| 2 | **浅色下的车机质感** | A 的材质参数是为暗色写的（顶部高光、渐变） | 浅色**同一套结构只换 token**（白面 + `#DEE0E3` 描边 + `#FFFFFF` 高光 + 更浅投影）——**不要另设计一套浅色** |
| 3 | **密度两档**（紧凑 / 舒适） | 未定 | 加**显示层**的密度，**不写进 manifest**（manifest 只描述尺寸） |
| 4 | **浅色是否还叫「车机质感」** | —— | 名不重要；但**结构必须同一套**——两套结构 = 两份组件 |
