## ⚠️ **三条最容易做错的地方**（**先看这个** ✓）

### ① **等待态是这块界面最难的地方** ⚠️

→ **一次调用跑完全程** ✓（**几十秒** ✓）→ **宿主不给进度** ✓
→ 所以界面必须能「等着」✓ —— **但不能只是一根转圈** ✗

**要做的**：
- **说得出「正在做什么」** ✓（**「建立第一个真相」** / **「试 13 个元操作」** / **「生成包」** ✓）
- **不许编百分比** ✗ —— 宿主不给 ✓ → **只说能说准的** ✓
- **跑着的时候按钮要禁用** ✓（否则用户重复提交 ✓）

**为什么这是最难的**：用户看到的是「三个字段 → 几十秒的等待 → 一次说人话的结果」✓
→ **中间那几十秒如果只是一根转圈** ✗ → **他不知道板子连上没有** ✗ → **他以为卡死了** ✗
→ **「正在做什么」这行字，比任何装饰都值钱** ✓。

### ② **失败态要把「板子没说话」和「连不上」分开** ⚠️

→ **它们是不同的故障** ✓ → **修法完全不同** ✓ → **文案上不许混** ✓
→ ⚠️ **「板子没说话」那屏不许出现「连接失败」四个字** ✗

| `kind` | 界面要说什么 | 要给什么提示 |
|---|---|---|
| `ok` | 「这块板现在有自己的包了」✓ | ⚠️ **一定要说「这是自动探出来的初版包 —— 说得准的是事实，说不准的是命名与语义（哪个温区是 SoC）」** ✓ |
| `port-unopenable` | 「**串口打不开**」✓ | ⚠️ **最常见的不是口错，是「有别的程序正独占着那个口」** ✓ → **这条必须说** ✓ |
| `no-reply` | 「**板子没说话**」✓ | 波特率不对 ✓ · 不是调试口 ✓ · 回包被吃了 ✓ |
| `connection-dead` | 「**那条连接一次都没通**」✓ | ⚠️ **这不是那些元操作的问题** ✓ → **先把连接查对，再查元操作** ✓ |

### ③ **成功的画面要克制** ⚠️

→ **主视觉是「成了」** ✓ → 下面一行「N 个可用 · M 个不可用」✓ → 再下面**包在哪** ✓（可复制 ✓）
→ ⚠️ **别做成一个大表格列出 13 个元操作** ✗ —— **那是「运行日志」页该干的** ✓（**别重复** ✓）
→ **那 13 个里哪几个不可用** → **折叠起来 / 一句话概括** ✓ → 想看细节的人点开 ✓。

## 接口（**是真的** ✓）

```ts
wizardRun(input: {
  port: string;                       // 串口号（手动选 ✓）
  baudrate: number;                   // 波特率（不试 ✓）
  boardName: string;                  // 板子名（**中文要能用** ✓）
  transport?: 'serial' | 'adb';       // 缺省 = 串口 ✓
}): Promise<{
  ok: boolean;
  kind: 'ok' | 'port-unopenable' | 'no-reply' | 'connection-dead';
  message: string;        // 一句话（**说人话** ✓）
  hints: string[];        // 下一步查什么（**逐条列出来** ✓）
  greenCount: number;
  redCount: number;
  installedDir?: string;
  boardId?: string;
}>;
```

**⚠️ 三条**：
1. **只给宿主** ✓ —— **卡片与 agent 都拿不到** ✓
2. **不返回进度** ⚠️ → **界面必须能等** ✓
3. **失败时 `ok: false` 但 `message` 仍然有话** ✓ → **别只看 `ok`** ✓

## 界面要求（**摘要** ✓ · 完整版看规格书）

| # | 要求 |

| 6 | **等待态**见上面 ① ✓ |
| 7 | **失败态**见上面 ② ✓ —— `hints` 要**逐条列** ✓，每条是**可执行的动作** ✓ |
