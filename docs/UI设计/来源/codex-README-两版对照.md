## 二、两份提案的对照

| | **DSH v2** | **Codex** |
|---|---|---|
| **材质** | 车机质感：深色渐变卡 + 顶部高光 + 14px 圆角 | 多维表格：浅色白卡 + 1px 描边 + 8px 圆角 |
| **主角** | **卡片画廊**（一屏 10 张卡，仪表为主） | **数据表**（卡片是容器，表格是主角） |
| **导航** | rail 58 + 视图标签栏 46 | 一级侧栏 72（图标）+ 二级侧栏 212 |
| **密度** | 高（60px 行高，12 列密集） | 中（34px 行高，可扫读） |
| **强项** | 卡片类型学丰富（半圈表盘 / 位幅值 / 寄存器组）、控制卡形态 | 状态语义表达到位、数据可扫读、AI 造卡入口显性 |
| **弱项** | 一屏信息量大，**初次使用者找不到入口** | 表现力弱，**做不出漂亮仪表** |

### 我的建议

**以 Codex 版为骨架，把 DSH v2 的卡片类型学搬进卡片内容区。**

1. 宿主外壳（导航 / 数据 / 详情）**要的是可扫读与可扩展**，多维表格的形态更合适；
2. **「好看」应该发生在卡片里，而不是发生在外壳里** —— 卡片是 AI 生成的，外壳是产品定的；
   外壳越克制，AI 的卡片越有发挥空间；
3. DSH v2 的卡片类型学是**内容层**的东西，与外壳形态不冲突，可以直接吸收。

**要合并才完整的三处**（DSH v2 更强）：

- **卡片类型学** → 进 `__host` 组件 kit，成为 AI 造卡的默认件
- **控制卡的凭据链**（guard chip + 回读结果 + 审计）→ 与 M6 的执行器对齐
- **dock 形态**（终端 / 文件 / 日志收进底部 dock，不占卡片槽）→ 与 `docs/22` 的工具面收敛一致
