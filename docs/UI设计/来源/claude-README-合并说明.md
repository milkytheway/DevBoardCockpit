## 三稿是怎么合并的

2026-11-14 有三份**并行**产出的 UI 设计稿。用户拍板：**以 DSH 的 harness 设计为主线**。

| 来源稿 | 谁 | 贡献 | 去向 |
|---|---|---|---|
| `docs/22-UI设计方案-卡片工作台.md` | DeepSeek | **Deck / 石墨甲板**：一屏四区、视图模型、卡片壳 chrome 归宿主、kit 设计套件、卡片库、性能预算 | **主线**，整体采纳 |
| `docs/23-UI视觉系统-色板字体与组件规范.md` | Codex | **ECAM 状态语义**（五态双编码）、failure flag、**实测对比度**、Bahnschrift 字型 | 状态语言与对比度方法采纳；**色值按实测修正后合并** |
| `docs/24-UI设计-开发者工具版.md` | Claude | **token 三层架构**（种子→映射→别名）、**用户换皮**（`theme.json`）、**主题实时下发**（机制修正）、**可看原型** | 全部采纳，融进总纲 §8.2 §15 §16 与原型 |

### 合并时改掉的三处（都有理由）

| # | 改什么 | 理由 |
|---|---|---|
| 1 | **浅色语义色**：`--warn #FF7D00 → #A85A00`、`--ok #00B42A → #0A7A2E`、`--accent #3370FF → #1F5AE0` 等 | **实测不达 WCAG AA**：原值在白底上只有 2.37 / 2.57 / 3.96 : 1。尤其 `--warn` 是橙色——**白底上几乎读不出来**，而它承载「stale / 降级」这句话 |
| 2 | **字体一律用系统自带**（不引 Inter / JetBrains Mono 作为首选） | 这个工具的卖点是「插上板子就能用」——**打包几百 KB 或走 CDN 都违背离线属性**。需要设计感时用**系统自带的那一款**（Windows 自带 Bahnschrift = DIN 1451） |
| 3 | **换主题不重载 iframe**，改走**卡片私有端口实时下发** | 卡片在**不透明源**里，宿主**碰不到它的 DOM**（跨源）——「重载 iframe」技术上做不到，且会闪、丢状态 |

### 合并时**没有**采纳的

- `docs/24` 的 **VS Code 标签组外壳** → 让位给 DSH 的**一屏四区**（rail + 检查器 + 视图栏）
- `docs/24` 的 **24 列 / 40 行高栅格** → 用 DSH 的 **12 列 / 56 行高**
- `docs/23` 的 **航空/仪表外壳**（ECAM failure flag 的整套外壳语言）→ 数据语言采纳，外壳不采纳
- `docs/22` 的 **Inter / JetBrains Mono** → 见上（改用系统自带）
