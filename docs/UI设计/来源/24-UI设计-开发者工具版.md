### 三处分歧（都带理由，不带情绪）

| # | `docs/23` | 本文 | 我的理由 |
|---|---|---|---|
| **1** | 视觉气质 = **航空/仪表**（ECAM 语义色 + Bahnschrift 的 DIN 字型） | 视觉气质 = **现代开发者工具**（VS Code 工作台骨架 + Grafana 面板网格） | 用户 2026-11-14 拍的是「现代开发者工具」那一路。**数据语言**（五态的双编码、不可用不是一个数）我们一致；**外壳哲学**不同：仪表靠仿生，开发者工具靠**信息密度与可预期性**。两者都成立，**这一版选后者** |
| **2** | 强调色 = **青** `#3CC6D0`（理由：蓝色在航空语义里已有职务） | 强调色 = **蓝** `#4AA3DF`（理由：与 Grafana/VS Code 的交互蓝同族，用户一眼知道「这是可点的」） | 这一条随分歧 1 走。**但有一条底线两边一致**：强调色**不得**与语义色（绿/琥珀/红/灰）混淆——所以强调色与 `ok` 的色相必须能一眼分开 |
| **3** | 字型：正文 Segoe UI Variable + **Bahnschrift** 做仪表标签与数字 | 字型：正文 Segoe UI Variable + 数字 **Cascadia Mono（`tabular-nums`）** | Bahnschrift 是好字型，但它是**可变宽的**——仪表读数要**小数点成列**，可变宽做不到。用 Cascadia Mono + `tabular-nums` 能拿到同样的对齐，且它是 Windows Terminal 的字型（开发者语汇）。**标签字型**我同意 `docs/23`：仪表丝印的标签确实该用 DIN 味 |

> **分歧 3 的细节**：Cascadia Mono 在 Win11 是**可选字体**（不一定装）。
> → 字型栈要写成 `'Cascadia Mono', 'Cascadia Code', Consolas, 'Courier New', monospace`，
> 回退到 Consolas（Windows 一定有）✓；并用 `font-variant-numeric: tabular-nums` 保证回退字体也等宽。

## 二 · 设计方向：为什么是「现代开发者工具」

**用户 2026-11-14 拍板：视觉气质走「现代开发者工具」那一路。**
这一节说清楚它在本产品里**具体**是什么，以及它与 `docs/23` 的「仪表」路线差在哪。

> **一句话**：**一个把板子当仪器看、但长得像 IDE 的东西。**
> 数据那一层用仪表的纪律（状态双编码、不可用不是一个数、数值带年龄）；
> 外壳那一层用 IDE 的效率（活动栏、标签组、底部面板、零阴影、一个强调色）。

**外壳的三条纪律**（这三条让「开发者工具」不等于「随便一个深色后台」）：

| # | 纪律 | 落地 |
|---|---|---|
| **1** | **零阴影、零渐变、零圆角白卡** | 面板是**直角 + 1px 边框**；层级靠**底色明度差**（surface-0/1/2/3）；只有浮层（弹窗、下拉）有阴影 |
| **2** | **一个强调色，只用在「可交互」** | 选中、聚焦、链接、当前标签。**语义色（绿/琥珀/红/灰）只用于状态**——两者一眼能分开 |
| **3** | **数字等宽、不跳位、右对齐** | `font-variant-numeric: tabular-nums`；值刷新时**不许有动画**（§九） |

**与 `docs/23` 的仪表路线的差别，只在外壳**：

| | 仪表（docs/23） | 开发者工具（本文） |
|---|---|---|
| 布局 | 状态轨 + 常驻侧栏 + 模式切换 | 活动栏 + 标签组 + 底部面板 + 状态栏 |
| 强调色 | 青（仪表背光） | 蓝（IDE 的交互蓝） |
| 字型 | DIN 做标签与数字 | DIN 只做标签；数字用等宽 |
| 数据语言 | 五态双编码、不可用斜纹 | **同一套** ✓ |

## 三 · token 架构：种子 → 映射 → 别名

**这一节是「原生可拓展、可自定义」的落点。**
核心主张：**换皮不应该改代码，自定义不应该改代码，用户换皮更不应该改代码。**

### 3.1 三层（模型取自 Ant Design 的 Seed / Map / Alias）

```
① 种子层  --seed-*      手挑的值。全产品只有这一层是「审美」
      ↓  （纯函数映射）
② 映射层  --map-*       角色：bg / panel / raised / selected / fg / fg-muted …
      ↓  （查表）
③ 别名层  --cockpit-*    组件与卡片用的语义名。**契约冻结的 15 个名字一个不改**
```

**为什么映射必须是纯函数**：因为它要**同时**产出四样东西，
而这四样东西**必须永远一致**：

```
映射(seed) ──┬─→ 应用自己的 CSS 变量（tokens.css）
             ├─→ 卡片注入的 <style>（协议 handler）
             ├─→ ECharts 主题 JSON（给卡片）
             └─→ xterm 的 theme 对象（终端）
```

**四处各自维护一份 = 迟早对不上**（终端和卡片颜色不一样，是这类产品最常见的破相）。
**一处映射，四处产出** = 换一次皮肤，全应用连着换 ✓。

### 3.2 种子层（暗色 · v1 精做）

**实测对比度**（WCAG 2.1；底色取面板底 `--cockpit-surface`）：

| `--seed-surface-1` | `#141920` | — | 面板底 |
| `--seed-surface-2` | `#1b222b` | — | 抬升面（抬头、输入框、悬浮） |
| `--seed-surface-3` | `#232c37` | — | 选中面 |
| `--seed-text-0` | `#d8e0ea` | **13.26 : 1** | ✅ AAA |
| `--seed-text-1` | `#93a1b3` | **6.72 : 1** | ✅ AA |
| `--seed-text-2` | `#828d9e` | **5.26 : 1** | ✅ AA |
| `--seed-accent` | `#4aa3df` | **6.38 : 1** | ✅ AA |
| `--seed-ok` | `#5cc98a` | **8.55 : 1** | ✅ AAA |
| `--seed-warn` | `#e3b341` | **9.07 : 1** | ✅ AAA |
| `--seed-danger` | `#f26d6d` | **6.04 : 1** | ✅ AA |

### 3.4 别名层（`--cockpit-*`，卡片拿到的就是这一层）

**这 15 个名字一个不改**（`docs/04` §6.5 已列）。
**⚠️ 但它们目前只在设计层**——实测 `spec/03` 里**一个字都没提**
（该文件搜不到 `CSS` / `变量` / `--cockpit`）。见本节末尾。

```
--cockpit-bg / --cockpit-bg-elevated / --cockpit-border
--cockpit-text / --cockpit-text-dim / --cockpit-text-faint
--cockpit-accent / --cockpit-accent-2
--cockpit-ok / --cockpit-warn / --cockpit-danger / --cockpit-unavailable
--cockpit-radius / --cockpit-font-mono / --cockpit-font-ui
```

**本文建议新增 9 个**（走「v1 定稿前的修正」口径，不升 `apiVersion`）：

```
--cockpit-surface          面板底（与 bg 区分）
--cockpit-surface-active   选中面
--cockpit-border-strong    面板边框 / 输入框（≥3:1）
--cockpit-font-label       仪表标签字型（Bahnschrift，Windows 自带）
--cockpit-grid             曲线网格线色
--cockpit-focus            焦点环
--cockpit-series-1..7      图表序列色
```

> **加 token 要不要改契约，取决于一件还没定的事**：
> 这 15 个名字现在**只在设计层**（`docs/04` §6.5），**契约里一个字都没有**。
> - 若保持「只在设计层」→ 加 token **不需要改契约**，但**卡片能依赖哪些变量就没有契约保证**；
> - 若要让卡片**可以放心依赖**→ 这 9 个别名（与现有的 15 个）**进契约 `spec/03` §六**，
>   走「v1 定稿前的修正」口径（不升 `apiVersion`）。
>
> **本文建议后者**：卡片是 AI 写的，**它需要一份「可以依赖什么」的清单**——
> 这正是契约该管的事。
> **种子层与映射层不进契约**（换皮不该动契约）。
>
> > 顺带一条实测更正：`docs/23` §九 写「契约 `spec/03` §6.5」——**该小节不存在**，
> > `spec/03` 只到 §六（§6.1 / §6.2）。两份稿子在这一点上都把设计层当成了契约层。

### 3.5 用户可定制：`<userData>/theme.json`

**「可自定义」的第一个落点：改 8 行 JSON 就换一张皮。**

```json
{
  "name": "深夜台",
  "seed": {
    "surface-0": "#08090c",
    "surface-1": "#0f1216",
    "accent": "#7cc4ff",
    "ok": "#6fd08c"
  }
}
```

| 规则 | 说明 |
|---|---|
| 只写**种子**层 | 写 `map` / `cockpit` 层会被**拒绝并报错**（用户改的是审美，不是实现） |
| 没写的种子 | 用内置值 |
| 文件损坏 / 字段不认识 | **报错并回落到内置暗色**，**不静默**（界面给一条提示） |
| 生效范围 | 应用 + 全部卡片（卡片跟着变，§八） |
| 卡片可覆盖 | 卡片 manifest 里可以声明自己的局部变量（对应 HA 的「逐卡主题」） |

> **为什么只允许改种子**：允许改别名层，用户就能把「不可用」改成绿色——
> 而**颜色在这个产品里携带语义**（§六）。所以能改的是「整体气质」，不能改的是「含义」。

## 四 · 排版与数字

| 角色 | 字型 | 字号 / 行高 | 用在哪 |
|---|---|---|---|
| 正文 | `'Segoe UI Variable Text', 'Segoe UI', system-ui` | 13 / 19 | 说明、错误、空状态 |
| 标签 | `'Bahnschrift', 'DIN Alternate', 'Segoe UI Variable'` 600 | 11 / 14 · **0.06em** | 面板标题、单位、组名（**丝印感**） |
| **读数** | `'Cascadia Mono', Consolas, monospace` **500** + `tabular-nums` | 34 / 36 · −0.02em | 指标块的主数值 |
| 次级读数 | 同上 | 13 / 18 | 表格里的数值 |
| 等宽 | `'Cascadia Mono', Consolas, monospace` | 12.5 / 18 | 终端、日志、路径、**tag 名** |

**数字的四条硬规则**（每条都对应一个真实的坏体验）：

1. **等宽表格数字**——每刷新一次就跳位，是最难受的一种噪音。
2. **右对齐**——小数点成列，量级一眼可比。
3. **单位降一级**——`37.2`（34px）+ `%`（13px，`text-dim`）。不写成 `37.2 percent` 混排。
4. **精度按量级定，不按「显得精确」定**——百分比 1 位；Hz 取整到 MHz；字节取 MB 整数。
   **不补零**：`0` 就写 `0`。**「读不到」写「不可用」，不写 `0.00`**（契约 §2.1.1）。

**跨平台**：字体栈必须完整降级；**布局不能依赖字体的具体宽度**——
数字位靠 `tabular-nums` 而不是定宽容器，标签靠固定 `letter-spacing` 而不是「填满一行」。

### 5.1 四条结构决定

| # | 决定 | 为什么 |
|---|---|---|
| **1** | **仪表盘 / 终端 / 文件 是标签，不是上下堆叠** | 现在是「读数面板在上、终端在中、文件在下」三层堆叠 → 纵向空间被切碎，谁都不够用。**「看板子的读数」是主线**，所以仪表盘是**第一个标签**，默认打开 |
| **2** | **不设常驻侧栏**（活动栏 48px 就够） | 侧栏会**永久吃掉 20% 的横向空间**，而终端要的是**行宽**——1200px 的窗口里，侧栏一占，终端只剩 ~70 列。连接只有 2–4 个，**标题栏的下拉足够**；连接多了，底部面板里有「连接」标签 |
| **3** | **底部面板常驻**（读数明细 / 卡片日志 / 会话日志） | VS Code 的 Problems 面板就是这个位置——**读数明细就是「问题清单」的同构物**（位号 → 状态 → 年龄）。它常驻，是因为**看板子的读数是这个产品的主线**，不该被终端挤掉 |
| **4** | **状态栏永远在最下面** | 无论在哪个标签，「板子连着没有、采样有没有在跑」一眼可见 |

### 5.2 仪表盘 = Slot 网格（与 `docs/21` §6.6 一致）

- `react-grid-layout`，**24 列**，行高 40px，间距 8px（4px 基数）
- **布局只认槽位，不认实现**：`Slot { id, kind: 'builtin'|'user', cardId?, connectionId?, layout:{x,y,w,h} }`
- `kind:'user'` → sandbox iframe（`cockpit://`）；`kind:'builtin'` → 宿主 React 组件（终端卡、连接卡）
- **内置卡与用户卡同权重**——它们都只是槽位

### 5.3 最小窗口与响应式

| 宽度 | 行为 |
|---|---|
| < 960px | 活动栏不变；网格降到 12 列；底部面板默认折叠 |
| 960–1440px | 24 列网格；侧边无 |
| > 1440px | 网格行高不变，**面板变宽不变高**（横向空间给曲线） |

**最小窗口 960×600**。低于这个，仪表盘一行放不下两个指标块。

## 六 · 读数的五种状态（数据语言）

**这一节与 `docs/23` §3.5 的结论一致**（状态色取 ECAM 谱系、双编码、不可用不是一个数），
实现上有一个差别：**本文给每个数值加「年龄」**。

### 6.1 五态 × 三通道

| 状态 | 颜色 | 形状 | 数值 | 文案 |
|---|---|---|---|---|
| `ok` | 绿 | 实心圆 | 显示 | — |
| `stale` | 琥珀 | 半实心 | **显示（旧值）** | 「已过时 · 14 秒前」 |
| `pending` | 中性 | 空心（缓慢呼吸） | **不显示** | 「等待第一次采样」 |
| `unavailable` | 灰 | **斜杠 ⊘** | **不显示** | 「不可用 · 缺 npu.usage」 |
| `error` | 红 | 叉 ✕ | 有旧值才显示 | 「读取失败（显示的是上一次的值）」 |

**三个通道缺一不可**：颜色（快看）、形状（色盲可读）、**文字**（读屏与截图可读）。

### 6.2 「年龄」：本文新增的一条

**每个数值都带它自己的年龄**，不只是全局一个心跳：

```
CPU 占用
37.2 %                 ← 值
2 秒前                 ← 年龄（这一次的采样距今多久）
```

| 规则 | 为什么 |
|---|---|
| 年龄是**这个值的**年龄，不是应用的 | 全局心跳只说「板子还活着」，年龄说「**这个数**有多旧」 |
| 超过 3 × poll 周期 → 年龄变琥珀，值变「已过时」 | 契约 §2.3 的 stale 判据是 **3 × 周期**——年龄在**越过那条线之前**就让人看见它 |
| `unavailable` / `pending` 没有年龄 | **没有值就没有年龄**。写「—」，不写「0 秒前」 |

### 6.3 序列色（图表）

| 序 | 暗色 | 亮色 |
|---|---|---|
| 1 | `#4aa3df` | `#0f6cbd` |
| 2 | `#e3b341` | `#8a5a00` |
| 3 | `#b18cf0` | `#6b3fa0` |
| 4 | `#4fc3c9` | `#006b70` |
| 5 | `#5cc98a` | `#0f7a4a` |
| 6 | `#f08fc0` | `#a13262` |
| 7 | `#f09a5a` | `#a34612` |

**三条规则**（前两条来自 Carbon 的分类色板方法）：

1. **按序号固定**——同一序列在所有图里同色，**不按名字分配**（名字会变，序号不会）。
2. **一图最多 6 条**（第 7 条是「其他」的中性色）。
3. **相邻不撞**：绿与橙不相邻（红绿色盲下最难分）。所以顺序是 蓝→琥珀→紫→青→绿→粉→橙。

**语义色与序列色可以重叠**（温度用琥珀是对的，它本来就是热的），
但**同一张图里 `ok` 绿只表示「正常区间」**，不表示「这条序列是绿的」。

## 七 · 卡片视觉契约（宿主注入什么）

**「卡片不得硬编码颜色，只用宿主注入的 CSS 变量」是契约 §六的要求。**
但**只给变量不够**——卡片作者仍然可能把 `unavailable` 画成一个灰色的 0。
所以宿主注入的不只是变量，还有**一套类**。

### 7.1 注入三样东西

| # | 注入什么 | 形式 | 为什么 |
|---|---|---|---|
| **1** | **全部别名变量** | 入口 HTML 里的 `<style>` | 首屏**无闪烁**（变量在第一帧就在） |
| **2** | **基础样式表**（状态类） | 同一个 `<style>` 里 | **让卡片不可能把状态画错** |
| **3** | **ECharts 主题 JSON** | `cockpit://card/<id>/__host/echarts-theme.json` | 卡片图表**自动随皮肤**（§3.1） |

### 7.2 基础样式表提供什么（这是**契约的一部分**，不是惯例）

```css
/* 宿主注入，卡片直接用 */
.cockpit-value                { font: 500 34px/1.05 var(--cockpit-font-mono);
                                font-variant-numeric: tabular-nums;
                                color: var(--cockpit-text); }
.cockpit-value--stale         { color: var(--cockpit-text-dim); }
.cockpit-value--error         { color: var(--cockpit-danger); }
.cockpit-unavailable           { /* 斜纹底 + 无数字 */ }
.cockpit-pending              { /* 骨架微光 */ }
.cockpit-note                 { color: var(--cockpit-text-faint); font-size: 11px; }
.cockpit-age                  { color: var(--cockpit-text-faint); }
```

**卡片作者要做的是选一个类名，不是画一个状态。**
想显示一个「不可用」的位号，用 `<span class="cockpit-unavailable"></span>` +
一行 `cockpit-note` 文案即可 —— **他不可能写错**。

### 7.3 卡片的本地覆盖（对应 HA 的「逐卡主题」）

卡片可以在自己的 CSS 里覆盖别名变量（**只能覆盖，别名名不改**）：

```css
:root { --cockpit-accent: #e3b341; }   /* 这张卡用琥珀做强调 */
```

宿主注入的 `<style>` 放在**卡片自己的样式表之前**，所以卡片的覆盖生效 ✓
（层叠顺序：宿主基础 → 卡片自有 → 卡片内联）。

## 八 · 主题的实时下发（**对计划 4 的一处机制修正**）

### 8.1 问题

计划 4 的 T11 写的是：「**换主题时重载 iframe**」。这是错的，两个理由：

1. **卡片会闪**（重载 = 白屏一帧 + 重新订阅 + 状态全丢）。
2. **技术上做不到「直接改」**：卡片在**不透明源**里（契约 §六不给 `allow-same-origin`），
   宿主**碰不到它的 DOM**——跨源，`contentDocument` 是 `null`。

### 8.2 正确做法：走卡片自己的通道

```
宿主改主题
  → main 把新的别名值经**卡片已有的私有端口**推给那张卡（计划 4 的 bridge 通道）
  → 卡片的 bridge 执行 document.documentElement.style.setProperty('--cockpit-text', v)
  → 卡片**实时换肤**，不重载、不闪、状态不丢
```

**这不需要新的契约**：计划 4 的卡片私有端口已经在那里了，
「宿主 → 卡片」是**已有**的方向（`cards:event`）。主题只是它推的又一种消息 ✓。

### 8.3 于是，主题的完整链路

| 时机 | 机制 | 特点 |
|---|---|---|
| **首次打开卡片** | 协议 handler 在入口 HTML 注入 `<style>`（别名 + 基础样式） | 无闪烁 |
| **运行中换主题** | main → 私有端口 → `style.setProperty` | **实时，不重载** |
| **卡片自己覆盖局部变量** | 卡片 CSS 里的 `:root { --cockpit-accent: … }` | 层叠顺序保证它赢 |

> **这一条要写进计划 4 的 T11**（现在写的是「注入主题 `<style>`」+「换主题时重载 iframe」）。
> 改动很小，但它是「可自定义」能不能实时生效的关键。

## 九 · 动效与可访问性

### 9.1 动效

| 场景 | 动效 | 时长 |
|---|---|---|
| **数据自己变** | **无** | — |
| 数值年龄跨过阈值 | 颜色淡入（不是跳动） | 120ms |
| `pending` 骨架 | 微光 | 1600ms 循环 |
| 面板展开/收起 | 高度 + 透明度 | 160ms |
| 拖拽吸附 | **边框闪一下**（不是阴影） | 100ms |
| 主题切换 | **无**（直接切） | — |

> **「数据自己变不配动画」是这一版最重要的一条**：
> 一个每 200ms 刷新一次的数字若带过渡动画，**整块仪表会一直在抖**——
> 这是最常见的「AI 生成的仪表盘」观感问题。仪表的数字就该**跳**
> （而且用等宽数字让它跳得不难看）。

**`prefers-reduced-motion: reduce`**：骨架停止微光，所有过渡降到 0ms。

### 9.2 可访问性

| 项 | 要求 |
|---|---|
| 对比度 | 正文 ≥ 4.5:1（§三·实测）；大字号 ≥ 3:1；**可聚焦控件边框 ≥ 3:1** |
| **不靠颜色单独传达信息** | 五态有形状通道（§六）；告警有图标 + 文案 |
| 焦点 | **2px accent + 1px offset**，**不用 `outline: none`** |
| 键盘 | 活动栏、标签组、底部面板全部可达；标签组支持 `Ctrl+Tab` / `Ctrl+W` |
| 读屏 | 状态灯带 `aria-label`（「正常」/「已过时」/「不可用：debugfs 未挂载」） |
| 缩放 | 200% 下不破版（用 grid + `minmax`，不用固定 px 宽） |
| 高对比度 | `@media (forced-colors: active)` 下用系统色，状态灯靠**形状** |
| 触摸目标 | ≥ 24×24 |

## 十 · 充分利用工具链特性

**这一节是「为什么要 Electron + React + 这套栈」的答案。**

| 特性 | 用在哪 | 换来什么 |
|---|---|---|
| **自定义协议 `cockpit://`** | 卡片资源托管 + **CSP 响应头注入** + **别名变量注入** + **ECharts 主题 JSON** | 卡片的「断网」与「统一皮肤」两条承诺**都由宿主强制**，卡片改不了 |
| **同一套映射函数产出四份** | 应用 CSS / 卡片 `<style>` / ECharts JSON / xterm theme | **一处换皮，四处齐换**；终端与卡片**永远同色** |
| **`titleBarStyle: 'hidden'` + `titleBarOverlay`** | 自绘标题栏，与状态栏连成一体 | Windows 上做出 IDE 那种一体化标题栏，省 30px 垂直空间 |
| **`nativeTheme`** | 跟随系统亮暗 | 不用自己监听 `prefers-color-scheme`（CSS 变量仍要自己定义两套） |
| **`console-message`（Electron 25+ 新签名）** | 抓 **CSP 违规** → 卡片运行时日志 | agent 能看到「这张卡试图联网」（契约 §6.1 承诺） |
| **`protocol.handle` 返回 `Response`** | 精确控制响应头 | CSP 是**响应头**，不是 `<meta>`（meta 管不了自己） |
| **React 18 `useSyncExternalStore`** | 订阅 `TagStore` | **无 tearing**——读数是高频外部源，`useState`+`useEffect` 在并发渲染下会读到不一致的快照 |
| **React 18 `startTransition`** | 切换标签组 | 切标签时**终端不闪**（重渲染被标记为可中断） |
| **`useDeferredValue`** | 读数明细的高频更新 | 筛选/滚动不被高频读数卡住 |
| **`Intl.NumberFormat`** | 数字格式化 | 按用户 locale 的小数点与千分位（欧洲用 `,`）；**不要手写 `toFixed(1)`** |
| **`font-variant-numeric: tabular-nums`** | 全部读数 | 不跳位 |
| **CSS `color-scheme`** | 滚动条、焦点环、表控件 | 不用为滚动条写伪元素 |
| **CSS `prefers-reduced-motion` / `forced-colors`** | 全部动效与高对比度 | 免费拿到可达性 |
| **CSS `text-wrap: balance/pretty`** | 告警条、错误消息 | 换行不产生孤儿词 |
| **`content-visibility: auto`** | 折叠的底部面板 | 不渲染看不见的内容 |
| **xterm.js 的 `ITheme`** | 终端主题 | 终端颜色**跟着 token 走**，不单独一套 |
| **ECharts 的 `registerTheme`** | 卡片内图表 | 宿主生成 JSON → 卡片注册 → 图表随皮肤 |
| **`react-grid-layout`** | 拖拽布局 | 已定（ADR-D3） |

## 十一 · 第一屏不该是空的（Home Assistant 的教训）

**Home Assistant 的做法**（实测引自官方文档）：

> "Home Assistant comes with a dashboard out of the box, **automatically generated from the devices you add**."

**我们的对应做法**：

> **首次接上一块板子，仪表盘不是空的——它按当前板型包声明的 tag 自动生成。**

| 规则 | 说明 |
|---|---|
| 生成依据 | 板型包的 `provides`（哪些 tag 这个板真的有） |
| 顺序 | **按语义重要度**（`core` 词表的前几项：CPU / 内存 / 温度），**不按字母序** |
| 形状 | 每个 tag 一块**指标块**（值 + 年龄 + 迷你趋势线） |
| 之后 | agent 写的卡片**替换/扩展**它，用户拖拽调整 |

**为什么这条重要**：这个产品的主线是「**看板子的读数**」。
一个空白的仪表盘 = 用户打开应用看到一片空白 = **产品看起来是坏的**。
自动生成让「插上板子 → 立刻有一屏东西看」成立 ✓。

> 这也回答了「卡片即文件」的一个空档：**第一屏不是卡，是宿主生成的**——
> 等 agent 写了卡，用户再一张张换掉它。
