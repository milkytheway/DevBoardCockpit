# 11 · 卡片内部设计规范

> **作者**：Codex　**日期**：2026-11-16　**状态**：规范（**可判**）
> **适用范围**：`cards/**`（卡片内部）—— **外壳由 DSH 定，本规范只约束卡片里面**
> **配套**：[`10-色彩使用规范.md`](10-色彩使用规范.md)（色彩纪律）
> **归属**：M5b 卡片框架的实现细节**由 DSH 判断是否调整**（用户已授权）；
> 本规范给的是**判据**，不是组件代码。

---

## 0. 结论先行

1. **一张卡 = 一个主张。** 能用一句话说清它在主张什么，说不清就拆卡。
2. **注意力是零和的。** N 张卡 × 每张 k 个视觉重心 = N·k 个竞争焦点。
   一屏 6 张卡要想都可读，**每张卡最多 1 个重心**。
   → **本规范的目标不是「让每张卡更漂亮」，是「让每张卡更弱」。**
3. **信息预算**：1 个主读数 + ≤ 2 个辅助读数 + 1 行状态 + **0 个自绘趋势图**。
4. **一张卡里不同的「数据形态」≤ 2。**
5. **颜色只表达状态**；**身份用文字**，不用颜色。
6. **常态不许发光**；越界时最多 1 处。
7. **趋势与历史明细归宿主详情面板**，卡片不重复画。
8. **状态必须用宿主注入的 `.cockpit-*` 类**——不许每张卡自己实现一套。

> 📐 **为什么卡片一多就乱（机制）**
>
> 卡片数量 ↑ → 每张卡能分到的「注意力预算」被摊薄 → 每张卡都必须**更用力**才能被看见
> → 整体更乱。**这是零和的**：注意力是共享资源。
>
> 所以「让每张卡更漂亮」是**错的方向**。正确方向是**把注意力集中到一个地方**，
> 让其余部分安静下来。

## 1. 现状体检（实测，不是印象）

### 1.1 五张内置卡的数据形态

「数据形态」= 卡里**视觉语言不同**的呈现方式。
形态混用是「卡片一多就乱」的直接来源——两套视觉语言放在一起，
大脑要切换两次，**两边都读不顺**。

| 卡片 | 形态清单 | 形态数 | 预算（≤2+1） | 判定 |
|---|---|:--:|:--:|:--:|
| **cpu-usage** | 半圆仪表 + meta-grid + sparkline + 核心柱 + note | **4 + 1** | 2+1 | ✗ **最严重** |
| **memory** | 大数字 + sparkline + 分段条 + 3 个 stat + note | **4 + 1** | 2+1 | ✗ |
| **gpu-npu** | 双环 + 4 个 fact + note | **3** | 2+1 | ✗ |
| **core-load** | 3 个 summary + 核心柱 + note | **3** | 2+1 | ✗ |
| **board-identity** | 型号头 + 2 个 cell + 2 条背光 + note | **3** | 2+1 | ✗ |
| **thermal** | hero 大数字 + 2 条 + note | **2 + 1** | 2+1 | ✓ |

### 1.2 色彩与装饰

| 项 | 实测 | 判定 |
|---|---|---|
| **身份色** | `gpu-npu`：GPU 环 `--cockpit-accent`（蓝）、NPU 环 `--cockpit-accent-2`（紫） | ✗ 颜色被用来区分**身份** |
| **常态发光** | `cpu-usage` 表盘弧 `drop-shadow` 常态发光；`gpu-npu` **两个环都发光** | ✗ 两张卡同屏 = 3 处常态发光 |
| **数据编码用渐变** | `core-load`/`cpu-usage` 的柱、`thermal` 的条、`board-identity` 的背光条，都是 `linear-gradient` 填充 | ✗ 渐变让「多长」读不准 |

| **卡片内硬编码色值** | **0** | ✓ 做得好 |
| **卡片用契约变量** | 全部只用 `--cockpit-*` | ✓ 做得好 |

## 3. 信息预算（可判）

```
┌─────────────────────────────────┐
│  [宿主画的标题栏 —— 卡片不许重复] │
├─────────────────────────────────┤
│                                 │
│         3 7 %                  │  ← 主读数（唯一的大字）
│         总占用                   │  ← 单位 / 副题
│                                 │
├─────────────────────────────────┤
│  A55  ▁▃▅▂▇▃  A76  ▂▅▁▃▂      │  ← 辅助（≤ 2 组，同量纲）
├─────────────────────────────────┤
│  采样 1s · 14:32:07              │  ← 状态行（1 行）
└─────────────────────────────────┘
```

| 槽位 | 上限 | 说明 |
|---|:--:|---|
| **主读数** | **1** | 唯一的大字（`.cockpit-value`）。**一张卡只能有一个视觉重心** |
| **辅助读数** | **≤ 2** | 必须与主读数**同量纲、同语义族**（都是 % 或都是 Hz） |
| **状态行** | **1** | `.cockpit-note`，放采样周期 / 时间戳 / 一句说明 |
| **自绘趋势图** | **0** | 归宿主详情面板（§4.3） |
| **重复宿主标题** | **0** | 宿主已经画了（`src/renderer/shell/cards.ts` 的 `name`） |

### 3.1 数据形态 ≤ 2

形态清单（**穷举**，卡片里出现的每种都算一种）：

| # | 形态 | 长相 |
|--:|---|---|
| F1 | **读数块** | 一个大字 + 单位 |
| F2 | **条形组** | 一排横条 / 竖条（每核、每通道） |
| F3 | **行组** | 若干「标签 – 值」行 |
| F4 | **仪表盘** | 圆弧 / 圆环 / 表针 |
| F5 | **迷你趋势** | sparkline / 折线 |
| F6 | **分段条** | 一根条切成几段（used/free） |

**一张卡里不同的形态 ≤ 2**（F1 + F2 是标准组合）。

> **为什么 ≤ 2 是硬数字**：形态每多一种，视觉语言就多一套，
> 大脑的切换成本就多一次。**≥ 3 种形态的卡，观众会先看「形状」再看「内容」。**

## 4. 七条硬规矩

### 4.1 颜色只表达状态，不表达身份

| 允许 | 禁止 |
|---|---|
| 同一张卡里所有读数用**同一个** `--cockpit-accent` | GPU 蓝 / NPU 紫这种**身份色** |
| 越界时用 `--cockpit-warn` / `--cockpit-danger` | 给某一路信号固定一个色相 |
| 身份用**文字标签**（`GPU` / `NPU`） | 用颜色当身份标签 |

> 一屏 6 张卡、每张 3 种色 = 18 种色相 → **没人能建立「蓝色 = 正常」这种直觉**。
> 状态色要**可学习**才有意义。

### 4.2 状态必须用宿主注入的类

宿主注入 `__host/theme.css`，卡片**只要选类名**就不可能画错状态：

| 类 | 什么时候用 | 长相 |
|---|---|---|
| `.cockpit-value` | 正常读数 | 等宽大字 |
| `.cockpit-value--stale` | 值还在但已过时 | 变暗 |
| `.cockpit-value--error` | 出错但还有旧值 | 变红 |
| `.cockpit-unavailable` | **这块板不提供这个能力** | 斜纹底 + **没有数字** |
| `.cockpit-pending` | 还在等第一次采样 | 骨架 |
| `.cockpit-degraded` | 降级 | 琥珀色 |
| `.cockpit-broken` | 坏了 | 红框 + 红字 |
| `.cockpit-label` / `.cockpit-note` / `.cockpit-age` / `.cockpit-unit` | 标签 / 注记 / 年龄 / 单位 | — |

**规矩**：

1. **不许自己写状态色**（不许 `color: #D29922` 表达「过时」）。
2. **不许把 `unavailable` 画成一个灰色的 0** —— 那是最不能出的错：
   「读不到」与「真的是 0」混淆，会让人以为板子坏了。
3. `.cockpit-unavailable` / `.cockpit-pending` **优先于**任何自绘图形：
   读不到的时候，**整块图形都应该消失**，只留那个占位符。

> 现状：**6 张卡里只有 1 张用了这些类**。
> 其余 5 张各自实现了一套「过时变暗 / 不可用画斜线 / 出错变红」——
> 行为**大体对，细节必然不一致**。统一到宿主类是**零成本的正确性**。

### 4.3 不重复宿主已有的能力

宿主已经有：

| 宿主已有的 | 卡片里就别再画 |
|---|---|
| **详情面板 →「采集」页签**（该卡声明的每个 tag 的最新值 / 状态 / 年龄 / 观测周期） | 卡片里的 meta-grid |
| **详情面板 →「原始读数」页签**（最新读数 JSON + 最近 30 条流水） | 卡片里的 **sparkline**、min/p95/max、历史统计 |
| **卡片标题栏**（宿主画） | 卡片内的标题 / 重复的卡片名 |

> **这是「卡片一多就乱」的最大单一来源。**
> cpu-usage 里的 sparkline(60s) + min/p95/max + 采样时间 + meta-grid，
> **全部**在宿主详情面板里已经有一份（而且是权威的那份）。
> 卡片重复画一遍 = 同一屏里同一个数字出现两次 = **读者要判断「这两个哪个是真的」**。

### 4.4 常态不许发光

| 允许 | 禁止 |
|---|---|
| 主读数在 **warn / danger** 时发一次光（且**只在那一刻**） | 常态 `drop-shadow` / 彩色 `box-shadow` |
| 交互反馈（hover / 拖拽 / 选中） | 数据图形常态发光 |

> 发光的含义是「**这里出事了**」。常态发光 = 「这里一直很亮」= **没有信息量**，
> 而且它会**掩盖**真正该发光的那一处。

### 4.5 渐变不许用来编码数据

| 允许 | 禁止 |
|---|---|
| 材质上的面高光（宿主的事） | 柱 / 条 / 弧的**填充**用 `linear-gradient` |
| — | 一根条从「实色」渐变到「半透明」——**看的人要重新校准长度感** |

> 数据编码要的是**可比较**：两根柱谁长，一眼就该看出来。
> 渐变把「长度」变成了「明暗」，就不可比了。

### 4.6 一次只用一个字重 / 一个字号层级

主读数用 `--cockpit-type-metric`（34px，宿主给），辅助用 `--cockpit-type-body`（13px），
标签用 `--cockpit-type-caption`（11px）。**不要在卡里另立字号阶梯**。

### 4.7 动效只回应操作

| 允许 | 禁止 |
|---|---|
| 数值变化的过渡（160–320ms） | 入场动画、逐个淡入、循环动画 |
| 骨架的 shimmer（宿主给的 `.cockpit-pending`） | 常态呼吸 / 呼吸灯 / 旋转 |

## 5. 何时拆卡

**判据（按顺序问）**：

1. 主读数能不能用**一句话**说清？→ 不能，**拆**。
2. 两件事的**量纲**一样吗？（都是 % / 都是 Hz / 都是温度）→ 不一样，**拆**。
3. 两件事的**状态**会同时变吗？（CPU 高 ≠ 内存高）→ 会同时变，**合**在一张卡（对比才有意义）。
4. 一张卡超过 **2 种形态** → **拆**。

**合的判据**（什么时候该合）：

> **两个量要一起看才有用 → 同一张卡；两个量各自独立 → 各自一张卡。**
>
> 例：CPU 总占用 + 每核分布（要一起看：总量高但只有 2 核满 vs 8 核均匀高，是两回事）→ **合**。
> 例：CPU 占用 + 内存占用（各自独立）→ **拆**。

## 6. 宿主该提供什么（给 DSH 的建议，**不是硬性**）

宿主**已经**给了：

| 提供物 | 在哪 |
|---|---|
| `.cockpit-*` 状态类 | `src/shared/theme/base-css.ts` → 注入 `__host/theme.css` |
| ECharts 主题（由 token 派生） | `src/shared/theme/echarts-theme.ts` |
| 契约别名 18 个 | `src/shared/theme/alias.ts` |
| 卡片 API（tags / storage / actions / workflows / log） | `src/main/cards/api-registry.ts` |

**还可以提供**（建议，**由 DSH 判断是否值得做**）：

| 建议 | 理由 | 成本 |
|---|---|---|
| `__host/ui.css`：`.cockpit-readout`（读数块）、`.cockpit-bar`（条）、`.cockpit-rows`（行组） | 现在每张卡都在**自己重写**一遍读数块 / 条 / 行组（`.meta-card` / `.fact` / `.th-stat` / `.bi-cell` —— **4 套**） | 低：三个类 |
| 宿主画一条 **「不可用 / 过时」** 的统一小标 | 现在每张卡各画各的 | 低 |

**边界（重要）**：

| 谁负责 | 什么 |
|---|---|
| **宿主** | 卡片**外面**的一切：标题栏、拖拽把手、边框、圆角、阴影、详情面板、卡片库 |
| **卡片** | 卡片**里面**的一切：读数怎么排、条怎么画、文案怎么写 |

> 本规范**只约束卡片里面**，且**只给判据**。
> M5b 卡片框架的实现细节（宿主给不给公共组件、组件长什么样）**由 DSH 判断是否调整**。

## 8. 现状整改建议（**给 DSH 的活，可分批**）

> **这些是建议，不是硬指标。** 改不改、怎么改由 DSH 判断。
> 每条都标了**观感变化**，便于排优先级。

| 卡片 | 建议 | 形态 | 观感变化 | 优先级 |
|---|---|:--:|---|:--:|
| **cpu-usage** | 删 sparkline + min/p95/max + meta-grid（都归详情面板）；仪表盘 → 大读数；保留每核条 | 4+1 → **2+1** | **大**（卡会明显安静） | **P0** |
| | 删 `arc-gradient` 死代码；弧与核心柱去掉发光与渐变填充 | — | 小 | P1 |
| **memory** | 删 sparkline + seg（与 3 个 stat 重复）；保留大读数 + 1 行已用/总量 | 4+1 → **2+1** | **大** | **P0** |
| **gpu-npu** | 双环 → 1 个主读数 + 1 个辅助行；**accent/accent-2 身份色 → 文字标签**；facts 归详情面板；环常态去发光 | 3 → **2+1** | **大** | **P0** |
| **core-load** | 3 个 summary → 1 个主读数（平均）+ 一行「峰值 / 总占用」 | 3 → **2+1** | 中 | P1 |
| **board-identity** | 背光条是**控制**不是读数 → 归卡片库 / 控制面（`actions.invoke`）；型号大读数 + 2 个 cell 保留 | 3 → **2** | 中 | P1 |
| **thermal** | **形态已合规**；只需去掉 hero 上的 `radial-gradient(warn 10%)` 常态染色晕 + 条的渐变填充 | 2+1 ✓ | 小 | P1 |
| **全部 6 张** | 状态统一到 `.cockpit-*` 类 | — | 小（**一致性提升大**） | **P0** |

### 8.1 优先级说明

- **P0（先做）**：状态语言统一 + cpu-usage / memory / gpu-npu 三张减法。
  这三张是**一屏上最抢注意力**的，也是用户抱怨「卡片一多就乱」的**主要来源**。
- **P1**：发光与渐变的清理（外观变化小，风险低）。
- **P2**（待拍板）：拆卡 / 换布局（影响用户的布局习惯，需要用户同意）。

## 9. 与契约的关系

| 这份规范里的东西 | 进不进契约？ |
|---|---|
| **色彩规则**（`--cockpit-*` 只用契约别名、不许硬编码） | ✅ **已在契约**（`spec/03` §6.3，ADR-D28） |
| **`.cockpit-*` 状态类** | ✅ 已在契约（`spec/03` §六） |
| **本文件的判据**（形态 ≤ 2、预算、状态类必用） | ❌ **不进契约** —— 它是**评审判据**，不是运行时契约。<br>进契约要评审（ADR-D15），且会**限制卡片作者的正当自由度** |
| **宿主提供的公共组件**（`.cockpit-readout` 等） | ❓ **待定** —— 要不要进契约，取决于 DSH 是否真做 |

> **为什么不进契约**：契约是**运行时**的硬边界（宿主与卡片之间的约定）。
> 这份规范是**设计评审**的软边界（"这样写出来好不好看"）。
> 把审美偏好写进契约，等于把设计品味变成 API —— **那是 DSH 的活，不是契约的活**。

## 10. 一句话总结

> **一张卡只主张一件事；颜色只说状态；趋势归详情面板；常态安静，出事才亮。**
>
> 卡片不是用来展示能力的，是用来**让人一眼读到板子现在怎么样**的。
