# UI 代码位置与目录约定

> **日期**：2026-11-14
> **对象**：`src/renderer/`、`src/shared/theme/`、`src/main/cards/kit/` 的**归属与分层**
> **依据**：`docs/UI设计/01-UI设计总纲.md`（设计基线）、`docs/UI设计/02-UI并行设计档案.md`（文件所有权表）、`docs/UI设计/04-视觉方向对照.md`（视觉取舍）
> **性质**：**约定**。它决定「一个文件该放哪、谁有权改它」，因此**要落盘**

---

## 一、三条摆放原则

| # | 原则 | 理由 |
|---|---|---|
| **1** | **零件（ui/）不知道业务，页面（app/ views/ library/）知道业务** | 零件可复用、可单测、可换皮；页面知道「板子」「卡片」「视图」这些词 |
| **2** | **token 的真源在 `shared/`，不在 renderer** | main 与 renderer **都要用**它（main 注入给卡片、renderer 用在自己身上）→ 放 renderer 就成了「main 抄一份」 |
| **3** | **生成产物不许手改** | `tokens.css` 由脚本产出 → 两个轨都不碰它 → 永不冲突、永不漂移 |

## 三、每一层的规矩

### 3.1 `src/shared/theme/` —— **唯一真源**

| 文件 | 职责 | 规矩 |
|---|---|---|
| `seed.ts` | 两套皮肤的**种子值** | **只有这里能手改色值**。每条种子带一行注释写它在哪儿用 |
| `map.ts` | **纯函数**：seed → 角色 → 别名 | **不许 import Electron / DOM**；输入 seed，输出两组变量 |
| `alias.ts` | 别名清单（名字 + 用途 + 是否进契约） | **这是契约面**：进契约的别名在这里标 `contract: true` |
| `echarts-theme.ts` | 由映射生成 ECharts 主题 JSON | 输出形状照 ECharts 文档的 theme JSON |
| `kit.ts` | 生成 `kit.css`（状态类） | **只输出 `var(--cockpit-*)`，不输出色值** |

**为什么在 shared**：main 要把它注入给卡片，renderer 要用它生成自己的 CSS。
放任何一边，另一边就得**抄一份**——那就是两份真相。

### 3.2 `src/renderer/ui/` —— **零件层**

| 规矩 | 说明 |
|---|---|
| **不 import `../app` 或 `../views`** | 零件不知道页面 |
| **不 import main** | 仓库既有规矩（AGENTS.md §5） |
| **只吃 props，不自己取数** | 数据由页面传进来 → 零件可单测、可做状态矩阵快照 |
| **颜色只来自 `var(--cockpit-*)`** | 零件里**不许出现 `#rrggbb`**（这条要有测试守） |
| **状态用类名表达** | `StatusLamp` 收 `status: TagStatus`，自己不判断 |

### 3.3 `src/renderer/app/` · `views/` · `library/` —— **页面层**

| 规矩 | 说明 |
|---|---|
| 可以 import `ui/` 的零件 | 页面组装零件 |
| **不直接 import main** | 数据一律经 `window.cockpit`（preload 白名单） |
| 视图预设是**纯数据** | `presets/*.ts` 导出 `{ id, name, slots, filter, density }`，不写 React |

### 3.4 `src/main/cards/kit/` —— **静态资产**

| 规矩 | 说明 |
|---|---|
| `kit.css` **只写 `var(--cockpit-*)`** | → **一份 kit，任何皮肤**；皮肤由宿主注入的 `__host/theme.css` 决定 |
| `kit.js` 是**纯 ES Module**（免构建） | 契约 ADR-D14：卡片脚本是免构建 ES Module |
| 不 import 任何东西 | 它跑在沙箱 iframe 里，**没有 Node、不能联网** |
| 归 UI 轨，**由 core 伺服** | core 的协议处理器把它们挂在 `cockpit://card/<id>/__host/` 下 |

## 四、生成脚本（**把「两份真相」变成「一份」**）

仓库已有同款先例：`scripts/gen-vocabulary.ts` → `src/shared/generated/tag-vocabulary.generated.ts` +
`npm run gen:vocabulary:check`（CI 里防漂移）。主题照抄这个套路：

```jsonc
// package.json
"gen:theme": "tsx scripts/gen-theme.ts",
"gen:theme:check": "tsx scripts/gen-theme.ts --check"
```

| 脚本做什么 | 产物 |
|---|---|
| 读 `src/shared/theme/seed.ts` → 跑 `map.ts` → 输出 CSS 变量块 | `src/renderer/theme/tokens.generated.css` |
| `--check` 模式：比对现有文件与应生成内容，不一致就**非零退出** | CI 判据 |

**这一条同时解决了并行冲突**：`tokens.css` 是**生成产物** →
**两个轨都不手改它** → 永远不会有冲突，也永远不会漂移 ✓✓

## 五、命名约定

| 类别 | 约定 | 例 |
|---|---|---|
| React 组件 | **PascalCase `.tsx`** | `StatusLamp.tsx`、`CardShell.tsx` |
| 纯函数 / 模块 | **camelCase `.ts`** | `format.ts`、`seed.ts`、`map.ts` |
| CSS 类 | `cockpit-` 前缀 + **BEM 修饰符** | `.cockpit-value--stale`、`.cockpit-tagcell` |
| CSS 变量 | `--cockpit-*`（别名层）；`--seed-*` / `--map-*` **不出现在 CSS 里** | 别名层是**契约面** |
| 卡片 kit 类 | `ck-` 前缀 | `.ck-stat`、`.ck-sparkline` |
| 图标 | **语义名**，不用形状名 | `icon-connection.svg` ✓ / `icon-blue-square.svg` ✗ |

## 六、什么**不该**进 `src/renderer/`

| 不该进 | 去哪 | 为什么 |
|---|---|---|
| 权限判断 | `src/main/cards/session.ts` | 权限是**安全边界**，必须在可信进程 |
| 板型包 / tag 的解析 | `src/main/tags/` | renderer 不 import main |
| 卡片 HTML / manifest 校验 | `src/main/cards/validate.ts` | 同上 |
| **kit.css / kit.js** | `src/main/cards/kit/` | 它们是**给卡片的资源**，要经 `cockpit://` 注入 |
| **ECharts 库文件** | `src/main/cards/vendor/`（或打包进 main） | 同上；卡片自己**不能联网**下载 |
| 色值字面量 | `src/shared/theme/seed.ts` | 别处出现色值 = 第二份真相 |

## 七、这套位置怎么支撑「可拓展、可自定义」

| 想要的能力 | 由哪一层支撑 |
|---|---|
| **换一套皮肤** | 改 `seed.ts` → `npm run gen:theme` → 应用、卡片、ECharts、终端**四处齐换** |
| **让用户自己换皮** | `<userData>/theme.json` 覆盖种子 → 同上（**只允许改种子**，理由见总纲 §十六） |
| **让卡片跟随宿主** | 宿主注入 `__host/theme.css`（别名层）→ 卡片只写 `var(--cockpit-*)` |
| **加一个新的 UI 零件** | 放 `src/renderer/ui/`，纯 props → 页面组装 → **不改任何 core** |
| **加一种新的卡片** | 放 `cards/<card-id>/` → manifest 校验 → 热插拔 → **不改宿主一行代码** |
| **加一种新的图表** | `src/main/cards/kit/kit.js` 加一个 `ck-*` → 卡片直接用 |

**一句话**：**可拓展性来自「真源只有一份 + 契约面用名字不用颜色」，可自定义性来自「种子层可被覆盖」**。
这两件事都落在 `src/shared/theme/` 那一层——它小，但它是对的地方。
