## 四、你可以自由做的（**明确授权**）

> 你说了「外壳之下的 UI 逻辑，实现中觉得该改就改」——以下是**逐条列出来**的授权范围。

### 4.1 renderer 外壳的一切

- `App.tsx` 的骨架重排（状态带 / rail / 视图标签栏 / 工作区 / 检查器）
- 组件拆分、状态管理方式（`useState` / `useSyncExternalStore` / 外部 store，随你）
- CSS 结构、类名体系、布局方式（CSS Grid / Flex / 绝对定位，随你）
- 空状态、加载态、错误态的**呈现**
- 交互细节：选中态、hover、快捷键、焦点管理、动效
- **旧壳的删除与替换**（新壳落地后一次性做）

### 4.2 M5b 布局那一套（**归你了**）

- 网格的列数/行高/间距、拖拽手柄的样式与行为、吸附与对齐反馈
- `Slot` 的**行为**：默认尺寸怎么算、新装的卡怎么落位、删掉的卡怎么腾位
- 布局的**视图模型**：要不要多视图（总览/监控/调试）、怎么切、怎么存
- 布局**持久化的时机**：拖完就存 / 防抖存 / 离开时存
- **卡片区的容器卡**（`kind: 'builtin'`）怎么摆 —— `board.tsx` 注释里说「v1 只实现 `kind: 'user'`，内置卡留给 M5b 的容器卡」，**那是留给你的**
- `react-grid-layout` 的用法要不要换、换不换随你

### 4.3 布局数据形状（**可以改，但有规矩**）

`src/shared/layout.ts` 的 `LayoutUnit` / `LayoutState` 过 IPC，所以形状是**跨进程约定**。

**规矩**：
1. 你可以**自由设计**新形状（多视图、每个视图一组 units、容器卡的类型标记……）；
2. 但 **`src/shared/layout.ts` 与 `src/main/cards/layout.ts` 必须同一次提交一起改**
   —— 两端不同步，中间会读出坏数据（`LayoutStore` 读不出来就当空布局，用户会丢布局）；
3. 改完在提交信息里写清「**形状变更 + 为什么 + 旧数据怎么办**」；
4. **旧布局文件不迁移**也可以，但要处理（读不出来 = 空布局，用户重摆一次）；
   如果你要迁移，那是 `src/main/cards/layout.ts` 里的事。

## 六、别自己实现（会重复造轮子 / 会破坏安全）

| # | 别做 | 用这个 |
|---|---|---|
| 1 | **自己写 CSS 变量体系** | `src/shared/theme/` 三层 + `scripts/gen-theme.ts`。**四处产出（应用 CSS / 卡片 `__host/theme.css` / ECharts 主题 / xterm 主题）由同一个映射函数生成** —— 你另写一套，终端和卡片颜色就对不上（这类产品最常见的破相） |
| 2 | **在 renderer 直接读 tag** | 读数只经 `TagStore` 出（ADR-D22）。页面只能经 `tags:readings` / `tags:changed` |
| 3 | **在 renderer 做权限过滤** | 权限判定在 main。页面拿到的**已经是过滤过的** |
| 4 | **自己实现动作执行 / 授权 / 回读 / 审计** | 那是 M6（契约 §四/§五）。**UI 可以画「需要确认」的壳，但不要自己写 executor** —— 参数编码 §4.6 是注入防线，写错一次就是命令注入 |
| 5 | **自己实现卡片沙箱 / CSP / `cockpit://`** | 都是 main 的 `protocol.handle`。你只负责在页面上摆 iframe |
| 6 | **给卡片开后门** | iframe 的 `sandbox="allow-scripts"`、CSP 由宿主注入。**卡片不能自己放宽** |
| 7 | **在 iframe 里直接塞宿主能力** | 卡片只能经 `broker` 的私有端口 |

## 七、六条最容易踩的坑

1. **「旧 UI 不要了」= 不要**壳**，不是不要**功能**。**
   旧的 `ReadingsPanel` / `FileBrowser` / `TerminalView` 背后是**真能力**（读数 / 文件互传 / 终端）。
   新壳必须接上 `CockpitApi` 里对应的方法。**把功能一起删掉 = 功能倒退**，比界面丑严重得多。

2. **重画外壳时，`broker` 的行为一个字都不能改。**
   它是卡片与宿主之间唯一的通道。你改的是**它摆在页面上的位置**，不是它。

3. **「卡片区」不是「工作区」。**
   现在 `CardPanel` 是主区里的一块。总纲的工作区是**视图驱动的** —— 视图标签栏切的是不同的**工作区**，不是同一屏里换内容。

4. **动效只回答动作。**
   数据自己变**不配动画**（每 200ms 刷一次的数字带过渡 = 整块仪表一直在抖）。
   数字用 `tabular-nums` 让它跳得不难看。

5. **五态不能只靠颜色。**
   `ok / stale / pending / unavailable / error` 的**形状**要能单独区分（实心 / 半实 / 空心 / 斜杠 ⊘ / 叉），
   并且 **`unavailable` 绝不显示数字**（`—`）。这直接对应契约 `unavailable ≠ 0`。

6. **别把「暂时没数」和「连不上」混成一句话。**
   `tagsStatus()` 专门给这个用（契约：`tags:readings` 只给读数，「为什么一个数都没有」到不了面板）。

## 九、基线的已知问题（**别当成你搞坏的**）

| # | 现象 | 性质 |
|---|---|---|
| 1 | `tests/unit/cards/paths.test.ts` **6 条红**：3 条是**测试夹具写错了**（`join('/cards','cpu-usage')` 在 Windows 上是根相对路径，`resolve()` 会补盘符 → 断言必红；**实现是对的**）；3 条是**软链测试 EPERM**（本机无开发者模式、非管理员，`symlinkSync` 建不出来） | 环境 + 夹具，**不是产品 bug** |
| 2 | **软链穿越防护从未被验证** —— `paths.ts` 的 realpath 二次判定是「AI 写的卡片不能读宿主文件系统」的唯一防线，而那 3 条测试在本机跑不起来 | ⚠️ **真缺口**。要有特权才能验，或给 `realpath` 留注入点 |
| 3 | `npm run mutation:check`：**4 条守卫是空的** —— M42/M48 的**目标串在源码里已经不存在**（变异没打上）；M40/M61 变异打上了但**测试照样绿** | ⚠️ **真缺口**。M48 守的是「CSP 违规能被认出来」= agent 唯一能看到「这张卡试图联网」的通道 |

| 5 | `@playwright/test` 声明了但 node_modules 里是**空壳目录** → `npm run test:cards` 一开始跑不起来（我已补装） | 环境 |

> **你改动之后，如果 `npm test` 的红条数**多于**上面第 1 条的 6 条，就是你弄坏的**；

## 十、协作与提交约定

1. **开工前**：确认工作树干净（`git status`）；把 Claude 那批 M5b 改动**先提交掉**。
2. **一次提交只做一件事**：外壳重画 / 布局行为 / 主题调整 分开提交，便于回退。
3. **形状变更**（`shared/layout.ts`）**与 main 侧同一次提交**，提交信息里写清「形状变了 + 为什么 + 旧数据怎么办」。
4. **碰 `src/main/**` 的其他部分之前先说一声** —— 那里有正在进行的改动。
5. **提交前跑完 §八.3 那 6 条**。
6. **设计稿落在 `docs/UI设计/`**：你的新稿放 `提案/`，别覆盖 `01-UI设计总纲.md`（那是当前基线）。
