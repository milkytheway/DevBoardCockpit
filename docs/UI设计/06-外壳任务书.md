## 一、任务

> 原文：「开始实现 UI 外壳，旧外壳可以完全摒弃，你来独立新实现一套，
> 酌情考虑把 shadcn 上可借鉴的搬下来为你所用。」

**独立实现一套新外壳**（骨架、组件、样式、交互、布局行为都随你）。
旧壳（`App.tsx` / `ReadingsPanel.tsx` / `FileBrowser.tsx` / `TerminalView.tsx` /
`app.css` 里的 `.cockpit-*` 类）**可以完全摒弃**——

**但「摒弃壳」≠「摒弃功能」**（施工图 §七.1）：那些组件背后是**真能力**
（读数 / 文件互传 / 终端 / 卡片区）。**新壳必须把它们接上**，
否则就是功能倒退——那比界面丑严重得多。

### 关于 shadcn：**借鉴，不引入**

| 可以 | 不可以 | 为什么 |
|---|---|---|
| **读 shadcn 的源码借鉴**：variants API、组件组合方式、a11y 处理（focus trap / dismissible / 键盘导航 / 语义 role） | **装 Tailwind** | 我们的主题机制是 **token 三层**（种子 → 映射 → 别名），`npm run gen:theme` **一处映射、四处产出**（应用 CSS / 卡片 `__host/theme.css` / ECharts / xterm）。引 Tailwind = **两套变量体系** → 终端与卡片颜色对不上（施工图 §六.1） |
| **用 Radix（headless、无样式）** —— 它不带视觉，正好补上「焦点陷阱 / 键盘导航 / 层叠关闭」这些自己写容易漏的 | **引入任何带样式的组件库**（antd / MUI / …） | ADR-D27 已定：**主体 UI 不引带样式的库**，用自有 token 层自写组件 |
| **把 shadcn 的组件源码抄进 `src/renderer/` 自己维护**（shadcn 本来就是「复制而非依赖」） | **动契约里的 15 个 `--cockpit-*` 别名**（`spec/03` §6.3） | **卡片靠它们活着**——卡片自己的 CSS 只用这些变量；改了别名 = 动契约 |

> **一句话**：**shadcn 当「源码参考」用，Radix 当「无样式依赖」用，Tailwind 不要。**
> 抄进来的组件要改成**消费我们的 `--cockpit-*` 变量**。

## 三、e2e 的**稳定钩子**（换皮也不会断）

`npm run test:cards` 的 10 条**不认任何 class 名**——它们靠：

| 钩子 | 用在哪 |
|---|---|
| `window.cockpit.cardsList()` → 拿 `instanceId` | 所有判据（唯一「卡片在不在」的依据） |
| 卡片帧的 **URL 前缀 `cockpit://card/`** | 隔离那几条 |
| `[data-cockpit-drag-handle="true"]` + `data-card-id="<cardId>"` | 布局那条（拖拽手柄） |

→ **你的 DOM 可以完全不同**，只要接口接上，10 条就该全绿。

## 五、依赖怎么加（**共享 node_modules 的坑**）

沙箱与 Windows 宿主**共享同一个 `node_modules`**，而 npm 的 optionalDependencies **按平台安装**：
在 Linux 上跑 `npm install` 会把宿主要的 win32 包**剪掉** → 宿主上 vitest 起不来。

| 谁加 | 怎么做 |
|---|---|
| **沙箱（Linux）** | `bash scripts/acceptance/add-dep.sh <pkg>[@version]` —— 隔离前缀装 → 只把缺的包拷进共享树 → 改 package.json → 更新 lock。**共享树一个字节都不碰** |
| **宿主（Windows）** | `npm install` → 然后**在沙箱里**跑 `bash scripts/acceptance/linux-natives.sh restore`（那个脚本在 Windows 上不能跑） |

> Radix 之类是纯 JS，风险低；但**别在沙箱里直接 `npm install`**。
