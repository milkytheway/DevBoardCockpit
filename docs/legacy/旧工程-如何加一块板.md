# Adding a board

## The easy way: a profile file

A board that speaks ADB, serial or SSH needs no code at all. Write a JSON
file into the profiles directory:

| Platform | Directory |
|---|---|
| Windows | `%LOCALAPPDATA%\DevBoardConsole\profiles\` |
| Linux | `~/.local/share/DevBoardConsole/profiles/` |

```json
{
  "id": "my-board",
  "label": "我的板子",
  "transport": "adb",
  "options": {
    "serial": "1234abcd",
    "pty": false,
    "prompt": "root@board",
    "commands": "adb"
  }
}
```

`pty` says whether the target runs a real terminal or a pipe, `prompt`
is what to draw before the real one is known, and `commands` picks the
quick-command set.

Restart the console and the board appears as a new tab.

### Options by transport

| Transport | Option | Meaning |
|---|---|---|
| `adb` | `adb_path` | Full path to `adb.exe`. Found automatically when it is on `PATH`. |
| `adb` | `serial` | Board serial. Empty means "the only device connected". |
| `serial` | `port` | e.g. `COM3` on Windows, `/dev/ttyUSB0` on Linux |
| `serial` | `baudrate` | e.g. `1500000` |
| `ssh` | `host` | Host name or address |
| `ssh` | `port` | SSH port, default 22 |
| `ssh` | `username` | Login name |
| `ssh` | `key_filename` | Private key; otherwise the usual keys are tried |
| `ssh` | `password` | Only if a key is not available |

### A transport of your own

The `transport` field is a plain name, not a fixed set. It is looked up
when the target is created, so a transport registered at run time works
like a built-in one:

```python
from devboard_console.core.registry import register_transport

register_transport("my-transport", MyTransport)
```

The profile then names it like any other:

```json
{ "id": "x", "label": "X", "transport": "my-transport" }
```

### Several profiles in one file

An array is also accepted, so one file can hold a whole lab:

```json
[
  { "id": "board-a", "label": "板子 A", "transport": "adb" },
  { "id": "board-b", "label": "板子 B", "transport": "ssh",
    "options": { "host": "10.0.0.5", "username": "root" } }
]
```

## The harder way: a new transport

When the board needs a protocol the console does not speak yet, implement
`Target` and register it. See
[architecture.md](architecture.md#adding-a-transport).

## Notes on the boards used during development

**RK3588 over ADB.** `adb shell` (no PTY) replies immediately and cleanly.
`adb shell -t -t` works but batches the reply until the next command, which
makes the transcript appear one command late.

**RK3588 over serial.** The CH343 adapter comes up as `COM3` at 1500000
baud. Note that `Win32_SerialPort` in PowerShell does not list it, even
though the port is there -- use `pyserial`'s `list_ports` instead. The
board's console echoes the command, so the reply is delimited with a unique
marker.

**Ubuntu guest.** SSH with a key works; `ssh.exe` from PowerShell cannot do
password authentication in a script on this machine, which is why the
console uses paramiko.
