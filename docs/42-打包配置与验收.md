## 一 · 配置（`package.json` 的 `build` 段 ✓）

```jsonc
"build": {
  "appId": "com.devboard.cockpit",
  "productName": "DevBoardCockpit",
  "directories": { "output": "release" },
  "files": ["out/**/*", "cards/**/*", "profiles/**/*"],
  "asar": true,
  "win": { "target": ["nsis"], "artifactName": "${productName}-${version}-setup.${ext}" },
  "nsis": { "oneClick": false, "allowToChangeInstallationDirectory": true, "createDesktopShortcut": true },
  "npmRebuild": true
}
```

### `files` 为什么是这三行（**打包后 `app.getAppPath()` = asar 根** ✓）

| 要带的东西 | 谁在读它 | 少了会怎样 |
|---|---|---|
| `out/**/*` | main / preload / renderer ✓ | 应用起不来 ✓ |
| **`cards/**/*`** | `join(app.getAppPath(), 'cards')` ✓（`src/main/index.ts:198` ✓） | **一张内置卡都没有** ✓（而开发期完全看不出来 ✓） |
| **`profiles/**/*`** | `profiles/settings.json` ✓ · `profiles/targets/` ✓ · `profiles/boards/` ✓ · `profiles/workflows/` ✓ | 没有连接、没有板型包、没有流程包 ✓ |

> **用户自己的**卡片 / profile / 流程包**不在 asar 里** ✓ —— 它们在
> `%LOCALAPPDATA%\DevBoardCockpit\` ✓（`src/main/util/paths.ts` ✓）→ **可写** ✓。

## 二 · 宿主上怎么出安装包

```bash
npm install            # postinstall 会 ensure-native（原生模块对齐 Electron 的 ABI ✓）
npm run dist           # 构建 → 产物自检 → electron-builder → NSIS 安装包
npm run check:package  # 打包产物自检（见下 ✓）
```

**产物**：`release/DevBoardCockpit-0.1.0-setup.exe` ✓。

### 宿主要准备什么

| # | 东西 | 为什么 | 没有会怎样 |
|---|---|---|---|
| 1 | **Node.js** ✓ | 构建 ✓ | — |
| 2 | **Visual Studio 生成工具（MSVC）** ⚠️ | `node-pty` 是**原生模块** ✓ → 要按 Electron 的 ABI 重编 ✓ | `npm install` 的原生编译会失败 ✓ |
| 3 | 网络（下载 Electron 二进制 ✓） | 首次打包 ✓ | — |

> **NSIS 不能跨平台构建** ✓ → **Windows 安装包必须在 Windows 上出** ✓
> （Linux 上只能验 `--dir` 的目录产物 ✓ —— 本轮就是这么验的 ✓）。
